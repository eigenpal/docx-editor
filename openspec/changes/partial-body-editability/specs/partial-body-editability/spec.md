## ADDED Requirements

### Requirement: Body editability is classified per top-level block
The engine SHALL assess each top-level body block against its preservation source range, semantic capture coverage, registered edit capability, and selective serializer. It SHALL derive a document mode of `full`, `partial`, or `none` without changing the block's canonical semantic kind.

#### Scenario: Mixed body has safe and read-only blocks
- **WHEN** a preserved body contains at least one fully captured editable paragraph and at least one top-level block that cannot be edited losslessly
- **THEN** the engine reports `partial`, identifies the editable paragraph as patchable, and identifies each unsafe block as read-only

#### Scenario: Unsupported inline child makes its containing paragraph read-only
- **WHEN** a top-level paragraph contains an unowned inline child such as an unsupported figure and no ownership-scoped inline capsule can reinsert it
- **THEN** the engine keeps the canonical block as a paragraph but classifies the whole paragraph as read-only

#### Scenario: Preservation evidence is unavailable
- **WHEN** the body has no validated preservation snapshot, document part, or trustworthy source ranges
- **THEN** the engine reports `none` and does not claim any imported body block is editable

### Requirement: Read-only blocks are immutable projection boundaries
The binding SHALL project every block classified as read-only to an identity-bound read-only node, including a canonical paragraph that is contextually read-only. Reverse mapping MUST validate the projected semantic ID, canonical kind, and current access policy rather than trusting projected attributes or inferring access solely from block kind.

#### Scenario: Paragraph-kind block uses a read-only projection
- **WHEN** a canonical paragraph is read-only because its source slice contains unmodeled OOXML
- **THEN** the binding projects it through the read-only lane and does not expose its text through the editable paragraph reverse mapper

#### Scenario: Read-only node is disturbed
- **WHEN** a transaction deletes, moves, duplicates, replaces, or retypes a read-only projected node
- **THEN** the binding rejects the entire transaction before canonical commit and restores the projection from unchanged canonical state

#### Scenario: Projection forges editable access
- **WHEN** a projected node marks a read-only block ID as an editable paragraph
- **THEN** reverse mapping rejects it because the current canonical access policy does not authorize that ID

### Requirement: Partial mode permits only proven in-place paragraph edits
When body mode is `partial`, the binding SHALL allow in-place text/run replacement only for a patchable paragraph whose original range has a registered lossless patch path. It MUST reject structural body operations before canonical commit.

#### Scenario: Safe neighboring paragraph is edited
- **WHEN** the user changes text within a patchable paragraph beside a read-only block
- **THEN** the binding emits one paragraph-scoped semantic operation and commits it without changing any neighboring block identity or order

#### Scenario: Paragraph split is attempted in partial mode
- **WHEN** Enter or another transaction attempts to split, join, insert, delete, reorder, or paste multiple body blocks while any top-level block is read-only
- **THEN** the binding rejects the complete transaction before the store revision changes

#### Scenario: Transaction crosses a read-only boundary
- **WHEN** a selection or replacement starts in an editable paragraph and crosses a read-only block
- **THEN** no partial semantic operation commits and the read-only block remains unchanged

### Requirement: Accepted edits have a selective-save proof before commit
The engine MUST NOT accept an edit that is known to require whole-region regeneration unavailable for the current preservation policy. Save-time source-integrity and serializer guards SHALL remain as defense in depth.

#### Scenario: Structurally unsafe edit is generated by a plugin
- **WHEN** a plugin generates a structurally valid ProseMirror transaction that the mixed-body serializer cannot reproduce losslessly
- **THEN** the binding rejects the transaction before `DocumentStore.apply` rather than allowing commit followed by save failure

#### Scenario: Untouched block is normalized internally
- **WHEN** store normalization produces a representation semantically equivalent to an untouched preserved block and the user edits a different patchable paragraph
- **THEN** save treats the untouched block as unchanged and does not invoke its edited-block serializer

### Requirement: Partial save preserves read-only content losslessly
A partially editable session SHALL save through selective serialization. The serializer MUST patch only changed ranges with proven ownership and MUST preserve every unchanged read-only range, unowned byte sequence, relationship, media payload, and unrelated package-part payload according to the declared exact-part and semantic-container comparators.

#### Scenario: Paragraph is edited beside unsupported content
- **WHEN** a safe paragraph is edited beside a read-only paragraph containing unsupported inline OOXML
- **THEN** save and reopen retain the edit while the read-only paragraph source slice and relative block order remain unchanged

#### Scenario: Paragraph is edited beside a table or content control
- **WHEN** a safe paragraph is edited in a body that also contains a read-only table or block content control
- **THEN** save and reopen retain the paragraph edit while the read-only block's source range remains unchanged

#### Scenario: Wholly read-only document is saved without edits
- **WHEN** body mode is `none` and no explicit non-lossless export is requested
- **THEN** save returns the original package bytes

### Requirement: Partial editability is structured and explainable
The framework-independent session and public editor snapshot SHALL expose document mode, effective editability, structural-mutation allowance, and structured read-only-region diagnostics. A region diagnostic SHALL include a stable reason code, story and block identity when applicable, block kind or root QName when known, and the missing capability lane.

#### Scenario: Owning editor opens a partial document
- **WHEN** an owning editor in edit mode opens a document whose body mode is `partial`
- **THEN** effective `editable` is true, structural body editing is false, and diagnostics identify every read-only region

#### Scenario: View-only host opens a partial document
- **WHEN** a host configured for view mode opens the same partial document
- **THEN** effective `editable` is false while the document capability mode and read-only-region diagnostics remain available

#### Scenario: Host handles warnings
- **WHEN** read-only regions are discovered
- **THEN** the engine returns structured diagnostics for the host to display, collect, or log and does not require unconditional output to a global console

### Requirement: Paired adapters apply one shared access policy
React and Vue SHALL consume the same engine-produced body access policy and MUST NOT independently classify OOXML or source ranges.

#### Scenario: Paired adapters open the same mixed fixture
- **WHEN** both adapters open identical bytes containing editable and read-only body regions
- **THEN** they report the same mode and diagnostic identities, expose the same editable regions, and reject the same boundary-crossing operations

### Requirement: Unsupported active content remains inert
Partial editability MUST NOT execute, activate, resolve, or fetch unsupported fields, macros, ActiveX, OLE, embedded objects, external figures, or executable relationships. Making a neighboring paragraph editable SHALL not change the trust classification or runtime behavior of preserved content.

#### Scenario: Editable paragraph neighbors an embedded object
- **WHEN** a safe paragraph is edited beside a read-only region containing an embedded object or external relationship
- **THEN** the edit and save perform no external request or execution and preserve the inert region unless an explicit non-lossless scrub export is requested
