# Public editing API documentation coverage

## Scope and method

This audit covers the root and browser exports of `@docx-editor.dev/editor-api`.
It uses the TypeScript checker over `src/index.ts` and `src/browser.ts`.
Aliases resolve to their source declarations. The inventory includes inherited public members.
It excludes private, protected, and `@internal` members, including hydration helpers and factories.
It excludes standard inherited `Error` fields from the API-specific member count.
Enum values, union branches, overloads, and exact setter types remain linked through generated declarations.

The source inventory has **86 unique exported names** and **390 class/interface member placements**, including inherited members.
All 86 names appear in the authored [API member directory](../../../docs/site/content/editor-api/reference.mdx).
Every listed member is discoverable in dedicated topic prose, member tables, or the linked generated reference.
These counts measure documentation discoverability, not Office.js compatibility or runtime equivalence.

The site now has **14 dedicated additions** beyond its overview and compatibility page.
Both navigation files register all 16 editing API pages in the same order.
The overview and package README link each task guide before their longer examples.
All 132 checked topic links resolve to authored local pages.

## Verification

- All 42 TypeScript examples in the new pages passed snippet diagnostics with strict source types.
- Typed setup inputs supplied only host-owned values and existing proxies named explicitly in the prose.
- The extraction excluded shell fences and the unchanged overview/compatibility examples.
- Seventeen exact executable samples ran against real in-memory DOCX files and saved/reopened successfully.
- These samples covered text, structural splitting, formatting, lists, tables, layout, footer creation, controls, comments, and revisions.
- The table read sample also exercised `getFirstOrNullObject().load(...)` on an empty table collection.
- `bun run check:docs-mdx` passed for all 64 site pages.
- Prettier formatted every edited MDX, metadata file, package README, and this audit.
- A navigation and link check verified all local editor API topic targets and both metadata files.

Snippet checking uses the repository TypeScript configuration and public source imports.
It disables unused-variable warnings for standalone teaching samples, while retaining strict type checking.
Runtime sample execution extracts each documented TypeScript fence and supplies a fresh server runtime.
Each runtime uses an explicit author and a fixture with the text targets required by that sample.
The test saves the result, opens it in a fresh runtime, and reads the body.
This is targeted sample validation, not an assertion that every arbitrary DOCX structure is editable.

## Runtime evidence and documented limits

| Area                     | Reviewed evidence                                                                                 | Limits made explicit                                                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Runtime and batching     | `src/runtime/runtime.ts`, `request-context.ts`, `load-options.ts`, `errors.ts`, and runtime tests | Explicit final sync, atomic writes, dependent reads, stale recovery, proxy adoption, disposal, stable codes                 |
| Text and search          | Model body/range/paragraph sources, read/write tests, consumer workflows                          | Story scopes, search flags, structural `Paragraph.split`, range snapshot lifetimes, and disjoint plain-text batching        |
| Formatting               | `src/model/font.ts`, core font-value mappings, formatting tests                                   | Authored nullable reads, palette values, unsupported underline enum tokens, tracked formatting refusal                      |
| Lists                    | List model, list authoring tests, batch regression tests                                          | Creation sync; distinct levels can batch; same-level aliases conflict; defined levels and font resources                    |
| Tables                   | Table model and table parity/cleanup tests, consumer workflows                                    | Rectangular structural edits, solitary row/column changes, whole-column widths, complex values refusal                      |
| Pictures                 | Picture model and picture/field parity tests                                                      | Inline PNG/JPEG, aspect-ratio conflicts, creation sync, explicit alternative text                                           |
| Fields                   | Field model, field pagination tests, runnable report agent                                        | PAGE/NUMPAGES only, inert instructions, measured font resources, separate result-update transactions                        |
| Stories and notes        | Sections and note models, furniture creation tests                                                | Section body is the shared main story; deferred header/footer creation; solitary note deletion                              |
| Controls                 | Control model, control creation and metadata regressions                                          | Main-story lookup, duplicate ids, typed existing values, binding and ancestor locks, only text-control creation             |
| Comments and revisions   | Review model, runtime review tests, collaborative review consumer                                 | Explicit authors, browser review gate, nullable dates, story-wide decisions versus published items                          |
| Null objects             | Runtime null-scalar-load regression tests                                                         | Load eligible scalar fields before sync, then check `isNullObject`; null-object writes still refuse atomically              |
| Source-shaped extensions | Public exports and generated API snapshots                                                        | Host infrastructure, control value helpers, note collections, revision views, and unavailable methods clearly distinguished |

Source files and tests establish behavior within their covered domains.
Pinned Office.js declarations establish signatures only.
The public guides do not infer runtime support from a signature match or an enum member.
See `packages/editor-api/compat/runtime-notes.json` for per-endpoint runtime differences.
