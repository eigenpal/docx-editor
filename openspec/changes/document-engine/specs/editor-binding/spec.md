## ADDED Requirements

### Requirement: EditorBinding is the only PM-aware store integration
`EditorBinding` SHALL own all ProseMirror-to-model and model-to-ProseMirror
mapping. `DocumentStore` and `ReplicatedStoreBackend` MUST expose no ProseMirror
type, and the binding MUST operate against model-shaped state rather than a
backend-owned editor fragment.

> **PM stays native (see ADR-S10).** The binding replaces PM's role as durable
> canonical storage ONLY. It MUST NOT reimplement ProseMirror's transaction,
> selection, or IME machinery with a custom editor engine; it maps PM transactions
> to `DocOp`s and projects `ModelChange` to minimal PM transactions, and lets PM own
> all other in-browser editing behavior. This is why the binding is a mapping layer,
> not a new editor.

#### Scenario: Binding package is removed
- **WHEN** the engine runs headless without the binding package
- **THEN** parsing, semantic editing, synchronization, layout, and export MUST still operate

### Requirement: Supported forward steps map to DocOps
The binding MUST evaluate each complete ProseMirror transaction, including
mapped multi-steps and appended transactions, against a shadow `EditorState`. Registered
mappers MUST convert it atomically to `DocOp`s against evolving mappings before
the actual view is dispatched. Rejection MUST discard the shadow; success MUST
reconcile the actual view only from normalized canonical state.

#### Scenario: Formatting transaction
- **WHEN** a transaction applies bold formatting to a selected range
- **THEN** the mapper MUST emit semantic mark operations, the store MUST commit them, and the projection MUST reflect the normalized result

### Requirement: Unsupported steps have an explicit fallback
The binding MUST use an explicit fallback when no mapper claims a step. It MAY let the projection calculate the
affected result only to derive identity-preserving `ReplaceBlockContent` for the
smallest owned blocks. Semantic `ReplaceNode` MUST mint identity. Capsule
ownership MUST be proven before fallback. It MUST NOT bypass `store.apply`. A command with no safe
mapping or replacement MUST be disabled or rejected as `unsupported`.

#### Scenario: Extension step lacks a mapper
- **WHEN** an extension dispatches a step with no registered mapper and a safe block replacement can be derived
- **THEN** the binding MUST apply that replacement as a `DocOp` through the store

### Requirement: Reverse reconciliation is incremental and normalized
For each `ModelChange`, the binding SHALL reconcile affected model ranges into
minimal ProseMirror steps where possible and SHALL fall back to affected-block
replacement where necessary. It MUST reconcile to canonical normalized state,
not replay unnormalized input.

#### Scenario: Remote normalized repair
- **WHEN** a remote merge triggers a deterministic structural repair
- **THEN** the editor MUST reconcile to the repaired model even if the original remote operation cannot be reconstructed

### Requirement: Selection and stored state survive reconciliation
The binding MUST preserve or deterministically resolve text selections, stored
marks, node selections, and table-cell selections using internal anchors.
Deleted selections MUST collapse by a documented affinity rule without crash.

#### Scenario: Remote insertion precedes caret
- **WHEN** a remote insertion occurs before the local caret
- **THEN** the caret MUST remain attached to the same semantic position after reconciliation

#### Scenario: Selected table cell is deleted
- **WHEN** a remote transaction deletes a cell participating in a cell selection
- **THEN** the selection MUST resolve to the nearest valid declared target or clear deterministically

### Requirement: IME composition defers remote reconciliation
The binding MUST defer inbound model changes that would rewrite the
composition range during active IME composition. On composition end, the binding MUST resolve
the composed result and queued changes against the latest model revision through
the normal semantic path.

#### Scenario: Remote edit during composition
- **WHEN** a remote insertion arrives inside an active composition
- **THEN** the binding MUST avoid replacing the composing DOM, then reconcile both edits after composition ends without duplicate text

### Requirement: Origins prevent feedback loops across both bindings
Mutation, projection, replication, and awareness origin domains SHALL be
distinct. Transactions generated by reverse reconciliation MUST carry
`ProjectionOrigin` so the forward mapper ignores them, while genuine
normalization transactions MUST still become semantic operations before commit.
Feedback-loop prevention MUST hold across BOTH bindings: a change entering from
the Yjs side (published via `publishDerived` under a remote origin) MUST reconcile
into ProseMirror exactly once and MUST NOT be mirrored back into the `Y.Doc`; a
local editor change committed to the store and mirrored into the `Y.Doc` under a
local transaction origin MUST NOT re-enter the store when the binding observes its
own Yjs echo. Echo suppression on the Yjs side is by transaction origin, not an
application-level update-id set.

#### Scenario: Remote change reaches projection once
- **WHEN** one remote update emits a model change
- **THEN** reconciliation MUST update the editor once and MUST NOT emit an echoing semantic operation or replication update

#### Scenario: Local edit is mirrored to Yjs without re-entry
- **WHEN** a local editor commit is mirrored into the `Y.Doc` under the local origin and the binding observes the resulting Yjs update
- **THEN** the binding MUST ignore that self-origin update and MUST NOT publish a second canonical revision

### Requirement: Extension mappers are deterministic
Extensions that add editable node, mark, or selection types MUST register
forward and reverse mapping behavior, affected-range calculation, anchor
semantics, and fallback policy. Registration MUST fail when required mapping is
missing.

#### Scenario: Editable extension lacks reverse mapping
- **WHEN** an extension declares an editable semantic node without a reconcile mapper or safe replacement strategy
- **THEN** editor initialization MUST fail with a capability error

### Requirement: Binding parity is property-tested
The binding MUST pass deterministic golden and randomized tests comparing PM
transactions through `DocOp`s with direct semantic application, and comparing
model changes with equivalent projected documents and selections.

#### Scenario: Random transaction sequence
- **WHEN** a generated supported transaction sequence is applied through the binding and directly as expected operations
- **THEN** authored model state, projected content, selection validity, origins, and revisions MUST remain equivalent

### Requirement: Reconciliation has before and after evidence
The binding MUST consume `ModelChange` before/after structural descriptors or a
binding revision index retaining old/new projected ranges, anchors, moves,
deletions, split/join mappings, and replacement identity until acknowledgement.
It MUST NOT require a whole-document diff.

#### Scenario: Node moves and another is deleted
- **WHEN** one commit moves a node and deletes its previous neighbor
- **THEN** reconciliation MUST map both old ranges to new boundaries using retained evidence

### Requirement: IME reconciliation is a deterministic state machine
Composition state MUST record start revision, anchored composing range, initial
text, local composing text, and ordered inbound changes. Intersecting inbound
changes SHALL be deferred. Commit MUST convert final composition text into one
semantic history group before replaying queued normalized revisions; cancel
MUST discard local composition before replay. Fixtures MUST state exact expected
strings for insertion and deletion conflicts.

#### Scenario: Remote deletion intersects committed composition
- **WHEN** composition replaces `ab` with `xy` while a queued remote change deletes `b`
- **THEN** the fixture's declared anchor/affinity rule MUST produce one exact final string, one local history group, and no duplicate composition text

### Requirement: Every selection kind has deterministic rules
The binding MUST define deterministic rules for forward/backward text ranges, carets, stored marks, node selections, partial and
complete cell selections, and whole-document deletion MUST resolve through
anchors and affinity. Moved nodes retain selection; deleted nodes/cells resolve
to the declared nearest valid boundary or clear deterministically.

#### Scenario: Complete cell selection is deleted
- **WHEN** every cell in a selected rectangle is deleted remotely
- **THEN** the cell selection MUST clear or collapse by the declared rule and MUST NOT select an unrelated table

#### Scenario: Backward range crosses insertion
- **WHEN** a remote insertion occurs at one endpoint of a backward text selection
- **THEN** endpoint affinity and selection direction MUST be preserved
