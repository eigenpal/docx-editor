A field stores an instruction and a cached result. Inserting or reading a field never evaluates its instruction. Only plain `PAGE` and `NUMPAGES` fields support evaluation.

Create a `runtime` with [Runtime and setup](/docs/2.x/editor-api/runtime).

## Insert a field

Insert the field, sync, then write its result:

```ts
await runtime.run(async (context) => {
  const hit = context.document.body.search('see section ').getFirst();
  const field = hit.insertField('After', 'Ref', '_Ref123456 \\h');
  await context.sync();

  field.result.insertText('Section 4', 'Replace');
  await context.sync();
});
```

`Range.insertField(location, fieldType?, text?, removeFormatting?)` returns a `Field`. It accepts `Before`, `After`, `Start`, `End`, and `Replace` within one paragraph. Sync before you use the returned field.

New fields start with an empty result and take the formatting of the text before them. Trim `code` before you compare it.

## Choose a field instruction

For a typed field, `text` holds the arguments. For `Empty` or no type, it holds the whole instruction:

| Field type | Instruction | Arguments |
| --- | --- | --- |
| `Page`, `NumPages` | `PAGE`, `NUMPAGES` | None. Switches refuse. |
| `Ref`, `PageRef`, `NoteRef` | `REF`, `PAGEREF`, `NOTEREF` | A bookmark name, then optional switches |
| `Seq` | `SEQ` | A sequence name, then optional switches |
| `StyleRef` | `STYLEREF` | A style name, quoted when it contains a space |
| `Date`, `Time` | `DATE`, `TIME` | Optional switches |
| `TOC` | `TOC` | Optional `\o` with ascending levels 1 through 9, `\h`, `\z`, and `\u` |

| Rule | Detail |
| --- | --- |
| Length | 255 characters or fewer, with no tabs, line breaks, or control characters. |
| Syntax | Switches, quoted strings, and bare words, separated by spaces. Quoted strings cannot contain `"` or `\`. |
| Refused types | Types that fetch, embed, link, run, or prompt, such as `DDE`, `DDEAUTO`, `IncludeText`, `IncludePicture`, `Import`, `Link`, `MacroButton`, `AutoText`, `Hyperlink`, and `FillIn`, also inside arguments. |
| `TOC` | Saves the instruction only. Duplicate or unknown switches, code writes, and `updateResult()` refuse. |
| Enums | `FieldType` and `FieldTypeLiteral` list more types than creation supports. |

New fields other than page and `TOC` fields are marked dirty, so a reader that evaluates fields recomputes them on open.

## Propose a field as a tracked change

With `TrackMineOnly`, the field and its result form one tracked insertion. If the result write fails, take the field back:

```ts
await runtime.run(async (context) => {
  context.document.changeTrackingMode = 'TrackMineOnly';
  const hit = context.document.body.search('as shown in ').getFirst();
  const field = hit.insertField('After', 'Ref', '_Ref123456 \\h');
  await context.sync();
  try {
    field.result.insertText('Figure 3', 'Replace');
    await context.sync();
  } catch (error) {
    field.delete();
    await context.sync();
    throw error;
  }
});
```

- Reject removes the field with its result. A tracked `Replace` strikes the range first.
- `delete()` removes your own pending field outright. A tracked `delete()` of any other field refuses with `NotSupported` and `edit.tracked-operation-unsupported`.
- Code writes and `updateResult()` refuse until a reviewer accepts the field. Tracked `TOC` creation refuses.

## Read or replace cached results

`Field.result` returns a `Range` that supports two members:

| Member | Behavior |
| --- | --- |
| `text`, after `load('text')` or `field.load('result')` | The cached result text |
| `insertText(text, 'Replace')` | Replaces the result with one line of plain text, 2,048 characters or fewer. A tab becomes `w:tab` |

The write never evaluates the instruction, and it marks the field dirty. Several result writes can share a sync.

| Tracking state | Requirement |
| --- | --- |
| Off | The field must sit outside every revision. |
| `TrackMineOnly` | The field must be your own pending insertion. The runtime never writes the result untracked instead. |

## Read and change instructions

Load `code` on each field in one sync:

```ts
const codes = await runtime.run(async (context) => {
  const fields = context.document.body.fields;
  fields.load('items/code');
  await context.sync();
  return fields.items.map((field) => field.code);
});
```

| Member | Behavior |
| --- | --- |
| `Body.fields`, `Range.fields` | A `FieldCollection` with `items`, `getFirst()`, `getLast()`, and their `OrNullObject` forms. A range lists fields it fully contains. |
| `Field.code` | Writing `'PAGE'` or `'NUMPAGES'` keeps the cached result. Code writes refuse on protected fields, unsupported instructions, and while tracking. |
| `Field.delete()` | Removes the field. Its proxy becomes invalid. |

## Configure measured server pagination

Server result updates require `CreateServerOptions.pagination`, a `ServerPaginationOptions` with a required `measurer` and optional `producer`:

```ts
const runtime = await DocxEditor.createServer(bytes, {
  pagination: { measurer },
});
```

Build the measurer from real font resources with `sha256FontBytes`, `createLayoutShaping`, and `createLayoutShapedMeasurer`. The runnable [report agent](https://github.com/eigenpal/docx-editor/blob/main/examples/editor-api-consumers/report-agent.ts) shows the setup.

- Font substitution can change page counts. Provide bullet fonts, such as Symbol, too.
- Dispose the runtime, and release shaping with `disposeLayoutShaping(shaping)`.
- A browser runtime uses its editor's layout instead.

## Update page fields

Insert a page field, then update it in a separate sync:

```ts
await runtime.run(async (context) => {
  const anchor = context.document.paragraphs.getLast().getRange('End');
  const field = anchor.insertField('After', 'NumPages');
  await context.sync();
  field.updateResult(); // Requires pagination on a server.
  await context.sync();
});
```

`Field.updateResult()` computes the result from measured pagination, including section page-number formats. Several updates can share a sync, but no other document writes, so finish layout-changing edits first. Updates fail with `NotSupported` without pagination, for unsupported instructions, or when the result cannot be rewritten.

## Limits

`insertField()` refuses in these cases, and nothing changes:

| Error | `innerError.code` | Cause |
| --- | --- | --- |
| `InvalidArgument` | `edit.field-unsupported` | Unsupported type or instruction, or malformed arguments. |
| `InvalidArgument` | `edit.protected-content` | The point is in content-locked or data-bound content. |
| `InvalidArgument` | `edit.invalid-argument` | `Replace` spans paragraphs, or `removeFormatting` is `true`. |
| `NotSupported` | `edit.tracked-operation-unsupported` | With `TrackMineOnly`, the type is `TOC`. |
| `NotImplemented` | `edit.tracked-foreign-revision-unsupported` | With `TrackMineOnly`, the point is in another author's structural change. |
| `ConflictingChanges` | None | Another edit in the sync changes the same paragraph. |
| `StaleDocument` | None | The range moved after you read it. |

A result write refuses in these cases:

| Error | `innerError.code` | Cause |
| --- | --- | --- |
| `NotImplemented` | `edit.field-result-unsupported` | A member other than `text` and `insertText(text, 'Replace')`. |
| `NotSupported` | `edit.unsupported-content` | The result holds a symbol, picture, line break, or nested field. |
| `NotSupported` | `edit.tracked-operation-unsupported` | With `TrackMineOnly`, the field is not your own pending insertion. |
| `NotImplemented` | `edit.revision-unsupported` | With tracking off, the field is inside a pending revision. |
| `InvalidArgument` | `edit.invalid-argument` | A line break, a control character other than a tab, or over 2,048 characters. |
| `InvalidArgument` | `edit.protected-content` | The field is locked, or in locked or data-bound content. |
| `InvalidObjectPath` | None | The insertion has not synced yet. |
