Use `Body` for a story, `Paragraph` for a paragraph, and `Range` for an addressed span. `context.document.body` is the main story, including table cells but not headers, footers, or notes. For those, see [Page layout and stories](/docs/2.x/editor-api/page-layout-and-stories).

Create a `runtime` with [Runtime and setup](/docs/2.x/editor-api/runtime).

## Read text without exporting proxies

Load `text`, sync, and return plain data:

```ts
const text = await runtime.run(async (context) => {
  const body = context.document.body;
  body.load('text');
  await context.sync();
  return body.text;
});
```

`Body.text` joins paragraphs with `\r`. Text reads follow the runtime's `revisionTextView` option. `Paragraph.uniqueLocalId` is valid within one runtime only.

## Address existing content

For an exact replacement, search and check the match count:

```ts
await runtime.run(async (context) => {
  const matches = context.document.body.search('within 7 days', {
    matchCase: true,
  });
  matches.load('items');
  await context.sync();
  if (matches.items.length !== 1) throw new Error('Choose one clause');

  const replacement = matches.items[0]!.insertText('within 30 days', 'Replace');
  replacement.load('text');
  await context.sync();
  return replacement.text;
});
```

Ranges read from the document accept text writes in the same sync. For search options, see [Search and navigation](/docs/2.x/editor-api/search-and-navigation).

| Member | Locations | Notes |
| --- | --- | --- |
| `Body.getRange(location?)`, `Paragraph.getRange(location?)` | `Whole` (default), `Content`, `Start`, `End`, `Before`, `After` | Endpoints are insertion points. |
| `Range.getRange(location?)` | `Whole`, `Content`, `Start`, `End` | `Whole` and `Content` match. `After` fails with `NotSupported`. |
| `Range.expandTo(other)` | None | Spans from the earlier start to the later end. Both ranges must share a story, or the sync fails with `InvalidArgument`. |

`RangeLocation` provides matching enum values. The API exposes no HTML and no document-wide offsets.

## Choose an insertion location

Each receiver accepts these locations:

| Receiver    | `insertText(text, location)`                 | `insertParagraph(text, location)` |
| ----------- | -------------------------------------------- | --------------------------------- |
| `Body`      | `Replace`, `Start`, `End`                    | `Start`, `End`                    |
| `Paragraph` | `Replace`, `Start`, `End`                    | `Before`, `After`                 |
| `Range`     | `Replace`, `Start`, `End`, `Before`, `After` | `Before`, `After`                 |

The type aliases are `BodyInsertTextLocation`, `BodyInsertParagraphLocation`, `ParagraphInsertTextLocation`, `RangeInsertTextLocation`, and `BesideLocation`. `InsertLocation` provides enum values.

This sample appends a paragraph and configures it after the creation sync:

```ts
await runtime.run(async (context) => {
  const paragraph = context.document.body.insertParagraph('Review complete.', 'End');
  await context.sync();
  paragraph.spaceAfter = 12;
  await context.sync();
});
```

| Behavior | Detail |
| --- | --- |
| Return values | `insertText()` returns a `Range`, and `insertParagraph()` a `Paragraph`. Load them in the same sync; edit them after it. |
| Paragraph separators | `insertParagraph()` and `ContentControl.insertText()` refuse `\r` and `\n`. |
| Manual line break | Write `\v`, or call `Range.insertBreak('Line', location)`. A single-line content control refuses it. |
| Body edges | Next to a table at a body edge, `insertParagraph()` lands outside the table. A second edit there in one sync refuses with `ConflictingChanges`. |
| Empty paragraph | Text takes the mark's character style, not its direct run properties. |
| Spacing | An insertion lands exactly at the endpoint, so include a trailing space in your search. |
| Tracked insertion | Content right after your own pending text joins that insertion. Text after a paragraph-ending field starts a separate insertion. |

## Clear or delete content

| Member | Effect |
| --- | --- |
| `Body.clear()` | Clears supported content and leaves one empty paragraph. Fails with `InvalidArgument` on a body with no paragraphs. |
| `Paragraph.clear()` | Clears content and keeps the paragraph. |
| `Paragraph.delete()` | Deletes the paragraph, or proposes deleting it while tracking. |
| `Range.clear()`, `Range.delete()` | Deletes the range content. |

Cross-cell boundaries, pending revisions, and protected or preserved structures refuse atomically. A body, note, or text box that ends with a table has an empty paragraph after the table. Without change tracking, `Paragraph.delete()` on that paragraph fails with `NotSupported` and `edit.operation-unsupported`; call `Paragraph.clear()` instead. With `TrackMineOnly`, whole-body replacement with `Body.insertText(text, 'Replace')` fails with `NotSupported` and `edit.tracked-operation-unsupported`; replace a range inside the body instead. In browser suggesting mode, `Body.clear()` and `Body.insertText(text, 'Replace')` on a body with a table fail with `NotSupported` and `edit.tracked-structure-unsupported`, even with runtime tracking off.

For tracked deletion, see [Propose removing paragraphs](/docs/2.x/editor-api/revisions#propose-removing-paragraphs).

## Split a paragraph

`insertText()` treats `\n`, `\r`, and `\r\n` as paragraph breaks. Replace only the gap between two sentences:

```ts
await runtime.run(async (context) => {
  const body = context.document.body;
  const first = body.search('the goods.').getFirst();
  const second = body.search('The buyer').getFirst();
  first.getRange('End').expandTo(second.getRange('Start')).insertText('\n', 'Replace');
  await context.sync();
});
```

New paragraphs keep the properties of the one you wrote into, so list items stay in their list. The returned range reads each break as `\r`. A break in a hyperlink makes two links with the same target.

To propose the split, see [Propose a paragraph split](/docs/2.x/editor-api/revisions#propose-a-paragraph-split).

| Member | Changes the document | Use |
| --- | --- | --- |
| `Paragraph.split(delimiters, trimDelimiters?, trimSpacing?)` | Yes, unlike Office.js | Split at every delimiter. Returns one range per new paragraph. Sync before you load them. With `TrackMineOnly`, `trimDelimiters: true` fails only when the split removes a found delimiter. |
| `getTextRanges(endingMarks, trimSpacing?)` | No | Read words or sentences. See [Split text into word ranges](#split-text-into-word-ranges). |

A write with breaks refuses in these cases, and nothing changes:

| Error | `innerError.code` | Cause |
| --- | --- | --- |
| `NotSupported` | `edit.indivisible-content` | The break lands inside an inline content control. |
| `ConflictingChanges` | None | Another edit in the sync changes the same paragraph. |
| `InvalidArgument` | None | The text holds a form feed, U+2028, or U+2029. |
| `InvalidArgument`, or `GeneralException` with tracking | `edit.protected-content` | The range is in content-locked or data-bound content. |
| `StaleDocument` | None | The range's text moved after you read it. |

With `TrackMineOnly`, the tracked refusals in [Supported tracked edits](/docs/2.x/editor-api/revisions#supported-tracked-edits) also apply.

## Split text into word ranges

`Paragraph.getTextRanges(endingMarks, trimSpacing?)` and `Range.getTextRanges()` return exact spans that you can edit in a later sync.

| Argument | Behavior |
| --- | --- |
| `endingMarks` | Each range ends after one mark, such as `' '` or `'. '`. At most 32 marks of at most 32 UTF-16 units each, with no unpaired surrogate. |
| `trimSpacing: false` | Default. Ranges keep trailing spacing, so a deleted word takes its space. Use it to plan edits. |
| `trimSpacing: true` | Trims edge spacing and drops spacing-only ranges. Use it to read words. |

Prefer `'. '` to `'.'`, which also matches inside `4.2`. A paragraph end always ends a range, and no range includes a paragraph mark.

| Element | Behavior in a word range |
| --- | --- |
| Field | One unit that joins the word it touches. Reads as its result, which can contain spaces. |
| Equation, picture, or note reference | One U+FFFC unit that joins the word it touches. |
| Tab | Ends a range only if you list `'\t'`. |
| Inline content control | Adds no boundary. |
| Content-locked control | A partial replacement fails with `edit.protected-content`. Branch on this inner code; the outer code varies with tracking. |
| Tracked deletion | Shows in the ranges in both text views. |
| Text that `revisionTextView` hides | Holds no mark. An edit through a range that spans it also changes it. |

Before you plan edits, load `contentControls` with `cannotEdit`, and keep each locked control as one unit.

## Rewrite a paragraph and read the result

To propose a model's rewrite, use `prepareRewrite` from `@docx-editor.dev/editor-api/agent`. See [Propose an AI rewrite as tracked changes](/docs/2.x/recipes/propose-rewrite).

To apply edits yourself, read the ranges once, plan by index, and apply from the last index with a sync after each:

| Difference | Call |
| --- | --- |
| Replace words | `first.expandTo(last).insertText(text, 'Replace')` |
| Delete words | `first.expandTo(last).delete()` |
| Insert before the first word | `words[0].insertText(text, 'Before')` |
| Insert after a word | `word.insertText(text, 'After')` |
| Insert after the last word | `last.insertText(' ' + text, 'After')`; the last word has no trailing space |

After tracked edits, `Paragraph.text` holds deleted and inserted words. Read the proposed text instead:

```ts
const proposed = paragraph.getReviewedText('Current');
await context.sync();
console.log(proposed.value);
```

`'Current'`, the default, reads as if all changes were accepted, and `'Original'` as if all were rejected. `ChangeTrackingVersion` provides the enum values. Do not split the paragraph again to plan more edits, because ranges can join deleted and inserted text.

## Handle text characters

Some elements read as one character, whatever their glyph:

| Element             | API text | `insertText()` behavior          |
| ------------------- | -------- | -------------------------------- |
| Non-breaking hyphen | U+001E   | Restores the non-breaking hyphen |
| Optional hyphen     | U+001F   | Restores the optional hyphen     |
| Symbol (`w:sym`)    | `(`      | Inserts a literal parenthesis    |
| Manual line break   | `\v`     | Inserts a manual line break      |
| Paragraph mark      | `\r`     | Starts a new paragraph           |
| Column break        | U+000E   | Refused                          |

Each occupies one UTF-16 unit. Search never matches a symbol. A round trip keeps hyphens but not symbols or fields.

### Upgrade text processing

Reads in 2.26.0 and earlier report manual line breaks and column breaks as `\n`. Later versions report `\v` and U+000E. Update code that compares or splits lines.

For display, convert `\v` to `\n` in a copy, and keep the original text for writes. Search and `Paragraph.split()` accept `\n` as a line break alias, but in `insertText()` it is a paragraph break.

## Insert an equation

`Range.insertOoxml(ooxml, location)` inserts one inline equation from a Flat OPC package and returns its range:

```ts
const ooxml =
  '<pkg:package xmlns:pkg="http://schemas.microsoft.com/office/2006/xmlPackage">' +
  '<pkg:part pkg:name="/word/document.xml" pkg:contentType="application/' +
  'vnd.openxmlformats-officedocument.wordprocessingml.document.main+xml">' +
  '<pkg:xmlData><w:document xmlns:w="http://schemas.openxmlformats.org/' +
  'wordprocessingml/2006/main" xmlns:m="http://schemas.openxmlformats.org/' +
  'officeDocument/2006/math"><w:body><w:p><m:oMath><m:r><m:t>E=m</m:t></m:r>' +
  '<m:sSup><m:e><m:r><m:t>c</m:t></m:r></m:e><m:sup><m:r><m:t>2</m:t></m:r>' +
  '</m:sup></m:sSup></m:oMath><w:r><w:t xml:space="preserve"> holds.</w:t>' +
  '</w:r></w:p></w:body></w:document></pkg:xmlData></pkg:part></pkg:package>';

await runtime.run(async (context) => {
  const hit = context.document.body.search('the relation ').getFirst();
  const inserted = hit.insertOoxml(ooxml, 'After');
  inserted.load('text');
  await context.sync();
  return inserted.text; // U+FFFC, then ' holds.'
});
```

It accepts `Before`, `After`, `Start`, `End`, and `Replace` within one paragraph. The equation reads as U+FFFC and can land inside an eligible hyperlink, content control, or your own pending insertion. With `TrackMineOnly`, it is one tracked insertion.

The package holds a `/word/document.xml` part and an optional `/_rels/.rels` part with one internal `officeDocument` relationship. The body holds one paragraph with one inline `m:oMath` of OMML elements. Plain runs of `w:rPr`, `w:t`, and `w:tab` can surround it.

The runtime uses a bounded parser and never fetches or evaluates anything. Other input refuses, and nothing changes:

| Error | `innerError.code` | Cause |
| --- | --- | --- |
| `NotSupported` | `edit.ooxml-unsupported` | Other parts, relationships, external targets, or binary data. Also two paragraphs or equations, no equation, `m:oMathPara`, paragraph properties, a section break, a bare `w:document`, or an element outside the allowlist, such as a field or picture. |
| `InvalidArgument` | `edit.invalid-argument` | Malformed XML, a DTD, an entity, or `Replace` across paragraphs |
| `InvalidArgument` | `edit.resource-limit` | Over 256 KiB or 8,192 elements, a value over 4,096 characters, or math deeper than 64 levels |
| `InvalidArgument` | `edit.protected-content` | The insertion point is in content-locked or data-bound content |
| `NotImplemented` | `edit.tracked-foreign-revision-unsupported` | With `TrackMineOnly`, the point is in another author's structural change |
| `ConflictingChanges` | None | Another edit in the sync changes the same paragraph |

## Replace the whole document

`Body.insertFileFromBase64(base64File, 'Replace')` replaces the whole document with a DOCX file and returns the range of the new body. The file's headers, footers, styles, numbering, theme, settings, comments, and tracked changes replace the current ones, so formatting follows the file.

```ts
await runtime.run(async (context) => {
  const range = context.document.body.insertFileFromBase64(docxBase64, 'Replace');
  range.load('text');
  await context.sync();
  return range.text;
});
```

The replacement is one edit. In a browser editor, one undo step takes it back. In a collaboration session, from a browser or a server runtime, other participants receive it as an ordinary edit. A file that matches the document changes nothing.

Make the replacement the only write in its sync. Loads on other objects in the same sync answer the document before the replacement. After the sync, an object you read earlier refuses with `InvalidObjectPath` when its content is gone, so read it again.

Only `Replace` on `document.body` is supported. Other calls refuse, and nothing changes:

| Error | `innerError.code` | Cause |
| --- | --- | --- |
| `NotSupported` | None | `Start` or `End`; a header, footer, or note body |
| `NotSupported` | `edit.preview-unsupported` | A call inside a preview callback |
| `NotSupported` | `edit.tracked-operation-unsupported` | `changeTrackingMode` is `TrackMineOnly`, or the browser editor is suggesting, because the replacement records no tracked changes |
| `NotSupported` | `edit.unsupported-content` | The file names another main document part, or the difference cannot apply as one edit |
| `NotSupported` | `edit.resource-limit` | The file is over 128 MiB |
| `NotSupported` | `edit.operation-unsupported` | The run joins an editor history group |
| `InvalidArgument` | None or `edit.invalid-argument` | Empty or invalid base64, an unknown location, or a file that is not a DOCX package |
| `NotImplemented` | `edit.protected-content` | Enforced document protection permits only comments, form fields, tracked changes, or no edits; or the document holds a locked or data-bound content control |
| `PreviewActive` | `edit.preview-active` | The browser editor shows a preview |
| `GeneralException` | `edit.read-only` | The browser editor is open for viewing |
| `GeneralException` | `edit.collaboration-not-ready` or `edit.refused` | The collaboration session cannot take edits now, or the room refused the edit |
| `ConflictingChanges` | None | Another write shares the sync |

The base64 must be canonical, with no line breaks or spaces. To replace the document from editor code instead of a script, see [Replace the document as one undoable edit](/docs/2.x/guides/loading-and-saving#replace-the-document-as-one-undoable-edit).

## Refresh ranges after edits

A `Range` keeps the paragraph identities and UTF-16 offsets from when you found it:

| Change                           | Result                               |
| -------------------------------- | ------------------------------------ |
| An earlier edit in its paragraph | The range fails with `StaleDocument` |
| A later edit, or formatting      | The range stays valid                |
| Deleting an endpoint paragraph   | The range becomes invalid            |

Search again after an edit. Tracking a proxy keeps it alive but does not make its range follow edits, unlike Office.js. For recovery, see [Batching, loading, and errors](/docs/2.x/editor-api/batching-and-errors).

## Limits

- Disjoint plain-text edits in ordinary paragraphs can share a sync, using the batch's initial coordinates.
- Insertions at one range position keep their call order. Repeated paragraph or body `Start` insertions prepend, and `End` insertions append.
- Overlapping edits refuse. So do text edits mixed with formatting, hyperlink, or structural changes in one paragraph.
- Rich paragraphs and browser suggesting edits allow one text edit per paragraph per sync.
- Text extraction and reinsertion do not preserve arbitrary document structure.
- The API reads no OOXML strings. `Range.shapes` is not available.
- For other members, see the [API member directory](/docs/2.x/editor-api/reference).
