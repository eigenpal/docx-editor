The API inserts and edits inline PNG and JPEG pictures. For runtime setup, see [Runtime and setup](/docs/2.x/editor-api/runtime).

## Insert and size a picture

The following server example inserts a PNG after the first paragraph and sizes it:

```ts
import { readFile } from 'node:fs/promises';

const imageBase64 = (await readFile('logo.png')).toString('base64');
await runtime.run(async (context) => {
  const paragraph = context.document.paragraphs.getFirst();
  paragraph.load('text');
  await context.sync();
  const anchor = paragraph.getRange('End');
  await context.sync();
  const picture = anchor.insertInlinePictureFromBase64(imageBase64, 'After');
  await context.sync();
  picture.altTextDescription = 'Company logo';
  picture.lockAspectRatio = true;
  picture.width = 96;
  await context.sync();
});
```

`Range.insertInlinePictureFromBase64(base64EncodedImage, location)` follows these rules:

- It accepts the locations `Replace`, `Start`, `End`, `Before`, and `After`.
- It takes base64 PNG or JPEG bytes. Invalid or unsupported bytes refuse.
- Sync the insertion before you configure the returned `InlinePicture`.

For loads and failures around that sync, see [Batching, loading, and errors](/docs/2.x/editor-api/batching-and-errors).

## Read picture properties

The following example reads sizes and descriptions:

```ts
const pictures = await runtime.run(async (context) => {
  const collection = context.document.body.inlinePictures;
  collection.load('items/width,items/height,items/altTextDescription');
  await context.sync();
  return collection.items.map(({ width, height, altTextDescription }) => ({
    width,
    height,
    altTextDescription,
  }));
});
```

`Body.inlinePictures` and `Range.inlinePictures` return an `InlinePictureCollection` with `items`, `getFirst()`, `getLast()`, `getFirstOrNullObject()`, and `getLastOrNullObject()`. A range collection includes pictures fully inside the range.

## Configure a picture

| `InlinePicture` member | Behavior                                                  |
| ---------------------- | --------------------------------------------------------- |
| `width`, `height`      | Positive dimensions in points                             |
| `lockAspectRatio`      | Aspect-ratio lock; changing one dimension keeps the ratio |
| `altTextDescription`   | Alternative description for readers                       |
| `delete()`             | Deletes the picture                                       |

When the aspect ratio is locked, conflicting `width` and `height` assignments refuse.

## Limits

- Queue a picture insertion as the only write in its sync.
- Tracking does not support picture insertion, removal, or formatting.
- Protected targets and pending revisions can refuse edits.
- No URL replacement, cropping, rotation, floating picture writes, or picture bullets exist.
- Server, browser, and collaborative runtimes all insert pictures. In collaboration, the picture, its media part, and its relationship replicate to every participant.
- To list floating shapes and edit text boxes, see [Read and edit text boxes](/docs/2.x/editor-api/page-layout-and-stories#read-and-edit-text-boxes).
