A runtime connects the document model to one host. Get document objects inside `runtime.run()`. The package requires the [EigenPal Pro License](https://github.com/eigenpal/docx-editor/blob/main/packages/editor-api/LICENSE.md).

## Create a server runtime

Install the API and its engine peer dependency:

```bash
npm install @docx-editor.dev/editor-api @docx-editor.dev/core
```

The following example replaces a unique token and saves a separate file:

```ts
import { readFile, writeFile } from 'node:fs/promises';
import { DocxEditor } from '@docx-editor.dev/editor-api';

const runtime = await DocxEditor.createServer(await readFile('input.docx'), {
  author: 'Document agent',
});
try {
  await runtime.run(async (context) => {
    const matches = context.document.body.search('{{customer}}', { matchCase: true });
    matches.load('items');
    await context.sync();
    if (matches.items.length !== 1) throw new Error('Expected one customer');
    matches.items[0]!.insertText('Ada', 'Replace');
    await context.sync();
  });
  await writeFile('output.docx', await runtime.save());
} finally {
  runtime.dispose();
}
```

- Requires Node.js `^20.16.0 || >=22.3.0` and one resolved copy of `@docx-editor.dev/core`.
- `createServer()` parses before it resolves and does not retain the input array.
- `save()` returns a fresh, caller-owned `Uint8Array`. It does not update an open editor.
- `dispose()` is idempotent. Later calls fail with `RuntimeDisposed`, and tracked objects become invalid.

## Choose a host

| Factory | Entry | Returns | Save through | Notes |
| --- | --- | --- | --- | --- |
| `DocxEditor.createServer(bytes, options?)` | Root and `/browser` | `Promise<DocxEditorServerRuntime>` | `runtime.save()` |  |
| `DocxEditor.createCollaborative(bytes, collaboration, options?)` | Root and `/browser` | `Promise<DocxEditorServerRuntime>` | `runtime.save()` | Joins an `EditorCollaborationSession` that your application owns |
| `DocxEditor.createBrowser(editor, options?)` | `/browser` only | `DocxEditorRuntime`, synchronously | The owning editor | Takes `CreateBrowserOptions` from the browser entry |

`DocxEditorNamespace` types each entry's factories, which are DocxEditor extensions outside Office.js. For a collaborative workflow, see [Let a server agent propose redlines](/docs/2.x/pro/collaboration#let-a-server-agent-propose-redlines).

### Drive an open browser editor

Pass an attached `DocxEditorInstance` from the core, React, or Vue integration:

```ts
import { DocxEditor } from '@docx-editor.dev/editor-api/browser';

const runtime = DocxEditor.createBrowser(editor, { author: 'Document reviewer' });
try {
  await runtime.run(async (context) => {
    const first = context.document.paragraphs.getFirstOrNullObject();
    first.load('text');
    await context.sync();
    if (!first.isNullObject) first.font.bold = true;
    await context.sync();
  });
} finally {
  runtime.dispose();
}
```

Edits join the editor's undo history. The browser runtime has no `save()`, so save through the editor. Disposal does not destroy the editor.

## Configure a runtime

| Option | Hosts | Meaning |
| --- | --- | --- |
| `author` | All | Author for comments, replies, and tracked edits |
| `revisionTextView` | All | `allMarkup` (default) or `original`, which hides pending insertions and keeps pending deletions in reads and search |
| `limits` | Server and collaborative | `DocumentLimits` for ZIP, XML, part, and relationship parsing |
| `pagination` | Server and collaborative | `ServerPaginationOptions`: required `measurer`, optional `producer`, for page-field results |
| `modules` | Server and collaborative | `EditorModule[]` for the DOM-free host; `id` and optional `collaboration`, no browser UI |

`CreateCollaborativeOptions` uses `CreateServerOptions`. Your application owns pagination font resources and their cleanup. For setup, see [Fields and pagination](/docs/2.x/editor-api/fields).

### Inspect capabilities

Read `runtime.capabilities` or `context.capabilities` without `load()`. `DocumentCapabilities` stays frozen for the runtime's lifetime.

| Host | Reported capabilities |
| --- | --- |
| Server and collaborative | `document`, `save`, `events` |
| Browser | `events`, `selection`, `scrolling`, `layout`, `preview`, and `document` when a document is open |

Capabilities do not prove write permission. Browser review writes also need the Pro review module and an editable document. The `events` flag adds no subscription API to the runtime.

## Join an editor history group

By default, each `context.sync()` that writes is one undo step. To join a larger undo step, pass an open handle from `editor.beginHistoryGroup()`:

```ts
// `keys` are the other party's change keys from `editor.getReviewItems()`.
const decision = editor.beginHistoryGroup();
try {
  const resolved = editor.exec(
    { type: 'resolveAllReviewChanges', action: 'reject', keys },
    { historyGroup: decision }
  );
  if (!resolved.ok) throw new Error(resolved.reason);
  await runtime.run({ historyGroup: decision }, async (context) => {
    const target = context.document.body.search('30 days').getFirst();
    target.insertText('45 days', 'Replace');
    await context.sync();
  });
} finally {
  decision.end();
}
```

One undo reverts both edits. `RunOptions` also accepts `previousObjects`, which adopts tracked objects.

| Case | Result |
| --- | --- |
| Run joins the group | Counts as one group write. `decision.lastOutcome?.kind` is `started`, `extended`, `split`, or `none`; `lastOutcome` is `null` before the first write. A `split` emits one `historyDiagnostic` event |
| Server or collaborative runtime | `NotSupported` before the callback starts |
| Closed handle, or a handle from another editor | `InvalidArgument`, `target: 'historyGroup'`; the callback does not run |
| Handle closes during the run | The next `context.sync()` rejects the same way and writes nothing |
| Run without the option | Never joins a group |

Office.js `run` has no options. For collaborative runtimes, see [Undo an agent operation](/docs/2.x/pro/collaboration#undo-an-agent-operation). For group boundaries, see [Group a review decision](/docs/2.x/core#group-a-review-decision).

## Preview other wording before you write it

`runtime.preview(callback)` shows edits in the page without writing them. The callback gets an ordinary request context over a private copy:

```ts
const proposal = await model.propose(clauseText); // Slow work first.
const preview = await runtime.preview(async (context) => {
  context.document.changeTrackingMode = 'TrackMineOnly';
  const range = context.document.body.search(proposal.find).getFirst();
  range.insertText(proposal.replace, 'Replace');
  await context.sync();
});
preview.reveal(); // Scroll to the first changed body paragraph.

if (accepted) await preview.commit();
else preview.discard();
```

Preview writes stay private until `commit()`: the live document, undo history, and peers see nothing. Do not wait for a model or server inside the callback. The live editor stays editable while the callback runs, so concurrent edits can make the preview stale before it appears.

| Member | Behavior |
| --- | --- |
| `status` | `active`, `stale` (the live document moved), or `ended`; watch with `onStatusChanged(listener)` |
| `result` | Plain data that the callback returned |
| `commit(options?)` | Replays the recorded batches as one undo step; never re-runs the callback. A tracking mode the callback set stays set on the runtime for later runs |
| `commit({ rebase: true })` | Applies the preview to the current document. Ranges follow their original target text, even after unrelated edits earlier in the same paragraph |
| `discard()` | Ends the preview without writing, including a tracking mode the callback set |

While a preview shows:

| Action | Result |
| --- | --- |
| Another `preview()`, or a `run()` write | Rejects with `PreviewActive` |
| An editor edit | Refused; `snapshot().editable` is `false` |
| A `run()` read | Sees the live document |
| Commit, discard, disposal, or a document load, detach, or move | Ends the preview |

### Handle preview changes

`commit()` failures need different recovery:

| Failure | Error | State and recovery |
| --- | --- | --- |
| Live document moved | `StaleDocument` | Nothing written; preview stays open with status `stale`. Retry with `rebase: true` |
| Rebase diverges: a replayed read differs, or a write would overwrite changed text | `StaleDocument`, `innerError.code` `edit.preview-diverged` | Nothing written; preview ends. Read again |
| Preview already ended | `PreviewEnded` | Start a new preview |
| Live document refuses a replayed batch | The live refusal | Writes already replayed are undone as one step; preview ends |
| Live replay and its undo rollback both fail | `GeneralException`, target `preview.rollback` | Inspect the document before you retry |

Editor and preview status listeners run after the complete commit. Listener exceptions do not change the commit result.

`preview()` rejects and shows nothing in these cases:

| Case | Error | `innerError.code` |
| --- | --- | --- |
| Server or collaborative runtime | `NotSupported`, target `preview` | None |
| Viewing mode, external refresh, or input method composition | `NotSupported`, target `preview` | `edit.read-only`, `edit.refresh-in-progress`, `edit.preview-composing` |
| Another preview is open | `PreviewActive` | `edit.preview-active` |
| No document is mounted | `DocumentUnavailable` | None |
| A write the preview cannot show | `NotSupported` from `sync()` | `edit.preview-unsupported` |
| A write the live editor refuses | The `run()` error, from `sync()` | The live reason, such as `edit.protected-content` |

A preview shows text, paragraph, formatting, comment, line break, and tracked-change edits, including text edits in headers, footers, and notes. It refuses table, picture, shape, field, list, hyperlink, content control, bookmark, page setup, page and section break, selection, and story creation or deletion writes. Office.js has no preview.

## Bound input parsing

Pass `limits` to `createServer()` or `createCollaborative()`:

| Type                | Fields                                                                    |
| ------------------- | ------------------------------------------------------------------------- |
| `DocumentLimits`    | Optional `zip`, `xml`, `maxXmlParts`, `maxRelationships`                  |
| `DocumentZipLimits` | Required `maxEntries`, `maxTotalBytes`; optional `maxRatio` (default 200) |
| `DocumentXmlLimits` | Required `maxBytes`; optional `maxElements` (default 10,000,000 per part) |

- Counts and byte budgets are finite nonnegative integers. Ratios can be fractional.
- `maxRatio` compares uncompressed and archive sizes, only once the uncompressed total exceeds 8 MiB.
- Hard caps per XML part: 50,000,000 elements, 64 MiB, and 256 nested levels. These do not guarantee enough memory.
- Malformed input or invalid limits fail with `InvalidArgument`. An exceeded budget fails with `ResourceLimitExceeded` and a `limit` field.
