`@docx-editor.dev/editor-api` edits DOCX files through a supported subset of the Office.js object model. It runs on a server over DOCX bytes or in the browser against an open editor.

## Install and edit a document

Install the API and its engine peer dependency:

```bash
npm install @docx-editor.dev/editor-api @docx-editor.dev/core
```

The following server example replaces every match and saves the result:

```ts
import { readFile, writeFile } from 'node:fs/promises';
import { DocxEditor } from '@docx-editor.dev/editor-api';

const runtime = await DocxEditor.createServer(await readFile('contract.docx'), {
  author: 'Review bot',
});
try {
  await runtime.run(async (context) => {
    const matches = context.document.body.search('$50k');
    matches.load('items');
    await context.sync(); // Read the matching ranges.

    for (const match of matches.items) match.insertText('$500k', 'Replace');
    await context.sync(); // One atomic batch: all of the writes, or none.
  });
  await writeFile('contract.filled.docx', await runtime.save());
} finally {
  runtime.dispose();
}
```

To make these edits tracked changes, set `context.document.changeTrackingMode = 'TrackMineOnly'` first. For supported tracked operations, see [Tracked changes](/docs/2.x/editor-api/revisions).

## Choose a host

| Host | Factory | Save through | Requirements |
| --- | --- | --- | --- |
| Server | `DocxEditor.createServer()` | `runtime.save()` | DOCX bytes and Node.js `^20.16.0 \|\| >=22.3.0` |
| Browser | `DocxEditor.createBrowser()` from `/browser` | The owning editor | An attached core, React, or Vue editor |
| Collaborative | `DocxEditor.createCollaborative()` | `runtime.save()` | DOCX bytes and an `EditorCollaborationSession` |

For complete host examples, options, and capabilities, see [Runtime and setup](/docs/2.x/editor-api/runtime).

## Requirements and limits

- The package uses the [EigenPal Pro License](https://github.com/eigenpal/docx-editor/blob/main/packages/editor-api/LICENSE.md). For options, see [pricing](https://www.docx-editor.dev/pricing).
- The API and editor adapters must share one resolved copy of the `@docx-editor.dev/core` peer dependency.
- Comments, replies, and tracked edits require an `author`. Browser review writes also require the Pro review module and an editable document.
- Only an explicit `await context.sync()` applies queued operations. Returning from `run()` does not.
- A failed load after a commit can leave writes applied. If `debugInfo.innerError.code` is `edit.read-after-commit`, do not repeat the edit. For recovery, see [Batching, loading, and errors](/docs/2.x/editor-api/batching-and-errors).
- The API covers a supported subset of Office.js. For differences, see [Office.js compatibility](/docs/2.x/editor-api/office-js-api).
