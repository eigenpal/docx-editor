Set character formatting through `Body.font`, `Paragraph.font`, or `Range.font`, and paragraph formatting on `Paragraph`. The API has no `ParagraphFormat` object and no style-creation API. Create a `runtime` with [Runtime and setup](/docs/2.x/editor-api/runtime).

## Format a phrase

Batch assignments on one proxy, then sync once:

```ts
await runtime.run(async (context) => {
  const matches = context.document.body.search('Confidential', {
    matchCase: true,
  });
  matches.load('items');
  await context.sync();
  for (const match of matches.items) {
    const font = match.font;
    font.bold = true;
    font.color = '#A00000';
    font.highlightColor = 'Yellow';
    font.underline = 'Single';
  }
  await context.sync();
});
```

Assignments on one `Font` proxy coalesce within a sync, but overlapping proxies can conflict. Bold, italic, size, and name writes also update complex-script properties that control the text.

## Choose font properties

Font getters return `null` for mixed, unset, or inherited values. Reads report authored values, not the rendered result, so never turn `null` into a write:

```ts
await runtime.run(async (context) => {
  const font = context.document.body.font;
  font.load(['bold', 'size']);
  await context.sync();
  if (font.size !== null) console.log(`Authored size: ${font.size} pt`);
});
```

| `Font` property | Write values |
| --- | --- |
| `bold`, `italic`, `strikeThrough` | Boolean |
| `name` | Font family name. Your host supplies the font resources. |
| `size` | Positive finite points within the OOXML range |
| `color` | `#RRGGBB` |
| `underline` | `None`, `Single`, `Word`, `Double`, `Thick`, `Dotted`, `DottedHeavy`, `DashLine`, `DashLineHeavy`, `DashLineLong`, `DashLineLongHeavy`, `DotDashLine`, `DotDashLineHeavy`, `TwoDotDashLine`, `TwoDotDashLineHeavy`, `Wave`, `WaveHeavy`, `WaveDouble`. `Mixed`, `Hidden`, and `DotLine` refuse. |
| `highlightColor` | `Yellow`, `Lime`, `Turquoise`, `Pink`, `Blue`, `Red`, `DarkBlue`, `Teal`, `Green`, `Purple`, `DarkRed`, `Olive`, `Gray`, `LightGray`, `Black`, `White`, or their hex colors. Reads return `#RRGGBB` or `null`. |
| `subscript`, `superscript` | Boolean. Both cannot be `true` in one write. |

`UnderlineType` provides the enum values.

### Clear highlighting

The Office.js reference documents `null` for clearing highlights, but the setter declares `string`. Use an explicit annotation:

```ts
await runtime.run(async (context) => {
  const font = context.document.body.font;
  // @ts-expect-error Office.js declares string but documents null clearing.
  font.highlightColor = null;
  await context.sync();
});
```

See the [`Font.highlightColor` reference](https://learn.microsoft.com/en-us/javascript/api/word/word.font#word-word-font-highlightcolor-member).

## Format paragraphs

Paragraph measurements use points:

```ts
await runtime.run(async (context) => {
  const paragraph = context.document.paragraphs.getFirst();
  paragraph.alignment = 'Left';
  paragraph.leftIndent = 18;
  paragraph.firstLineIndent = -9;
  paragraph.spaceAfter = 6;
  await context.sync();
});
```

| Property | Values |
| --- | --- |
| `leftIndent`, `rightIndent`, `spaceBefore`, `spaceAfter`, `lineSpacing` | Finite points within supported bounds |
| `firstLineIndent` | Finite points. A negative value makes a hanging indent. |
| `alignment` | `Left`, `Centered`, `Right`, `Justified`. `Mixed` and `Unknown` are read-only values. |

Assignments on one proxy coalesce per sync. Paragraph properties and `style` also apply in an unlocked data-bound control. With `TrackMineOnly`, these writes record property revisions.

### Right-to-left paragraphs

Office.js has no paragraph direction member, so `Paragraph.readingOrder` is a DocxEditor addition. Its values follow `Word.SectionDirection`:

```ts
await runtime.run(async (context) => {
  const paragraph = context.document.body.paragraphs.getFirst();
  paragraph.readingOrder = 'RightToLeft';
  await context.sync();
});
```

- A read returns the displayed direction after styles. Writing back a value you read changes nothing.
- Other values fail with `InvalidArgument`.
- In a right-to-left paragraph, `alignment` `Left` aligns to the right margin. A `readingOrder` write keeps `alignment` and adds no `w:rtl` to runs.
- When `style` and `readingOrder` share a sync, direction resolves against the new style.

For editor commands, see [Right-to-left text](/docs/2.x/guides/right-to-left).

## Apply an existing style

Assign the display name of a paragraph style the document defines:

```ts
paragraph.style = 'Heading 1'; // The document must define this name.
await context.sync();
```

`Body.style`, `Paragraph.style`, and `Range.style` accept paragraph style names only. Character, table, and list style names refuse, and assigning a name never creates a style. A read can return `null` for mixed styles, for a style that shares its name with an earlier paragraph style, or when no explicit or default paragraph style resolves.

### List the defined styles

Call `Document.getStyles()` and filter the visible paragraph styles:

```ts
const styles = context.document.getStyles();
styles.load('items/nameLocal,items/type,items/visibility,items/unhideWhenUsed,items/priority');
await context.sync();

const names = styles.items
  .filter((style) => style.type === 'Paragraph' && (style.visibility || style.unhideWhenUsed))
  .sort((a, b) => a.priority - b.priority || a.nameLocal.localeCompare(b.nameLocal))
  .map((style) => style.nameLocal);
```

`styles.getByNameOrNullObject(name)` finds one style, ignoring case and surrounding spaces, and prefers the paragraph style. `styles.getCount()` returns the count. `Style` properties are read-only:

| Property | Value |
| --- | --- |
| `nameLocal` | The declared `w:name`, such as `heading 1` |
| `type` | `Paragraph`, `Character`, `Table`, or `List` |
| `builtIn` | `false` when the style states `w:customStyle` |
| `baseStyle` | The `w:basedOn` style of the same type, or an empty string |
| `nextParagraphStyle` | The `w:next` paragraph style, or the style itself. An empty string for other style types, or when `w:next` names no listed paragraph style |
| `linked` | `true` when `w:link` pairs a paragraph style with a listed character style, or the reverse. Other links return `false` |
| `visibility` | `false` for `w:semiHidden` or `w:hidden` |
| `priority` | `w:uiPriority`, or 99 |
| `quickStyle` | `true` for `w:qFormat` |
| `unhideWhenUsed` | `true` for `w:unhideWhenUsed` |

Styles follow source order. The last duplicate ID wins, and later duplicate names of the same type are omitted.

`Table.style` takes the `nameLocal` of a `Table` style. See [Tables and cells](/docs/2.x/editor-api/tables).

## Set or remove a hyperlink

Assign a permitted URL to `Range.hyperlink`, or an empty string to remove it:

```ts
range.hyperlink = 'https://example.com/terms';
await context.sync();
```

- The runtime validates the URL.
- A partial span inside a link can be retargeted or unlinked.
- Collapsed ranges and complex or nested link wrappers refuse.
- There is no `Hyperlink` object.

## Limits

- Only the first 4096 `w:style` definitions count, and names over 255 characters are not read. Styles without a valid name or type are left out.
- A `style` write with no styles part refuses with `edit.no-styles-defined`. An undefined name refuses with `edit.style-not-defined`.
- The API cannot add, delete, or change styles. `Style` has no `font` or `paragraphFormat`.
- Never switch tracking off to bypass a refused tracked write.
- Hidden paragraph marks (`w:vanish` on the mark) join paragraphs on screen only in a bounded subset of body paragraphs. When hidden marks with visible content cannot join, the export layout's `contentWarnings` report `unsupported-style-separator`. Saving still preserves the source content.
- For style cascade and justification rendering, see [DOCX fidelity](/docs/2.x/docx-fidelity).
