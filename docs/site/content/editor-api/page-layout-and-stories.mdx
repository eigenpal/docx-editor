A story is a text container: the main body, a header, a footer, a note, or a text box. A section controls page layout for part of the main story. For runtime setup, see [Runtime and setup](/docs/2.x/editor-api/runtime).

## Set page geometry

Resolve a section before you load or change its page setup:

```ts
await runtime.run(async (context) => {
  const section = context.document.sections.getFirst();
  await context.sync();
  const setup = section.pageSetup;
  setup.orientation = 'Landscape';
  setup.leftMargin = 54;
  setup.rightMargin = 54;
  await context.sync();
});
```

| `PageSetup` property | Unit or domain |
| --- | --- |
| `pageWidth`, `pageHeight` | Positive dimensions in points |
| `topMargin`, `bottomMargin`, `leftMargin`, `rightMargin` | Finite margins in points |
| `orientation` | `Portrait` or `Landscape` (`PageOrientation`) |

The engine validates the resulting geometry. Page setup writes refuse while tracking changes. Update page fields afterward in a separate sync; see [Fields and pagination](/docs/2.x/editor-api/fields).

`Section.body` returns the shared main body, not a section-limited slice. `Section.getNext()` fails with `ItemNotFound` after the last section.

## Address headers and footers

The following example writes a primary footer:

```ts
await runtime.run(async (context) => {
  const section = context.document.sections.getFirst();
  await context.sync();
  const footer = section.getFooter('Primary');
  footer.load('text');
  await context.sync();
  footer.insertText('Internal document', 'End');
  await context.sync();
});
```

`getHeader(type)` and `getFooter(type)` take `Primary`, `FirstPage`, or `EvenPages` and return a `Body` story. A missing story reads empty, and its first supported insertion creates it. Linkage and first-page toggles are unavailable.

## Insert a break

The following example adds a page break after the first paragraph:

```ts
await runtime.run(async (context) => {
  const paragraph = context.document.paragraphs.getFirst();
  paragraph.load('text');
  await context.sync();
  const anchor = paragraph.getRange('End');
  await context.sync();
  anchor.insertBreak('Page', 'After');
  await context.sync();
});
```

`Range.insertBreak(breakType, insertLocation)` takes `Before` or `After`:

| `BreakType` | Where | Batching | With `TrackMineOnly` |
| --- | --- | --- | --- |
| `Line` | Any story, including cells and text boxes | Can share a sync with other edits | Tracked insertion |
| `Page` | An inserted run in its paragraph | Alone in its write sync | Tracked insertion; reject removes it |
| `SectionNext` | A main-body paragraph outside a table | Alone in its write sync | Tracked insertion; reject joins the paragraphs and removes the section. Refuses with `NotSupported` if the section does not start on a new page |
| `Next` and other section kinds | None | Refused | Refused |

Read sections again after a section break. Do not reuse old indexes as section identities.

## Read footnotes and endnotes

The following example reads footnote text in two batches:

```ts
const notes = await runtime.run(async (context) => {
  const collection = context.document.body.footnotes;
  collection.load('items');
  await context.sync();
  for (const note of collection.items) note.load(['type', 'text']);
  await context.sync();
  return collection.items.map((note) => ({ type: note.type, text: note.text }));
});
```

| Member | Behavior |
| --- | --- |
| `Body.footnotes`, `Body.endnotes` | Referenced notes in order; a cell body lists its own references only |
| `NoteItem.type`, `text`, `body` | `Footnote` or `Endnote`, plain text, and the note story |
| `NoteItem.getNext()` | Next note of the same kind; `ItemNotFound` after the last |
| `NoteItem.delete()` | Removes the note and its references; sync pending work first and run it alone |

Note creation is unavailable. `Document.footnotes` and `Document.endnotes` are DocxEditor extensions that enumerate note parts.

## Read and edit text boxes

The following example reads every text box and shape story, then redlines one match:

```ts
import { ShapeType } from '@docx-editor.dev/editor-api';

await runtime.run(async (context) => {
  const shapes = context.document.body.shapes.getByTypes([
    ShapeType.textBox,
    ShapeType.geometricShape,
  ]);
  shapes.load('items/id');
  await context.sync();

  const bodies = shapes.items.map((shape) => shape.body.load('text'));
  await context.sync(); // Resolve each story before you search it.

  const target = bodies.find((body) => body.text.includes('Acme Holdings'));
  if (!target) throw new Error('No text box holds the phrase.');
  const matches = target.search('Acme Holdings', { matchCase: true });
  matches.load('items');
  await context.sync();

  context.document.changeTrackingMode = 'TrackMineOnly';
  matches.items[0]!.insertText('Beta Logistics', 'Replace');
  await context.sync();
});
```

`Body.shapes` and `Paragraph.shapes` list shapes in reading order. A `Shape` has read-only `id`, `name`, and `type`, plus `body`. `ShapeType` is `TextBox`, `GeometricShape`, `Picture`, `Group`, `Canvas`, or `Unsupported`.

Main-body reads, search, comments, and revisions exclude text-box content. If `body.text` is empty or short, read the text boxes first. Do not insert into an empty anchor paragraph; its text appears behind the boxes.

| Shape | `body` behavior |
| --- | --- |
| Text box or geometric shape in the body, a header, or a footer | Its own story |
| Such a shape with no stored text story | Reads empty; writes refuse with `InvalidArgument`, `innerError.code` `edit.unsupported-story` |
| Picture, group, line, connector, or linked continuation text box | Refuses with `InvalidArgument` |
| Shape inside a note or text box | Listed; `body` refuses with `InvalidArgument` |
| Inline picture | Listed as `Picture`; also in `inlinePictures` |

## Limits

- Separate writes to different stories into different syncs.
- Text-box `insertComment()` refuses with `InvalidArgument`. Review text-box changes through that body's revisions.
- Repeated `getByTypes()` calls keep only types that every filter allows. Unknown types refuse with `InvalidArgument`.
- Duplicate or missing DrawingML drawing IDs refuse shape enumeration.
- Shapes selected through a legacy VML fallback are not listed. Saving a DrawingML text box also updates its retained VML copy.
- A standalone VML shape (`w:pict`) is listed only with a numbered shape ID that no other shape uses. Text in an unlisted VML text box is unreachable, and its tracked changes stay with the owner story.
- A VML shape's `id` is the number in `o:spid`, or in `id` when `o:spid` is absent. Its `name` is the `id` attribute.
- VML template `#_x0000_t202` returns `TextBox`, and other text-bearing VML shapes return `GeometricShape`. VML pictures return `Picture`. VML text paths, horizontal rules, and embedded object previews return `Unsupported`.
- Shape geometry, text frames, and shape insertion or deletion are unavailable.
