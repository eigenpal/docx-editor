A story is a text container, such as the main body, a header, a footer, or a note. A section controls page layout for part of the main story.

Create a `runtime` with [Runtime and setup](/docs/2.x/editor-api/runtime). Use `context` and document proxies inside `runtime.run()`.

## Inspect sections and page setup

`Document.sections` returns `SectionCollection` with `items` and `getFirst()`. `Section.getNext()` returns the next section and fails with `ItemNotFound` at the end. `Section.body` returns the shared main body, not a section-limited text slice. `Section.pageSetup` addresses that section's page properties.

Resolve a section before loading or changing its page setup:

```ts
await runtime.run(async (context) => {
  const section = context.document.sections.getFirst();
  await context.sync();
  const setup = section.pageSetup;
  setup.load(['pageWidth', 'pageHeight', 'orientation']);
  await context.sync();
  console.log(setup.pageWidth, setup.pageHeight);
  setup.orientation = 'Landscape';
  setup.leftMargin = 54;
  setup.rightMargin = 54;
  await context.sync();
});
```

| `PageSetup` property | Unit or domain |
| --- | --- |
| `pageWidth`, `pageHeight` | Positive supported dimensions in points |
| `topMargin`, `bottomMargin`, `leftMargin`, `rightMargin` | Supported finite margin values in points |
| `orientation` | `Portrait` or `Landscape`, also available through `PageOrientation` |

Assignments on one page-setup proxy coalesce per sync. The engine validates dimensions, margins, and the resulting page geometry. The runtime rejects page-layout changes while tracking changes. After layout changes, update page fields separately using [Fields and pagination](/docs/2.x/editor-api/fields).

## Address headers and footers

`Section.getHeader(type)` and `getFooter(type)` return `Body` proxies. `HeaderFooterType` accepts `Primary`, `FirstPage`, or `EvenPages`. Each variant is its own story scope. A missing header or footer returns a deferred empty body. Its first supported content insertion creates the missing story.

This example writes a primary footer after resolving its body:

```ts
await runtime.run(async (context) => {
  const section = context.document.sections.getFirst();
  await context.sync();
  const footer = section.getFooter('Primary');
  footer.load('text');
  await context.sync();
  footer.insertText('Internal document', 'End');
  await context.sync();
});
```

Use the returned body's paragraph, search, bookmark, field, and review accessors for that story. `Body.bookmarks` and `Body.revisions` do not combine separate stories. The public surface does not expose header/footer linkage or first-page layout toggles.

## Insert page and section breaks

`Range.insertBreak(breakType, insertLocation)` supports `Page` and `SectionNext`. The insertion location must be `Before` or `After`. A next-page section break requires a main-body paragraph outside a table. The exported `BreakType` also names unsupported kinds. The runtime rejects `Line`, `Next`, and other section break kinds.

Queue break insertion alone in its write transaction:

```ts
await runtime.run(async (context) => {
  const paragraph = context.document.paragraphs.getFirst();
  paragraph.load('text');
  await context.sync();
  const anchor = paragraph.getRange('End');
  await context.sync();
  anchor.insertBreak('Page', 'After');
  await context.sync();
});
```

Read affected sections again after a section break changes their structure. Do not reuse old indexes as permanent section identities.

## Read footnotes and endnotes

`Body.footnotes` and `Body.endnotes` return distinct referenced notes in reference order. Each returns `NoteItemCollection`, which exposes `items` and `getFirst()`. A table-cell body includes only its own references. A `NoteItem` exposes loaded `type` and `text`, plus its own `body`. `NoteItemType` is `Footnote` or `Endnote`. `NoteItem.text` reads the same plain text as the note body's text.

Read note text in two batches:

```ts
const notes = await runtime.run(async (context) => {
  const collection = context.document.body.footnotes;
  collection.load('items');
  await context.sync();
  for (const note of collection.items) note.load(['type', 'text']);
  await context.sync();
  return collection.items.map((note) => ({ type: note.type, text: note.text }));
});
```

`NoteItem.getNext()` advances within the same note kind. It fails with `ItemNotFound` after the last note. Use `note.body` for supported structured reading and editing within that note story. Separate writes to different notes with `context.sync()`.

`NoteItem.delete()` removes the note and its references. Run note deletion alone in its sync. Sync all pending reads or writes before queuing note deletion. Note creation and reference-number formatting are not exposed by this subset.

The legacy `Document.footnotes` and `Document.endnotes` accessors enumerate note parts. They are DocxEditor extensions, outside the Office.js document model.

## Read and edit text boxes

`Body.shapes` and `Paragraph.shapes` return the floating shapes that the body or paragraph anchors, in reading order. Each returns `ShapeCollection`, which exposes `items`, `getFirst()`, `getFirstOrNullObject()`, and `getByTypes(types)`. A `Shape` exposes read-only `id`, `name`, and `type`. `ShapeType` values are `TextBox`, `GeometricShape`, `Picture`, `Group`, `Canvas`, and `Unsupported`.

A text box's `body` is its own story. Read, search, and edit it with the same `Body` members as the main story. The main body's `text`, `search`, comments, and tracked changes do not include text box content. To review changes inside a text box, use the tracked changes of its `body`. A geometric shape that holds text also has a `body`. A shape without its own text, such as a picture or a linked text box, refuses `body` with `InvalidArgument`.

Shapes in the body, headers, and footers have a `body`. Shapes in notes and in text boxes are listed, but their `body` refuses with `InvalidArgument`.

The following example replaces a client name inside a text box:

```ts
await runtime.run(async (context) => {
  const boxes = context.document.body.shapes.getByTypes([ShapeType.textBox]);
  boxes.load('items');
  await context.sync();
  const body = boxes.items[0].body;
  body.load('text');
  await context.sync();
  const matches = body.search('Acme Holdings');
  matches.load('items');
  await context.sync();
  matches.items[0].insertText('Beta Logistics', 'Replace');
  await context.sync();
});
```

Sync after reading `shape.body` and before you search it. Text boxes are reachable in the body, headers, and footers. Inline drawings are inline pictures and are not listed as shapes. Shape geometry, text frames, and inserting or deleting shapes are not exposed.

When a text box has a legacy VML copy for older readers, saving writes the edited text into that copy too.
