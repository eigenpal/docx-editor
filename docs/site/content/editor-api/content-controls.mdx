Content controls mark template content. For runtime setup, see [Runtime and setup](/docs/2.x/editor-api/runtime).

## Fill a control by tag

The following example fills one eligible text control:

```ts
await runtime.run(async (context) => {
  const matches = context.document.contentControls.getByTag('customer');
  matches.load('items/subtype,items/isBound,items/cannotEdit');
  await context.sync();
  if (matches.items.length !== 1) throw new Error('Expected one customer control');
  const control = matches.items[0]!;
  if (control.isBound || control.cannotEdit) return;
  if (control.subtype !== 'plainText' && control.subtype !== 'richText') return;
  control.setValue({ kind: 'text', text: 'Ada' });
  await context.sync();
});
```

| Member | Behavior |
| --- | --- |
| `contentControls` | On `Document`, `Body`, `Paragraph`, `Range`, and `ContentControl`. Paragraph and range lists include every overlapping control. |
| `getByTag()`, `getByTitle()` | Return collections, because matches need not be unique. |
| `getById(id: number)` | Returns the first match, or fails with `ItemNotFound`. A noninteger `id` fails with `InvalidArgument`. |
| `ContentControl.id` | Loads as a string, because DOCX IDs can be missing or repeated. Convert it to an integer before you pass it to `getById()`. |

## Choose a control value

`ContentControl.setValue(value)` is a DocxEditor extension that takes a `ContentControlValue`:

| Value                                     | Use                              |
| ----------------------------------------- | -------------------------------- |
| `{ kind: 'text', text: 'Ada' }`           | Eligible text control            |
| `{ kind: 'listItem', value: 'approved' }` | A declared list item             |
| `{ kind: 'checkbox', checked: true }`     | Checkbox state and its glyph     |
| `{ kind: 'date', iso: '2026-09-13' }`     | Date, or a full ISO-8601 instant |

Choose the value from the loaded `subtype`, such as `plainText`, `dropDownList`, or `checkbox`. `insertText(text, location)` takes `Replace`, `Start`, or `End` on text-like controls. Typed controls refuse it with `NotSupported`.

### Propose a value as a tracked change

When `document.changeTrackingMode` tracks changes, `setValue()` and `insertText()` propose the change inside the control:

- `setValue()` and `insertText(text, 'Replace')` make the shown text, prompt included, a tracked deletion and the new text a tracked insertion.
- `insertText(text, 'Start')` and `'End'` add a tracked insertion and delete nothing.
- The recorded state (checked state, list item, or date) moves to the new value at once, because control properties have no tracked form.
- Accept or reject sets that state again from the remaining text. A rejected date drops its stored day.
- Setting the value shown before your own pending change withdraws that change.
- Temporary controls and block controls with more than one paragraph refuse with `NotSupported`.

## Read or change metadata

| Property                                | Access                  |
| --------------------------------------- | ----------------------- |
| `id`, `subtype`, `isBound`              | Read-only               |
| `tag`, `title`                          | Read and write strings  |
| `cannotDelete`, `cannotEdit`            | Read and write booleans |
| `text`, `placeholderShown`, `temporary` | Read-only               |

Changing one lock keeps the other. Lock setters do not bypass ancestor locks or bindings. `ContentControlLockState` is vocabulary only; no combined `lock` property exists.

`isBound` is advisory, because sync checks binding and protection again. Writes to custom XML-bound controls refuse, and `xmlMapping` does not exist.

## Create or remove a control

The following example wraps a placeholder in a plain-text control:

```ts
await runtime.run(async (context) => {
  const matches = context.document.body.search('{{customer}}');
  matches.load('items');
  await context.sync();
  if (matches.items.length !== 1) throw new Error('Choose one placeholder');
  const control = matches.items[0]!.insertContentControl('PlainText');
  await context.sync();
  control.tag = 'customer';
  await context.sync();
});
```

`Range.insertContentControl(type?)` creates `RichText` (default), `PlainText`, or `DatePicker` over an eligible single-paragraph span, and keeps the text. Other `ContentControlType` values refuse. Sync creation before you set metadata.

| Method | Effect |
| --- | --- |
| `getRange(location?)` | `Whole`, `Content`, `Start`, `End`, `Before`, or `After`; resolve before use |
| `delete(true)` | Removes the wrapper and keeps its content |
| `delete(false)` | Removes the wrapper and its content |

## Limits

- Picture controls, repeating sections, typed subtype objects, and date formats are unavailable.
- Prefer `setValue()` for a placeholder. A range edit that consumes prompt text outside its target, or starts away from the prompt start, fails with `NotSupported`.
- A range over exactly a checkbox glyph accepts the checked or unchecked glyph. Other text there fails with `NotSupported`.
- In a browser, `contentLockPolicy.allowFormattingInLockedContent` lets untracked font writes pass a content lock. Server runtimes ignore it. See [Formatting content-locked controls](/docs/2.x/guides/content-controls#formatting-content-locked-controls).
- Paragraph alignment, indents, and spacing can change in a content-locked control. Style writes refuse.
- `TrackMineOnly` can wrap nonempty ordinary text in a new control, outside collaboration only. Reject restores the text.
- Inserting a control or paragraph into a control and deleting it with `delete(false)` in one batch fails with `ConflictingChanges`. Text writes can share that batch.
- Do not delete a binding or wrapper to force a write. Report the control to the template author.
