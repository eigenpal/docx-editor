Collaboration replicates the whole canonical document across peers: text,
formatting, tables, headers, footers, notes, images, comments, and tracked
changes. Every peer edits a local replica and the replicas converge, so typing
stays fast on any connection.

Peers also share presence. You see who is in the room, and each person's caret
and selection paint in their author color — the same color that marks their
tracked changes and comments.

Collaboration ships in [`@docx-editor.dev/pro`](/docs/2.x/pro) as an editor
module. The transport is yours to choose: peer-to-peer WebRTC, a
[Hocuspocus](https://tiptap.dev/docs/hocuspocus) server, or any Yjs provider
you already run.

## Start in one component

The framework hook owns the room. `create-or-join` means every peer opens the
room the same way: the first peer seeds it from your document bytes, and every
later peer joins it.

```tsx
import { useRef } from 'react';
import { DocxEditor, type DocxEditorRef } from '@docx-editor.dev/react';
import { useWebrtcCollaboration } from '@docx-editor.dev/pro/react/webrtc';

export function CollaborativeEditor({ roomId, bytes }: { roomId: string; bytes: Uint8Array }) {
  const editorRef = useRef<DocxEditorRef>(null);
  const { document, modules, session, pending, error, leave } = useWebrtcCollaboration({
    room: {
      roomId,
      identity: { actorId: 'alex', name: 'Alex' },
      bootstrap: { kind: 'create-or-join', document: bytes },
    },
  });

  async function leaveRoom() {
    const saved = await editorRef.current?.save();
    if (saved) leave(new Uint8Array(saved));
  }

  if (error) return <p>{error.detail ?? error.code}</p>;
  if (pending || !document) return <p>Connecting…</p>;

  return (
    <>
      <button type="button" onClick={leaveRoom}>
        Leave
      </button>
      <DocxEditor ref={editorRef} key={session?.sessionId} document={document} modules={modules} />
    </>
  );
}
```

The same hook exists for Vue on `@docx-editor.dev/pro/vue/webrtc`. For the
full walkthrough, see
[realtime collaboration](/docs/2.x/pro/collaboration).

## What replicates

Everything a person can author replicates: typing, formatting, structure,
tables, images, comments, tracked-change decisions, tables of contents, and
custom nodes. Undo stays personal — each person undoes their own edits, never
a collaborator's.

Review workflows keep working in a room. One person can suggest in tracked
changes while another accepts or rejects, and the review sidebar stays live on
every peer. For the review features themselves, see
[tracked changes](/docs/2.x/pro/tracked-changes) and
[comments](/docs/2.x/pro/comments).

## Presence out of the box

Remote carets and selections paint with zero wiring once the module is
registered. For the rest of the presence interface, the Pro package ships
components and hooks:

- `DocxEditorCollaboration.Avatars` renders the participant stack, colored to
  match each person's review markup.
- `DocxEditorCollaboration.CaretLabels` replaces the caret name tags with your
  own component, rendered inside the normal adapter tree so every hook works
  in it.
- `useCollaborationStatus` and `useCollaborationParticipants` drive a
  connection badge and a people list.

For details, see
[presence UI](/docs/2.x/pro/collaboration#presence-ui).

## Pick a transport

| Transport             | When to use it                                         | How                                                                           |
| --------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------- |
| WebRTC                | Demos and small teams, no server to run                | `useWebrtcCollaboration` with your own signaling for production               |
| Hocuspocus            | A server you host, with authentication and persistence | `useHocuspocusCollaboration`; the server validates tokens in `onAuthenticate` |
| Your own Yjs provider | An existing Yjs deployment                             | `createDocumentCollaboration` over your `Y.Doc` and provider                  |

Pair any server with Yjs 13. The stock `y-websocket` server and Hocuspocus
both work unchanged.

## Offline editing

Pass `offlineEditing: true` to keep editing through a transport drop. The
buffered edits merge on reconnect like any concurrent edit. Show the
connection status when you enable it, so people know when their edits have
not reached the room yet.
