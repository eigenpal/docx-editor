---
title: DOCX to Markdown
description: Convert DOCX files to Markdown in Node with the same semantic layout engine used by the editor.
---

`@docx-editor.dev/docx-to-markdown` is a server-only converter. It opens untrusted DOCX bytes,
lays them out without a browser or editor instance, and translates the resulting semantic records.
The Node defaults use the packaged metric-compatible fonts and HarfBuzz, so page projections use
the same shaping path as the browser editor.

The package is currently private to this repository workspace. Publishing and public installation
are intentionally deferred to the final release step.

## Repository workspace

```bash
bun run --filter '@docx-editor.dev/docx-to-markdown' build
```

Core is a required peer dependency so the process owns exactly one engine instance.

## Convert a document

```ts
import { readFile } from 'node:fs/promises';
import { exportMarkdown } from '@docx-editor.dev/docx-to-markdown';

const bytes = new Uint8Array(await readFile('document.docx'));
const result = await exportMarkdown(bytes, {
  image: (drawing) =>
    drawing.resource.kind === 'ready'
      ? { url: `/media/${drawing.resource.contentId}` }
      : { skip: true },
});

console.log(result.markdown);
console.log(result.pages[0]?.headerMarkdown);
```

The image callback only sees already-laid-out drawing records. When you need the validated media
bytes, open a reusable session and call its narrow `validatedImageBytes(drawing)` capability.

```ts
import { exportMarkdownFrom, openDocumentForExport } from '@docx-editor.dev/docx-to-markdown';

const opened = await openDocumentForExport(bytes);
if (!opened.ok) throw new Error(opened.reason);

try {
  const first = await exportMarkdownFrom(opened.session);
  // Populate this asynchronously before translation in application code.
  const imageUrls = new Map<string, string>([['content-id', 'https://cdn.example/image.png']]);
  const second = await exportMarkdownFrom(opened.session, {
    image: (drawing) => {
      if (drawing.resource.kind !== 'ready') return { skip: true };
      const url = imageUrls.get(drawing.resource.contentId);
      return url ? { url } : { skip: true };
    },
  });
} finally {
  opened.session.dispose();
}
```

Pass an `AbortSignal` or `resourceTimeoutMs` when a request owns a deadline. Image decoders are
bounded, and layout waits for pending image metadata before publishing final pages.

The image mapper is deliberately synchronous because translation is a deterministic record walk.
Upload validated bytes and build the URL map first; returning a Promise throws a `TypeError`
instead of producing a broken Markdown destination.

EMF, WMF, and TIFF are preserved as labelled placeholders by default. To render them, provide a
`convertPreservedImage` hook when opening or exporting. It receives the validated source bytes,
MIME type, resource limits, and session abort signal, and returns bytes plus a supported raster
MIME type (or `null` to keep the placeholder).

```ts
const result = await exportMarkdown(bytes, {
  convertPreservedImage: async (source, mime, limits, signal) =>
    convertWithYourImageService(source, { mime, limits, signal }),
});
```

## Translation policy

- Headings use resolved outline levels and bounded built-in heading style names.
- Ordered lists use layout-published ordinals; nested items use CommonMark continuation columns.
- Tables become GFM tables. Grid spans flatten into empty cells and vertical continuations are empty.
- External links use the engine's sanitized destination. Internal and unresolved links remain text.
- Footnotes and endnotes become Markdown footnote definitions.
- Inline and positioned anchored images use the image callback. Anchored text boxes are omitted
  because Markdown has no unambiguous linear position for them.
- EMF, WMF, and TIFF stay labelled placeholders unless `convertPreservedImage` converts them.
- Page headers and footers are returned on each `pages` entry rather than mixed into the logical body.
- Tracked deletions are struck only in `all-markup`; `original` and `proposed` contain only the
  revision projection selected before translation.

The implementation lives in the core `./export` lane. PDF and future exporters reuse the same
headless opening, resource settlement, font shaping, semantic records, and traversal foundations.
