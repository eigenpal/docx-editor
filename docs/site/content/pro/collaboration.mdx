Realtime collaboration replicates the canonical document across peers.

It covers text, structure, formatting, tables, headers, footers, notes, drawings, relationships, and embedded parts. Peers also share presence and remote selections that can span paragraphs.

Collaboration requires the collaboration module from [`@docx-editor.dev/pro`](/docs/2.x/pro).

Without that module, the editor does not attach a replica. Local undo stays in charge, and `snapshot().collaborationStatus` is `'inactive'`.

## Prerequisites

Install the Pro package plus Yjs. Add `y-webrtc` when you use the WebRTC helper:

```bash
npm install @docx-editor.dev/pro yjs y-webrtc
```

`yjs` and `y-webrtc` are optional peers of Pro. `y-protocols` installs with Pro.

## Open a room with the hook

`useWebrtcCollaboration` owns the WebRTC room. It creates the replica, builds `modules`, and destroys the room when you leave.

The hook lives on a WebRTC subpath so a review-only bundle does not load a network provider. Import `@docx-editor.dev/pro/react/webrtc` or `@docx-editor.dev/pro/vue/webrtc`.

Pass `room` to connect when the component mounts. Call `leave` when the session should end. While `pending` is true, wait before you mount the editor.

The hook returns a host session (`CollaborationSession`). That type exposes identity, status, presence, and undo. It does not expose `attach` or `gateOperations`.

`error` is a `CollaborationFailure`. Branch on `error.code` instead of matching message strings.

The sugar `<DocxEditor>` host accepts `document` and `modules`. You do not need `DocxEditor.Root` to collaborate.

<FrameworkTabs>
<Framework value="react">

```tsx
import { useRef } from 'react';
import { DocxEditor, type DocxEditorRef } from '@docx-editor.dev/react';
import { useWebrtcCollaboration } from '@docx-editor.dev/pro/react/webrtc';

export function CollaborativeEditor({ roomId, bytes }: { roomId: string; bytes: Uint8Array }) {
  const editorRef = useRef<DocxEditorRef>(null);
  const { document, modules, session, pending, error, leave } = useWebrtcCollaboration({
    room: {
      roomId,
      identity: { actorId: 'alex', name: 'Alex' },
      bootstrap: { kind: 'create-or-join', document: bytes },
    },
  });

  async function leaveRoom() {
    // `leave` requires the current bytes. The hook cannot read them itself, and
    // anything else would drop what the room typed.
    const saved = await editorRef.current?.save();
    if (saved) leave(new Uint8Array(saved));
  }

  if (error) return <p>{error.detail ?? error.code}</p>;
  if (pending || !document) return <p>Connecting…</p>;

  return (
    <>
      <button type="button" onClick={leaveRoom}>
        Leave
      </button>
      <DocxEditor ref={editorRef} key={session?.sessionId} document={document} modules={modules} />
    </>
  );
}
```

</Framework>

import { ref } from 'vue';
import { DocxEditor, type DocxEditorRef } from '@docx-editor.dev/vue';

  },

  <p v-if="error">{{ error.detail ?? error.code }}</p>
  <p v-else-if="pending || !document">Connecting…</p>

  </template>
</template>

With `create-or-join`, every peer can open the same room with the same options. The first peer finds no room and seeds it from `document`. Every later peer finds the room and joins it, so no host has to decide out-of-band which peer creates the room. The `create` and `join` kinds remain available for hosts that already know their role.

Two peers that seed the same room at the same time, without seeing each other, produce a room no client can repair. Every replica then reports the failure code `concurrent-seed` and stops. Recover by creating a new room from bytes you saved.

Omit `room` when the user chooses share or join later. Call `connect` with the same options after that choice. `connect` and `leave` keep a stable identity across renders.

The editor reads `modules` at construction time. Set `key` to the session `sessionId`, as in the examples. Without the `key`, a connect after mount leaves the collaboration module unregistered, the editor keeps editing locally, and nothing replicates. The session logs a console warning when it is created but never attached.

The hook also returns `ydoc` and `provider` (both `null` while pending), so you can add persistence such as `y-indexeddb` or drive the provider directly. `rejoin(bytes)` recovers from an `error` status: it leaves with your saved bytes and reconnects to the same room as a joiner.

The default Pro entry re-exports `collaborationModule` and does not import a network provider. Import `@docx-editor.dev/pro/collaboration` for the Yjs factories. Import `@docx-editor.dev/pro/collaboration/webrtc` for room helpers such as `createCollaborationRoomId`.

## Show status and participants

`useCollaborationStatus(session)` returns the live status and last failure. `useCollaborationParticipants(session)` returns the people in the room for a presence list. Both live on `@docx-editor.dev/pro/react` and `@docx-editor.dev/pro/vue`.

When you own the Yjs resources yourself, `useDocumentCollaboration` from the same entries gives you the identical `connect`/`leave` lifecycle over `createDocumentCollaboration`, with no WebRTC import.

## Use your own signaling

`DEMO_SIGNALING_ENDPOINTS` is a public demo signaling service. Production deployments must supply their own signaling and TURN servers.

For production, pass your own `signaling` URLs to `connect` or to the `room` option. You also need your own TURN servers. WebRTC peers cannot connect across many networks without TURN.

## Own a Yjs document

If you already own a `Y.Doc` and awareness instance, call `createDocumentCollaboration` from `@docx-editor.dev/pro/collaboration`. It replicates the whole canonical package, which is what the WebRTC wrapper and the module use. You destroy those resources.

Four rules make a bring-your-own-provider integration work:

1. Connect your provider before you pass `bootstrap: { kind: 'join' }`. The factory reads already-synced shared state. A joiner with no connected provider fails with `initialization-timeout` after 30 seconds.
2. Pass an `Awareness` instance from `y-protocols/awareness`. Presence and remote selections travel through it.
3. Wire your provider's connection events to `session.setTransportStatus`. Without that call, the status stays `ready` during an outage and users get no signal.
4. Large documents exceed the single-message ceiling of some transports. The WebRTC wrapper installs its own message framing. A WebSocket provider does not need it.

This example wires `y-websocket`:

```ts
import * as Y from 'yjs';
import { Awareness } from 'y-protocols/awareness';
import { WebsocketProvider } from 'y-websocket';
import { createDocumentCollaboration } from '@docx-editor.dev/pro/collaboration';

const ydoc = new Y.Doc();
const awareness = new Awareness(ydoc);
const provider = new WebsocketProvider('wss://example.test', 'room-1', ydoc, { awareness });

await new Promise((resolve) => provider.once('sync', resolve));

const room = await createDocumentCollaboration({
  ydoc,
  awareness,
  documentId: 'room-1',
  identity: { actorId: 'alex', name: 'Alex' },
  bootstrap: { kind: 'join' },
});

provider.on('status', ({ status }: { status: string }) => {
  room.session.setTransportStatus(
    status === 'connected' ? 'ready' : 'disconnected',
    status === 'connected' ? undefined : 'websocket-disconnected'
  );
});
```

The factory rejects with a typed `CollaborationSchemaError`. The codes you handle in this flow are `initialization-timeout` (no synced room appeared), `document-id-mismatch` (the room replicates a different `documentId`), and `protocol-version-mismatch` or `schema-version-mismatch` (the room uses a different protocol or schema version).

The same entry exports `createTextCollaboration`, which replicates paragraph text alone and refuses structural edits. It is an experimental proof. Use `createDocumentCollaboration`.

## Headless replica

`DocxEditor.createCollaborative` on `@docx-editor.dev/editor-api` opens a DOM-free replica. It registers the session through the same module seam.

```ts
import { DocxEditor } from '@docx-editor.dev/editor-api';
import { createDocumentCollaboration } from '@docx-editor.dev/pro/collaboration';

const room = await createDocumentCollaboration({
  ydoc,
  awareness,
  documentId: 'room-1',
  identity: { actorId: 'agent', name: 'Agent', role: 'agent' },
  bootstrap: { kind: 'join' },
});

const runtime = await DocxEditor.createCollaborative(room.document, room.session, {
  author: 'Agent',
});
```

Call `room.destroy()` when the replica should stop.

## Compose the editor

Use `DocxEditor.Root`, `Viewport`, and `Content` when you need custom chrome around the same `document` and `modules` values.

<Framework value="react">

```tsx
import { DocxEditor } from '@docx-editor.dev/react';
import { useCollaborationStatus } from '@docx-editor.dev/pro/react';
import { useWebrtcCollaboration } from '@docx-editor.dev/pro/react/webrtc';

function Status({ session }: { session: ReturnType<typeof useWebrtcCollaboration>['session'] }) {
  const { status } = useCollaborationStatus(session);
  return <span>{status}</span>;
}

export function CollaborativeEditor() {
  const collaboration = useWebrtcCollaboration({
    room: {
      roomId,
      identity: { actorId: 'alex', name: 'Alex' },
      bootstrap: { kind: 'create', document: bytes },
    },
  });
  if (collaboration.pending || !collaboration.document) return <p>Connecting…</p>;
  return (
    <DocxEditor.Root document={collaboration.document} modules={collaboration.modules}>
      <Status session={collaboration.session} />
      <DocxEditor.Viewport>
        <DocxEditor.Content />
      </DocxEditor.Viewport>
    </DocxEditor.Root>
  );
}
```

</Framework>

Destructure the composable return so each ref is a top-level binding. Vue unwraps those bindings in the template.

Do not destroy the room from an effect that lists the room object as a dependency. StrictMode runs that cleanup and can hand a destroyed room to the remount. The hook owns that lifetime.

## Limits

Peers connect directly over WebRTC when you use the WebRTC helper. A room lasts only as long as one peer stays open.

Comments, tracked-change decisions, tables of contents, and custom nodes replicate while a replica is attached. Each named review write intent is admitted: add, reply, resolve, and delete comments; resolve tracked changes; and package-scoped writes such as tables of contents and custom nodes.

Two write paths stay refused while a replica is attached. Applying an edited ProseMirror document is refused because no host exercises that derivation under replication. A review write without a named intent is also refused.

Tree edits are refused when the session is destroyed, not ready, or not attached to the document port. A transport drop therefore pauses editing until the connection returns.

A typing run undoes as one step through the session undo manager.

### Numeric limits

Each limit produces a typed failure code when a value exceeds it.

| Limit                                      | Value          | Failure code                                  | Remedy                                                             |
| ------------------------------------------ | -------------- | --------------------------------------------- | ------------------------------------------------------------------ |
| Seed document size                         | 20 MB          | `baseline-too-large`                          | Reduce the document before you create the room.                    |
| One embedded file                          | 32 MiB         | `blob-too-large`                              | Compress or downscale the media file.                              |
| All embedded files in a room               | 64 MiB         | `blob-store-full`                             | Remove media from the document, then reseed a new room.            |
| `actorId`, `name`, and `documentId` length | 256 characters | `invalid-identity`, `invalid-document-id`     | Shorten the value.                                                 |
| Participants listed with presence          | 256            | none; presence reads list the first 256 peers | Keep rooms below 256 participants.                                 |
| Join wait for a synced room                | 30 seconds     | `initialization-timeout`                      | Connect the provider first, and confirm one peer created the room. |
