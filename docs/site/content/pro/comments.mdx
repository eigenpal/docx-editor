Comments attach a discussion thread to a text range. They share the review rail, the `useReview()` hook, and the card layout with [tracked changes](/docs/2.x/pro/tracked-changes). Comments require `reviewModule()` from [`@docx-editor.dev/pro`](/docs/2.x/pro), which uses the EigenPal Pro License.

## Add a comment

`comment(text, author?)` comments on the current selection. This example keeps the draft when the editor refuses the write:

<FrameworkTabs>
<Framework value="react">

```tsx
import { useState } from 'react';
import { useReview } from '@docx-editor.dev/pro/react';

function CommentBox() {
  const { comment, selectionAnchorY } = useReview();
  const [text, setText] = useState('');

  // null when nothing is selected: there is nowhere to anchor a comment.
  if (selectionAnchorY === null) return null;

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();
        if (comment(text)) setText('');
      }}
    >
      <textarea value={text} onChange={(e) => setText(e.target.value)} />
      <button type="submit" disabled={!text.trim()}>
        Comment
      </button>
    </form>
  );
}
```

</Framework>
<Framework value="vue">

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { useReview } from '@docx-editor.dev/pro/vue';

const text = ref('');
const review = useReview();

function submit() {
  if (review.comment(text.value)) {
    text.value = '';
  }
}
</script>

<template>
  <form v-if="review.selectionAnchorY.value !== null" @submit.prevent="submit">
    <textarea v-model="text" />
    <button type="submit" :disabled="!text.trim()">Comment</button>
  </form>
</template>
```

Mount this component inside `DocxEditorRoot`.

</Framework>
</FrameworkTabs>

A refused write returns `false` and does not throw. `selectionAnchorY` is the selection's document-space Y coordinate.

The packaged `DocxEditorReview.AddComment` and `DocxEditorReview.Draft` parts provide this workflow. For placement in custom cards, see [Custom cards in the review rail](/docs/2.x/recipes/custom-review-cards).

## Read and update threads

`useReview().items` holds comments and revisions. This example lists comments with a reply button:

<FrameworkTabs>
<Framework value="react">

```tsx
import { useReview } from '@docx-editor.dev/pro/react';

function Threads() {
  const { items, reply } = useReview();
  return (
    <ul>
      {items
        .filter((item) => item.kind === 'comment')
        .map((item) => (
          <li key={item.key}>
            {/* File-derived. Render as text, never as markup. */}
            {item.text}: {item.author}
            <button onClick={() => reply(item, 'Agreed.')}>Reply</button>
          </li>
        ))}
    </ul>
  );
}
```

</Framework>
<Framework value="vue">

```vue
<script setup lang="ts">
import { computed } from 'vue';
import { useReview } from '@docx-editor.dev/pro/vue';

const review = useReview();
const comments = computed(() => review.items.value.filter((item) => item.kind === 'comment'));
</script>

<template>
  <ul>
    <li v-for="item in comments" :key="item.key">
      {{ item.text }}: {{ item.author }}
      <button type="button" @click="review.reply(item, 'Agreed.')">Reply</button>
    </li>
  </ul>
</template>
```

</Framework>
</FrameworkTabs>

Each action returns whether the editor applied it. `commentResolutionDisabledReason` explains why `resolve` and `reopen` are unavailable, such as in viewing mode:

| Action | Result | Refusal behavior |
| --- | --- | --- |
| `comment(text, author?)` | Adds a thread to the selection | Returns `false`; the caller keeps its draft |
| `reply(item, text, author?)` | Adds a reply, or comments on a revision range | Returns `false` |
| `edit(item, text, expectedText?)` | Replaces your comment or reply text | Returns `false`; `lastRefusal.action` is `edit` |
| `resolve(item)` | Marks an open thread complete | Repeating it succeeds without a write. Returns `false` for a stale or non-comment item. |
| `reopen(item)` | Reopens a complete thread | Repeating it succeeds without a write. Returns `false` for a stale or non-comment item. |
| `remove(item)` | Deletes a comment thread or rejects a tracked change | Returns `false` when refused; a refused tracked change sets `lastRefusal.action` to `reject` |

Comment items include these fields:

| Field                        | Meaning                                            |
| ---------------------------- | -------------------------------------------------- |
| `key`, `id`                  | Stable review and OOXML identifiers                |
| `author`, `initials`, `date` | Comment author metadata                            |
| `text`                       | File-derived comment text                          |
| `replyIds`                   | Reply identifiers in the thread                    |
| `resolved`                   | Whether `w15:commentsEx` marks the thread complete |
| `parentId`                   | Parent comment identifier; absent on a thread root |
| `anchorY`, `pageIndex`       | Document placement                                 |
| `isActive`                   | Whether the caret is in the item                   |

`editor.getComments()` on the core editor returns an empty array. For comment records, use `getReviewItems()` with the review module.

## Edit comments and replies

The React and Vue cards provide an actions menu for comments and replies. **Edit** appears when the editor's comment author matches the comment's nonempty author name. This metadata does not authenticate users. Your application must authenticate users and control document access.

Viewing mode disables editing. Resolved threads remain editable and keep their resolved state.

1. Open **Comment actions** or **Reply actions**, then select **Edit**.
2. Change the text. Press Enter to add a line.
3. Select **Save changes**, or press Ctrl+Enter on Windows and Linux, or Command+Enter on macOS.

Select **Cancel**, or press Escape, to discard the draft. Save and Cancel return keyboard focus to the actions menu button. Empty and unchanged drafts cannot be saved. The actions menu also contains **Delete**. Use arrow keys to select an action, or press Escape to close the menu.

Saving replaces the comment body with plain text, including line breaks and tabs. Existing character formatting is removed. The editor refuses bodies with unsupported structures, including tracked changes. The editor keeps the comment identifier, author, date, replies, and resolved state.

Drafts survive closed cards, scrolling, and viewing-mode changes. If another participant changes the text, saving stops and your draft remains available. Copy your draft before canceling, then review the updated comment before editing again. If the comment disappears, a recovery panel keeps your draft available for copying. Loading another document clears unsaved drafts.

For custom cards, use `review.edit(item, draft, originalText)`. Capture `originalText` when editing starts to prevent replacing a newer comment value. A refused edit returns `false`; retain the draft and show `lastRefusal`. For document automation, use the standard `Comment.content` and `CommentReply.content` setters. See [Comments](/docs/2.x/editor-api/comments) for automation examples and supported limits.

## Show refused actions

`lastRefusal` from `useReview()` records the latest refused review action. This example shows the cause under a custom card:

<FrameworkTabs>
<Framework value="react">

```tsx
import {
  useReview,
  useReviewRefusalMessage,
  type ReviewItemView,
} from '@docx-editor.dev/pro/react';

function RefusalNotice({ item }: { item: ReviewItemView }) {
  const { lastRefusal } = useReview();
  const refusalMessage = useReviewRefusalMessage();
  if (lastRefusal?.key !== item.key) return null;
  return <p>{refusalMessage(lastRefusal)}</p>;
}
```

</Framework>
<Framework value="vue">

```vue
<script setup lang="ts">
import { useReview, useReviewRefusalMessage, type ReviewItemView } from '@docx-editor.dev/pro/vue';

defineProps<{ item: ReviewItemView }>();

const review = useReview();
const refusalMessage = useReviewRefusalMessage();
</script>

<template>
  <p v-if="review.lastRefusal.value && review.lastRefusal.value.key === item.key">
    {{ refusalMessage(review.lastRefusal.value) }}
  </p>
</template>
```

</Framework>
</FrameworkTabs>

`lastRefusal` names the refused `action`, the card `key` (`null` for a new comment), and the diagnostic `code`. `final` is `true` when the collaboration session ended, so a retry cannot help. `sequence` rises with each refusal, including repeats.

- Every `useReview()` over one editor shares `lastRefusal`. The packaged card shows it with `DocxEditorReview.Refusal`.
- The next applied action, or a change to the document, mode, editability, collaboration status, or author filter, clears it. A caret move does not.
- A mounted `DocxEditorReview` announces every refusal in one polite live region. Do not add a second one.
- Without `DocxEditorReview`, announce `lastRefusal` yourself, keyed on `lastRefusal.sequence`.

For every code and its remedy, see [Diagnostics](/docs/2.x/guides/diagnostics#codes).

## Save comment changes

Each comment or reply write emits the editor's `change` event. Use it for autosave and dirty tracking:

```ts
useEditorEvent('change', (change) => void autosave(change.revision));
```

The editor saves author, initials, date, reply threading, and resolved state in the comments part. Other DOCX applications can continue these threads.

## Limits

- **Author:** `comment` and `reply` require a non-empty `author`, because OOXML requires `w:author`.
- **Browser writes:** All writes need `reviewModule()`, an attached editor, and an editable mode.
- **Protection:** Comments-only protection permits comment actions. Read-only protection and `mode="view"` refuse writes. See [Document protection](/docs/2.x/guides/document-protection).
- **Ranges:** Empty comment text and cross-cell anchors are refused, never approximated.
- **Revisions:** A reply to a revision becomes a comment over the revision range, because `w:ins` and `w:del` have no body.
- **Undo:** Resolve and reopen write one transaction and one **Undo** entry. A repeated call creates none.
- **Suggesting mode:** Resolve and reopen work in suggesting mode and create no tracked change.
- **Security:** Render file-derived comment text as text, never as HTML.
