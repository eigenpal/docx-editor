`@docx-editor.dev/pro` adds review, collaboration, drawing, and custom-node modules to the React and Vue editors. Production use requires the [EigenPal Pro License](#configure-licensing).

## Install the package

Install the Pro package with your adapter and the core engine:

<FrameworkTabs>
<Framework value="react">

```bash
npm install @docx-editor.dev/react @docx-editor.dev/core @docx-editor.dev/pro
```

</Framework>
<Framework value="vue">

```bash
npm install @docx-editor.dev/vue @docx-editor.dev/core @docx-editor.dev/pro
```

</Framework>
</FrameworkTabs>

The package has these main entry points:

| Entry point | Contents |
| --- | --- |
| `@docx-editor.dev/pro` | Framework-neutral modules and functions, such as `reviewModule` and `customNodesModule` |
| `@docx-editor.dev/pro/react` | React review rail, `useReview()`, and custom-node chrome |
| `@docx-editor.dev/pro/vue` | Vue review rail, `useReview()`, and custom-node chrome |
| `@docx-editor.dev/pro/drawing` | `drawingModule` and `installDrawing` |

## Register a module

This example registers `reviewModule`, sets the author, and adds the review rail:

<FrameworkTabs>
<Framework value="react">

```tsx
import { DocxEditor } from '@docx-editor.dev/react';
import { reviewModule, DocxEditorReview } from '@docx-editor.dev/pro/react';

// Build the module array once, outside render.
const MODULES = [reviewModule()];

export function Reviewer({ bytes }: { bytes: Uint8Array }) {
  return (
    <DocxEditor.Root document={bytes} modules={MODULES} author="Jess Lin">
      <DocxEditor.Toolbar />
      <DocxEditor.Viewport>
        <DocxEditor.Content />
        <DocxEditorReview />
      </DocxEditor.Viewport>
    </DocxEditor.Root>
  );
}
```

</Framework>
<Framework value="vue">

```vue
<script setup lang="ts">
import {
  DocxEditorContent,
  DocxEditorRoot,
  DocxEditorToolbar,
  DocxEditorViewport,
} from '@docx-editor.dev/vue';
import { DocxEditorReview, reviewModule } from '@docx-editor.dev/pro/vue';

defineProps<{ bytes: Uint8Array }>();

const modules = [reviewModule()];
</script>

<template>
  <DocxEditorRoot :document="bytes" :modules="modules" author="Jess Lin">
    <DocxEditorToolbar />
    <DocxEditorViewport>
      <DocxEditorContent />
      <DocxEditorReview />
    </DocxEditorViewport>
  </DocxEditorRoot>
</template>
```

</Framework>
</FrameworkTabs>

The editor registers modules during creation, so keep the module array stable across renders. The packaged `DocxEditor` component also accepts `modules`.

- **Author:** Comments and tracked changes require an `author`, because OOXML requires one. Without an author, `useReview().comment()` and `reply()` return `false`, editor commands return an `ExecResult` with `ok: false`, and document API calls throw a structured error.
- **No review module:** The editor still opens and saves revisions and comments unchanged. It renders revisions in their final state and shows no review controls.

## Choose a feature

| Feature | Module | Guide |
| --- | --- | --- |
| Suggesting mode, markup, accept and reject | `reviewModule` | [Tracked changes](/docs/2.x/pro/tracked-changes) |
| Comment threads and replies | `reviewModule` | [Comments](/docs/2.x/pro/comments) |
| Author colors and review card styles | `reviewModule` | [Review colors and styling](/docs/2.x/pro/review-styling) |
| Compare two DOCX files as tracked changes | `reviewModule` | [Compare documents](/docs/2.x/pro/compare-documents) |
| Inline node types stored as content controls | `customNodesModule` | [Custom nodes](/docs/2.x/pro/custom-nodes) |
| Charts, DrawingML diagram layout, effects, VML text paths, EMF, and WMF | `drawingModule` | [Advanced drawing rendering](/docs/2.x/pro/drawing) |
| Rooms, providers, presence, and recovery | `collaborationModule` | [DOCX collaboration reference](/docs/2.x/pro/collaboration) |

For the review hook, `useReview()`, see [Tracked changes](/docs/2.x/pro/tracked-changes).

## Control the review pane

Set the starting pane options on the module, and change them at runtime with `setReviewPaneOptions`:

```ts
const MODULES = [reviewModule({ pane: { revisionsIn: 'balloons', opening: 'manual' } })];

editor.setReviewPaneOptions({ commentMarkers: 'initials', overflow: 'scroll' });
const revisionsIn = editor.snapshot().reviewPane.revisionsIn;
```

| Setting          | Values                          | Default |
| ---------------- | ------------------------------- | ------- |
| `opening`        | `auto`, `manual`                | `auto`  |
| `revisionsIn`    | `pane`, `balloons`              | `pane`  |
| `commentMarkers` | `initials`, `icon`              | `icon`  |
| `overflow`       | `float`, `shrinkPage`, `scroll` | `float` |

The settings apply to one editor instance and are never saved to the document. `setReviewPaneOptions` returns an `ExecResult`: `invalidArgs` for an unknown field or value, and `unsupported` without a review module. For what each value does, see [Tracked changes customization](/docs/2.x/customization/tracked-changes).

- When another participant resolves a tracked change during your reply, the balloon keeps your draft.
- With `overflow: 'scroll'` and a mounted pane, fit zoom ignores padding that your app adds to the scroll container.

## Configure licensing

This package uses the [EigenPal Pro License](https://github.com/eigenpal/docx-editor/blob/main/packages/pro/LICENSE.md). Production use requires one. For license and support options, see [pricing](https://www.docx-editor.dev/pricing).

`reviewModule`, `customNodesModule`, `collaborationModule`, `drawingModule`, and `installDrawing` accept an optional `licenseKey`. Pass it once, to any of them:

```ts
const MODULES = [reviewModule({ licenseKey: process.env.NEXT_PUBLIC_DOCX_LICENSE })];
```

- The key identifies your license when you contact support. Every module works the same without it.
- The editor never validates or transmits the key, and module construction makes no network request.
- The key is not a secret, so you can ship it in browser code. In Vue, read it from your build tool.
- `@docx-editor.dev/docx-to-pdf` includes the drawing module and needs no separate key.
