An agent that rewrites a paragraph should propose the smallest set of tracked changes, not one replacement of the whole paragraph. `proposeRewrite` from `@docx-editor.dev/editor-api/agent` does this in one call. It sends the paragraph to your model, compares the answer with the original words, and writes each difference as a tracked change.

## Rewrite a paragraph

Pass the request context, the paragraph, and a function that calls your model. The following example rewrites the first paragraph on a server:

```ts
import { DocxEditor } from '@docx-editor.dev/editor-api';
import { proposeRewrite } from '@docx-editor.dev/editor-api/agent';

const runtime = await DocxEditor.createServer(bytes, { author: 'Rewrite agent' });
try {
  const result = await runtime.run(async (context) => {
    const paragraph = context.document.body.paragraphs.getFirst();
    return proposeRewrite(context, paragraph, (draft) => callModel(draft.prompt), {
      instruction: 'Make this clause shorter. Keep its meaning.',
      timeoutMs: 30_000,
    });
  });
  console.log(`${result.changes} changes: ${result.proposed}`);
  const saved = await runtime.save();
} finally {
  runtime.dispose();
}
```

`draft.prompt` holds your instruction, the placeholder rules, a legend of the placeholders, and the paragraph text. To write your own prompt, use `draft.text` and `draft.placeholders` instead. The changes use the runtime's `author`. In a page, create the runtime with `DocxEditor.createBrowser` from `@docx-editor.dev/editor-api/browser`, and give the editor the review module.

The `rewrite` function gets the draft and a `signal`. Pass the signal to your model client: it aborts when `options.signal` aborts or when the call takes longer than `options.timeoutMs`. A timed-out call is retried like a call that throws. An aborted rewrite fails with `aborted` and writes nothing.

The `rewrite` function runs outside the batch, so it must not use `context` or its proxies. While it runs, `context.sync()` fails with `context-used`. If it queues an edit, such as `insertText()`, the helper discards the edit and fails with `context-used`. Read what the model needs from the draft, and make other edits before or after the rewrite.

One helper call runs on a request context at a time. A second call on the same context, such as two `proposeRewrite()` calls in `Promise.all()`, fails with `busy`. To rewrite several paragraphs, use `proposeRewrites()`. The helper also refuses with `context-used` when edits are queued on the context and not synced, so its tracked writes never send them. Call `await context.sync()` first.

`result.proposed` and `result.original` read as `getReviewedText()` does. An equation, a picture, or a note reference reads as U+FFFC, and a line break reads as U+000B. After the rewrite, `paragraph.text` reads both the deleted and the inserted words. To read the proposed text later, call `paragraph.getReviewedText('Current')`.

To check a draft before you write it, call `prepareRewrite(context, paragraph, options)`. It returns the same draft, and `draft.apply(modelText)` writes the answer.

## What the model sees

Each field, picture, equation, note reference, line break, and content-locked control reaches the model as its own numbered placeholder, also when several sit in one word or two read the same. A placeholder stands for the content only, so the text beside it stays ordinary text that the model can change:

```text
Placeholders:
<placeholders>
⟦1⟧ = field with code "REF _Ref1 \\h", reads "Section 4.2"
⟦2⟧ = footnote or endnote reference mark
</placeholders>

Paragraph:
<paragraph>
Subject to ⟦1⟧, the Supplier shall deliver the goods herein⟦2⟧.
</paragraph>
```

The legend describes each placeholder: a field by its code and result, a locked content control by its tag and text, a picture by its alternative text, and an equation, a note reference, or a line break by its kind. A field that shows no text, such as an index entry, also gets a placeholder, so that deleting it is the model's explicit choice. A note reference is told apart from an equation by its superscript formatting.

Text from the file never reads as instructions. Every value in the legend is a quoted string, and the paragraph and the legend sit between tags that their text cannot close. The prompt tells the model that the text between the tags is document content, not instructions. If the paragraph already contains `⟦` or `⟧`, the placeholders use another bracket pair, such as `⟪1⟫`. Read the exact placeholders from `draft.placeholders`.

Fields that show no text at one place, such as several index entries side by side, share one range. Each gets its own placeholder, but the model can keep them or leave them out only together; an answer that keeps some of them fails with `placeholder-grouped`.

The result of a field that spans paragraphs, such as a table of contents, reads as ordinary text in each paragraph, and the helper edits it as text. Updating that field later replaces the edits. Rewrite the headings that the table of contents lists instead.

A placeholder that the model keeps never changes. A placeholder that the model leaves out deletes what it stands for as one tracked deletion. A deletion of a whole equation strikes the whole equation, and a deletion of a whole content-locked control proposes removing the control. To refuse a left-out placeholder instead, pass `keepPlaceholders: true`.

## Rewrite several paragraphs

`proposeRewrites(context, items, options)` rewrites a list of `{ paragraph, rewrite }` items. It prepares every paragraph first. Then it asks the model for up to `concurrency` paragraphs at a time, including each paragraph's retries, and checks every answer. Last, it writes the checked answers one paragraph after another. The default `concurrency` is `4`. `TrackMineOnly` stays on for the whole write phase, and the helper turns it off again at the end if it was off.

`context.document.body.paragraphs` lists every paragraph, including empty paragraphs and the paragraphs in table cells. Load the properties that you filter on, and pass only the paragraphs to rewrite. The following example skips empty paragraphs and headings:

```ts
import { proposeRewrites } from '@docx-editor.dev/editor-api/agent';

await runtime.run(async (context) => {
  const paragraphs = context.document.body.paragraphs;
  paragraphs.load('items/text,items/style');
  await context.sync();

  const body = paragraphs.items.filter(
    (paragraph) => paragraph.text.trim() !== '' && !paragraph.style.startsWith('Heading')
  );
  const results = await proposeRewrites(
    context,
    body.map((paragraph) => ({ paragraph, rewrite: (draft) => callModel(draft.prompt) })),
    { instruction: 'Use plain language.', concurrency: 4 }
  );
  for (const result of results) {
    if (result.status === 'rejected') console.warn(result.reason.code, result.reason.message);
  }
});
```

Every item settles. The results have the shape of `Promise.allSettled` results, in the order of the items. If `options.signal` aborts during the write phase, the paragraphs that are not written yet report `aborted`, and the written ones keep their results. A paragraph that fails has `status: 'rejected'` and a `RewriteError` as `reason`. The other paragraphs are not affected. Pass each paragraph once.

## Guarantees

- Either every change lands and the paragraph reads as the model's answer, or the paragraph stays as it was.
- A failed write rejects only the changes that this rewrite made, also in a collaboration session. The helper records each change it makes by its type, author, date, and text. Changes by other participants stay, including changes by a worker or a person who uses the same author name.
- The helper checks the answer before it writes anything. An answer that breaks a placeholder rule writes nothing.
- If tracking is off, the helper turns on `TrackMineOnly` for its writes and turns it off again. It never turns tracking off. If turning it off again fails, the proposal stands and `document.changeTrackingMode` reads `TrackMineOnly`.

## Handle errors

The helper throws a `RewriteError`. When `error.isModelError` is `true`, the answer broke a placeholder rule, nothing was written, and `error.message` explains the rule in words that you can send back to the model. `proposeRewrite` and `proposeRewrites` retry on their own:

- After a refused answer, they call your function again with `draft.feedback` set and the reason in `draft.prompt`.
- After your function throws, they call it again with the same draft.
- After a `stale` or a `verification-failed` error, they prepare the paragraph again and call your function again.

The `retries` option caps all three together. It takes a whole number from `0` to `5`, and the default is `2`. A paragraph that still fails is reported with the last error, such as `model-failed` when your function threw on every attempt.

| `code` | Meaning | What to do |
| --- | --- | --- |
| `invalid-output` | The answer is empty or has a line break. | Ask the model again. |
| `placeholder-unknown` | The answer has a placeholder that the paragraph does not have. | Ask the model again. |
| `placeholder-moved` | The answer changes the order of the placeholders. | Ask the model again. |
| `placeholder-repeated` | The answer has a placeholder more than once. | Ask the model again. |
| `placeholder-missing` | With `keepPlaceholders: true`, the answer leaves out a placeholder. | Ask the model again. |
| `placeholder-grouped` | The answer keeps some, but not all, of the placeholders at one place. | Ask the model again. |
| `model-failed` | Your `rewrite` function threw or timed out on every attempt. `error.cause` holds its last error. | Check the model service. |
| `aborted` | `options.signal` aborted. | Nothing to do. |
| `context-used` | Your `rewrite` function used `context`, or edits were queued on `context` when you called the helper. | Do not use `context` inside the function, and sync your own edits first. |
| `busy` | Another helper call runs on the same request context, or your code called `context.sync()` while a helper call was in progress. | Await the helper call first, or use `proposeRewrites()`. |
| `pending-changes` | The paragraph has tracked changes. | Accept or reject them first. |
| `tracking-unavailable` | The runtime cannot record tracked changes. | Create the runtime with an `author`. In a page, give the editor the review module. |
| `draft-used` | The draft already wrote to the paragraph. | Prepare the paragraph again. |
| `too-long` | The paragraph or the answer has more than 20,000 words and placeholders, or the answer makes more than 2,000 word edits. The paragraph length is checked before the model is asked; the edit count, after the model answers. | Ask the model for fewer changes, or split the paragraph. |
| `unsupported-text` | The paragraph contains every bracket pair that placeholders can use. | Rewrite the paragraph another way. |
| `read-failed` | The document refused a read of the paragraph. `error.cause` holds the reason. | Read `error.cause`. |
| `stale` | The paragraph changed while the helper ran, through another participant or your own code. The rewrite was rolled back. | Prepare the paragraph again. |
| `locked` | An edit touched protected content. The rewrite was rolled back. | Keep the content whole. |
| `write-failed` | The document refused an edit. The rewrite was rolled back. `error.cause` holds the reason. | Read `error.cause`. |
| `verification-failed` | The paragraph would not read as the answer. The rewrite was rolled back. | Prepare the paragraph again. |
| `rollback-failed` | A write failed, and the rollback failed too or left the paragraph different from before. | Review the paragraph. `error.cause` holds both errors. |

If a cleanup step fails after an error, such as turning tracking off again, `error.suppressed` holds that second error. It never replaces the first one.

## How it works

1. The helper splits the paragraph into word ranges with `getTextRanges([' ', '\t'])`, and reads the `fields`, `inlinePictures`, and `contentControls` of every range.
1. In a word that holds an atom, it finds each atom by its own range. A content control answers its range. A search finds each U+FFFC and U+000B. A word that holds a field is split with every one of its characters as an ending mark, because a field never splits. A field that shows no text sits in the range between two words or two of these pieces. The helper addresses the text between atoms with `getRange('Start')`, `getRange('End')`, and `expandTo()`, and reads each part back to check it. A word whose parts do not read back as expected becomes one placeholder, with its trailing space outside it.
1. It compares the answer with the original words by longest common subsequence. Each run of differences becomes one call: `insertText(text, 'Replace')`, `delete()`, or `insertText(text, 'Before')` or `'After'`.
1. It writes the calls from the last one to the first, one sync each, so the earlier ranges stay valid. After each write, it reads the paragraph's revisions and records the new ones.
1. It reads the result with `getReviewedText('Current')` and compares it with the answer.
1. If a step fails, it finds the paragraph again by its `uniqueLocalId`, rejects the revisions that it recorded, and checks that the paragraph reads as it did.

For the word-range rules, see [Text and ranges](/docs/2.x/editor-api/text-and-ranges#split-text-into-word-ranges). For tracked edit limits, see [Tracked changes](/docs/2.x/editor-api/revisions).
