`@docx-editor.dev/docx-to-pdf` converts DOCX documents to PDF using Core's pagination, font resolution, and positioned glyphs. It runs on Node.js. Browser applications send documents to a server for conversion.

The package is private and is not available from the public npm registry. It is distributed under the EigenPal Pro License. Production use requires a commercial agreement.

## Convert a document

```ts
import { readFile, writeFile } from 'node:fs/promises';
import { exportPdf } from '@docx-editor.dev/docx-to-pdf';

const source = await readFile('document.docx');
const result = await exportPdf(source, {
  displayMode: 'proposed',
  comments: true,
});

await writeFile('document.pdf', result.bytes);
```

## Configure conversion

By default, export includes proposed revisions and preserves comments as native PDF annotations. Set `comments: false` to omit annotations. Set `displayMode` to `'original'` or `'all-markup'` to change how revisions appear. Conversion preserves the source DOCX.

The default `fidelityPolicy: 'strict'` rejects unsupported or approximate output. Use `'best-effort'` to receive available output with `result.diagnostics`.

Core's `fontPolicy` controls failed font sources and incomplete face coverage. Inspect `result.fontResolution` for the fonts used in the PDF.

## Handle limits and failures

Set `maxPages`, `maxOutputBytes`, and `timeoutMs` for your conversion workload. `maxPages` checks completed layout before painting. `maxOutputBytes` checks encoded output; neither option limits process memory. Pass `signal` to cancel conversion between processing batches.

`PdfPageLimitError` and `PdfOutputLimitError` include `limit`, `actual`, and stable `code` fields. `PdfFidelityError.diagnostics` explains a strict refusal. `PdfDocumentOpenError.reason` identifies rejected input.

A `font-origin-failed` diagnostic identifies source failures that fallback sources can recover from. Inspect `fontResolution.originFailures` for causes. Set `fontPolicy: 'strict'` when source failures must reject conversion.

## Configure server fonts

Set `useSystemFonts: false` for consistent font selection across hosts. Supply `fonts` to override packaged sources. Supply `lastResortFonts` to resolve missing faces after embedded fonts and before generic substitutes. Import `createFontSource` and `defineFontResolver` from the converter package.

## Reuse a conversion session

Use `openDocumentForExport` and `exportPdfFrom` to reuse font resolution and layout. Pass the same session to Markdown's `exportMarkdownFrom` when you need both formats. Dispose the session in `finally` after all exports. An export failure does not dispose a caller-owned session.

Page diagnostics include one-based `pageNumber`, consistent with Markdown warnings. The existing zero-based `pageIndex` remains available.

## Supported content

The exporter supports searchable multilingual text, tables, images, notes, textboxes, structured equations, links, and comments. Charts, rotated table-cell text, and advanced image effects produce diagnostics.

For supported fonts, resource limits, and error handling, see the [package documentation](https://github.com/eigenpal/docx-editor/tree/main/packages/docx-to-pdf).

## Try the demo

Run `bun run dev:pdf` from the repository root and open <http://127.0.0.1:5180>. Edit the sample or select **Open DOCX**, then select **Generate PDF**. The preview appears beside the editor. Use **Download PDF** to save the result.

After editing the document, select **Regenerate PDF** to update the preview. The demo runs conversions on request and does not retain uploaded documents or generated PDFs.
