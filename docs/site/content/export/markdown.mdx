Use `@docx-editor.dev/docx-to-markdown` to convert DOCX files to Markdown.
The result includes the document body, individual pages, and separate headers, footers, comments, and tracked changes.

[Try the DOCX to Markdown demo](https://docx-to-markdown.docx-editor.dev/).

## Before you begin

For Node.js, use version 20.16.0 or later in the 20.x release line, or version 22.3.0 or later.
The converter requires WebAssembly and uses bundled fonts by default.

## Install the package

```sh
npm install @docx-editor.dev/docx-to-markdown @docx-editor.dev/core
```

`@docx-editor.dev/core` is a required peer dependency. Use the same release version for both packages.

## Convert a DOCX file

The following example reads a local file in Node.js:

```ts
import { readFile } from 'node:fs/promises';
import { exportMarkdown } from '@docx-editor.dev/docx-to-markdown';

const docxBytes = await readFile('document.docx');
const result = await exportMarkdown(docxBytes);
console.log(result.markdown);
```

## Include images

Pass `{ images: true }` to return image links and bytes in `result.media`.
Use `createMarkdownZip(result)` for downloads or `images.resolveUrl` to return URLs from your storage service.
For JSON responses without image bytes, use `toMarkdownJSON(result)`.

See [image workflows](https://github.com/eigenpal/docx-editor/blob/main/packages/docx-to-markdown/docs/images.md) for browser, local Node.js, and server examples.

### Preserve displayed image sizes

Use HTML image syntax to include each occurrence's displayed size:

```ts
const result = await exportMarkdown(docxBytes, {
  images: { syntax: 'html' },
});
```

Generated `img` tags include `width` and `height`, rounded to whole CSS pixels.
Configure your renderer to parse sanitized HTML and retain those attributes.
The default `images: true` uses standard Markdown image syntax without size attributes.

Use each occurrence's `displayWidthPx` and `displayHeightPx` for exact displayed dimensions in custom previews.
Asset `pixelWidth` and `pixelHeight` describe the image file, which Word can display at different sizes.
Crop, rotation, and floating text wrapping are not reproduced.
See [custom image previews](https://github.com/eigenpal/docx-editor/blob/main/packages/docx-to-markdown/docs/images.md#preserve-displayed-image-sizes) for renderer setup and responsive sizing.

## Read page output

The document layout engine calculates page breaks.

```ts
for (const page of result.pages) {
  console.log(page.number, page.markdown);
  console.log(page.headerMarkdown, page.footerMarkdown);
}
```

`result.markdown` joins the body into one document. Headers and footers stay in `result.pages`.

For search and AI ingestion, use `{ displayMode: 'proposed' }` to show pending insertions and hide pending deletions. The default, `'all-markup'`, shows both.

## Runtime and output

For Next.js, use the Node.js runtime and [server package configuration](https://github.com/eigenpal/docx-editor/blob/main/packages/docx-to-markdown/docs/integrations.md#nextjs). Edge runtimes are not supported.

Page breaks depend on fonts, document features, and revision mode; they can differ from Microsoft Word. Store the document version with page citations. `result.warnings` reports omitted images, shapes, text boxes, and font problems. See [output limits](https://github.com/eigenpal/docx-editor/blob/main/packages/docx-to-markdown/docs/api.md#markdown-limitations) before using the output as a complete transcription.
