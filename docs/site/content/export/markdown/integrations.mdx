## Return a JSON response

The following Next.js route accepts DOCX bytes as the request body and returns JSON:

```ts
// app/api/convert/route.ts
import {
  DocumentOpenError,
  exportMarkdown,
  toMarkdownJSON,
} from '@docx-editor.dev/docx-to-markdown';

export const runtime = 'nodejs';

export async function POST(request: Request) {
  try {
    const result = await exportMarkdown(new Uint8Array(await request.arrayBuffer()), {
      displayMode: 'proposed',
      signal: request.signal,
      resourceTimeoutMs: 15_000,
    });
    return Response.json(toMarkdownJSON(result));
  } catch (error) {
    if (error instanceof DocumentOpenError) {
      return Response.json({ error: 'Document could not be opened' }, { status: 422 });
    }
    throw error;
  }
}
```

Authenticate and limit upload size before the route reads the body. `toMarkdownJSON` excludes image bytes, so deliver images separately or as a ZIP. For field meanings, see [Read the result](/docs/2.x/export/markdown/api#read-the-result).

## Deploy with Next.js

Keep the packages external so Node.js can load their font and WebAssembly files:

```js
// next.config.mjs
export default {
  serverExternalPackages: [
    '@docx-editor.dev/docx-to-markdown',
    '@docx-editor.dev/core',
    '@docx-editor.dev/fonts',
  ],
};
```

- Use a Node.js runtime that allows WebAssembly. Edge runtimes are unsupported.
- Keep the package font and WebAssembly assets in the deployed artifact.
- Run a conversion from the production build to confirm that tracing kept the assets.

## Create page citations

The following example needs `@langchain/core` and `@langchain/textsplitters`. It stores an export snapshot and creates one LangChain `Document` per page before splitting:

```ts
import { createHash, randomUUID } from 'node:crypto';
import { readFile, writeFile } from 'node:fs/promises';
import { Document } from '@langchain/core/documents';
import { RecursiveCharacterTextSplitter } from '@langchain/textsplitters';
import { exportMarkdown, toMarkdownJSON } from '@docx-editor.dev/docx-to-markdown';

const source = 'contract.docx';
const bytes = await readFile(source);
const documentVersion = createHash('sha256').update(bytes).digest('hex');
const exportId = randomUUID();
const result = await exportMarkdown(bytes, { displayMode: 'proposed' });

// Retain the export so retrieved citations can reopen the same page text.
const snapshot = { exportId, source, documentVersion, result: toMarkdownJSON(result) };
await writeFile('contract.export.json', JSON.stringify(snapshot));

const documents = result.pages
  .filter((page) => page.markdown.trim().length > 0)
  .map(
    (page) =>
      new Document({
        pageContent: page.markdown,
        metadata: { source, documentVersion, exportId, page: page.number, pageId: page.id },
      })
  );

const splitter = new RecursiveCharacterTextSplitter({ chunkSize: 1500, chunkOverlap: 150 });
const chunks = await splitter.splitDocuments(documents);
```

`splitDocuments` copies metadata to each chunk and keeps overlap within one page. Build citations from chunk metadata; never ask the model for page numbers. Store warnings, package versions, font configuration, and `displayMode` with the snapshot.

## Limits

- Conversion runs in memory. Limit upload size and concurrent conversions, and measure peak memory on representative documents.
- `resourceTimeoutMs` limits each resource wait, not total conversion time.
- An `AbortSignal` cannot interrupt synchronous parsing or layout. For a hard deadline, convert in a worker thread or process and terminate it on timeout.
- For large files, convert in a background job that reads from object storage.
- JSON output excludes image bytes. See [Images in Markdown exports](/docs/2.x/export/markdown/images).
