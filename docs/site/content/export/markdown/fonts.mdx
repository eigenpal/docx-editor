The converter measures text to find line wraps, row heights, and page breaks. Fonts change page references, not the Markdown font. Your renderer controls the displayed font.

## Supply font files

The following example registers four licensed Aptos faces through `fonts` and loads missing faces from Google Fonts through `fallbackFonts`:

```js
import { readFile } from 'node:fs/promises';
import { createFontSource, exportMarkdown } from '@docx-editor.dev/docx-to-markdown';
import { googleFonts } from '@docx-editor.dev/fonts/google';

const faces = [
  { file: 'Aptos.ttf', weight: 400, style: 'normal' },
  { file: 'Aptos-Bold.ttf', weight: 700, style: 'normal' },
  { file: 'Aptos-Italic.ttf', weight: 400, style: 'italic' },
  { file: 'Aptos-BoldItalic.ttf', weight: 700, style: 'italic' },
];

const sources = [];
for (const { file, weight, style } of faces) {
  const bytes = new Uint8Array(await readFile(`fonts/${file}`));
  const admitted = createFontSource(bytes, { family: 'Aptos', weight, style });
  if ('failure' in admitted) {
    throw new Error(admitted.failure.diagnostic ?? admitted.failure.reason);
  }
  sources.push(admitted.source);
}

const result = await exportMarkdown(await readFile('document.docx'), {
  fonts: { sources },
  fallbackFonts: googleFonts(),
});
console.dir(result.fontResolution, { depth: null });
```

Register each face under the family name that the DOCX requests. `googleFonts()` needs `npm install @docx-editor.dev/fonts` and network access. For offline conversion, omit `fallbackFonts`.

## Choose source precedence

| Order | Source | Use it to |
| --- | --- | --- |
| 1 | `fonts` | Supply licensed fonts or override a bundled substitute. Earlier entries win. |
| 2 | Bundled substitutes | Cover common DOCX default fonts with no configuration. |
| 3 | `fallbackFonts` | Supply faces that earlier sources did not resolve. It never overrides a resolved face. |
| 4 | Document-embedded fonts | Supply faces that earlier sources did not resolve. |

The bundled substitutes match character widths for the glyphs they cover:

| Original font   | Bundled substitute |
| --------------- | ------------------ |
| Calibri         | Carlito            |
| Cambria         | Caladea            |
| Times New Roman | Liberation Serif   |
| Arial           | Liberation Sans    |
| Courier New     | Liberation Mono    |

## Choose a font policy

| `fontPolicy` | Behavior |
| --- | --- |
| `'best-effort'` (default) | Allows approximate measurement for unresolved fonts. |
| `'strict'` | Rejects font-source failures, and missing regular, bold, italic, or bold-italic faces among checked families. Fails with `ExportResourceError` code `layoutFailed`. |

Strict mode checks all four static faces, even when the document uses only regular text. It also fails when another source recovered from a font-source failure. Strict mode does not guarantee matching page breaks.

To inspect the report before a strict rejection, pass a callback:

```js
const result = await exportMarkdown(docxBytes, {
  fontPolicy: 'strict',
  onFontResolution: (report) => console.dir(report, { depth: null }),
});
```

The exporter does not await callback promises. `fontPolicy` and `onFontResolution` with a live view or a custom `measurer` throw `TypeError`.

## Read font evidence

`result.fontResolution.families` lists each checked family:

| Field | Meaning |
| --- | --- |
| `coverage` | `'complete'` (all four static faces), `'partial'`, or `'none'`. |
| `faces` | Resolved weight and style variants only. A missing variant is absent from this list. |
| `faces[].via` | `'direct'` or `'substitution'`. Inspect `sourceFamily` and `substitution` for substitutes. |

`result.fontResolution.originFailures` lists font-source failures for the whole report, even when another source supplied the faces.

`fontResolution: null` means evidence is unavailable, not that no fonts were needed. Detached layouts and custom measurers can return `null`. To store reports as JSON, use `toMarkdownJSON(result)`, which turns failure causes into strings.

## Troubleshoot fonts

| Symptom | Action |
| --- | --- |
| Page breaks differ from a reference rendering | Supply the source fonts through `fonts` and match `displayMode`. |
| `incomplete-font` warning | Supply the regular, bold, italic, and bold italic faces that `faces` does not list. |
| `font-origin-failed` warning | Fix the resolver or path in `fontResolution.originFailures`. For remote sources, check network access. |
| Google Fonts does not change a font | Move the replacement to `fonts`. `fallbackFonts` never overrides a resolved face. |
| Strict export fails with `layoutFailed` | Supply missing faces or fix the failing source. |
| Deployed export cannot load bundled fonts | See [Deploy with Next.js](/docs/2.x/export/markdown/integrations#deploy-with-nextjs). |

## Limits

- Resolution checks at most 64 candidate families: body first, then headers and footers, then notes. Extra families never fail strict mode.
- `'complete'` coverage does not prove glyph coverage for every script or original-font selection.
- `googleFonts()` uses a pinned catalog with verified hashes. Requests disclose requested family names to the CDN.
- Glyph and kerning differences in substitutes can still move line and page breaks.
- For size and memory bounds, see [font limits](https://github.com/eigenpal/docx-editor/blob/main/packages/docx-to-markdown/docs/api.md#font-limits). For general font loading, see [Fonts](/docs/2.x/guides/fonts).
