## Export images

Images are off by default. The following example sets `images: true` to add relative image links and extracted bytes:

```ts
import { readFile } from 'node:fs/promises';
import { exportMarkdown } from '@docx-editor.dev/docx-to-markdown';

const result = await exportMarkdown(await readFile('document.docx'), { images: true });
console.log(result.markdown); // ![Description](media/<digest>.png)
console.log(result.media); // Unique bytes, paths, URLs, dimensions, and occurrences.
```

`images: true` and `images: {}` use relative URLs. Without `images`, the result has no image links and `media: []`. Identical bytes share one asset with separate occurrences.

## Choose image delivery

| Delivery | API | Notes |
| --- | --- | --- |
| Local folder | `writeMarkdownBundle(result, { directory })` from `@docx-editor.dev/docx-to-markdown/node` | Writes `document.md`, `document.json`, and `media/`. |
| ZIP file | `createMarkdownZip(result)` | Same files as the folder. Deterministic entry order and timestamps. |
| JSON response | `toMarkdownJSON(result)` | Omits image bytes. Send images separately. |
| Hosted URLs | `images.resolveUrl` | Your application uploads each unique image and returns a URL. |

Folder and ZIP output need portable URLs (`image.url === image.path`). Export with `images: true` and no `resolveUrl`. Hosted URLs make both helpers throw `MarkdownBundleError` with `non-portable-image-url`.

The following example saves a folder:

```ts
import { writeMarkdownBundle } from '@docx-editor.dev/docx-to-markdown/node';

await writeMarkdownBundle(result, { directory: './output' });
```

The parent directory must exist, and the output directory must be new or empty. Existing files are never overwritten. Files use `0o600` permissions where supported.

The following example saves a ZIP file:

```ts
import { writeFile } from 'node:fs/promises';
import { createMarkdownZip } from '@docx-editor.dev/docx-to-markdown';

await writeFile('document.zip', await createMarkdownZip(result));
```

ZIP compression yields between bounded chunks and needs no workers. In the browser, configure your bundler to serve the package font and WebAssembly assets; see the [browser demo](https://github.com/eigenpal/docx-editor/tree/main/examples/docx-to-markdown).

### Return hosted URLs

The following route uploads each image to your storage and returns JSON:

```ts
import { exportMarkdown, toMarkdownJSON } from '@docx-editor.dev/docx-to-markdown';

// storage and documentId belong to your application.
const result = await exportMarkdown(docxBytes, {
  signal: request.signal,
  images: {
    resolveUrl: (image, { signal }) =>
      storage.upload(`documents/${documentId}/${image.path}`, image.bytes, {
        contentType: image.mimeType,
        signal,
      }),
  },
});
return Response.json(toMarkdownJSON(result));
```

- The resolver runs once per unique image, in sequence, after all extraction and budget checks pass. It has no automatic retries.
- It returns a relative path or an absolute HTTP(S) URL. Metadata keeps the raw URL; the exporter escapes it only in Markdown destinations.
- Your application owns uploads, cleanup after failure, access control, and signed-URL expiry.

### Preview in the browser

The following code maps image paths to object URLs for a custom image component:

```ts
const imageUrls = new Map(
  result.media.map((image) => [
    image.path,
    URL.createObjectURL(new Blob([image.bytes.slice().buffer], { type: image.mimeType })),
  ])
);

// On result replacement, unmount, or a discarded async result:
for (const url of imageUrls.values()) URL.revokeObjectURL(url);
```

Create URLs outside rendering, and look up only known paths. Never persist or transmit object URLs.

## Read image metadata

| Asset field                 | Meaning                                                           |
| --------------------------- | ----------------------------------------------------------------- |
| `id`                        | Hexadecimal SHA-256 digest, without a `sha256:` prefix.           |
| `path`, `url`               | Relative path, and the URL used in Markdown.                      |
| `mimeType`                  | Type of the exported bytes, including converted images.           |
| `bytes`                     | Caller-owned bytes. Treat them as read-only to keep the ID valid. |
| `pixelWidth`, `pixelHeight` | Intrinsic pixel size.                                             |
| `occurrences`               | Each placement of the image.                                      |

| Occurrence field | Meaning |
| --- | --- |
| `displayWidthPx`, `displayHeightPx` | Displayed size in CSS pixels at 96 DPI, with fractions. Before crop and rotation. |
| `kind` | `inline` or `anchored`. |
| `alt`, `decorative` | Alternative text: the drawing's description or title, then a chart title. `decorative: true` has an empty `alt`. |
| Page, story, and source location | Where the drawing sits. Source offsets use UTF-16 code units. |

Occurrence and page identifiers belong to one export. Metadata objects and collections are frozen. For every field, see the [image types](https://github.com/eigenpal/docx-editor/blob/main/packages/docx-to-markdown/src/media-types.ts).

## Preserve displayed sizes

Markdown image syntax has no size attributes. The following option emits `img` tags with displayed sizes:

```ts
const result = await exportMarkdown(docxBytes, { images: { syntax: 'html' } });
// <img src="media/<digest>.png" alt="Banner" width="300" height="80">
```

The converter escapes attributes and rounds sizes to whole CSS pixels. The default `syntax: 'markdown'` emits standard image links.

To display `img` tags, your renderer must do the following:

1. Parse the raw HTML, for example with `react-markdown` and `rehype-raw`.
2. Sanitize it, for example with [`rehype-sanitize`](https://github.com/rehypejs/rehype-sanitize).
3. Keep `src`, `alt`, `width`, and `height`.

Never size every image with a URL from its asset's first occurrence. Occurrences follow physical layout, include repeated headers, and are not a Markdown image index.

## Handle failures and limits

`MarkdownMediaError.code` values:

| Code | Meaning |
| --- | --- |
| `media-limit` | Unique image bytes exceed `maxTotalBytes`. Includes `limitBytes` and `actualBytes`. |
| `url-resolution-failed` | `resolveUrl` failed. Keeps `cause` and the asset ID. |
| `invalid-image-url` | `resolveUrl` returned neither a relative path nor an absolute HTTP(S) URL. |
| `image-bytes-unavailable` | Image bytes are unavailable. Keep the owning session open during extraction. |

`MarkdownBundleError.code` values:

| Code                     | Meaning                                              |
| ------------------------ | ---------------------------------------------------- |
| `invalid-media-path`     | An image path is unsafe.                             |
| `duplicate-output-path`  | Two files map to one output path.                    |
| `non-portable-image-url` | The result uses hosted URLs.                         |
| `output-not-empty`       | The output directory has files.                      |
| `write-failed`           | A filesystem write failed. Keeps the cause and path. |
| `archive-failed`         | ZIP creation failed.                                 |

On failure, helpers remove only files they created.

- The default `maxTotalBytes` is 64 MiB of unique extracted bytes, including omitted text-box stories. It must be a positive safe integer. It is not a parsing or memory limit.
- A limit failure rejects the export before any resolver runs, with no partial Markdown.
- Cancellation throws `ExportResourceError` with code `aborted`. It cannot interrupt synchronous parsing or layout, or undo completed uploads.
- The resolver gets a separate byte copy. Returned image bytes stay usable after you dispose the export session.
- Serve untrusted media from an isolated origin, with the real `Content-Type` and `X-Content-Type-Options: nosniff`. For SVG, add a CSP such as `sandbox; default-src 'none'`.
- Core image validation is not SVG sanitization. Render SVG through `<img>`, never inline.
- Extraction never fetches linked external images. Hidden and revision-suppressed images are not extracted.
- A chart exports its saved fallback picture when images are on. Without one, it gets an `omitted-drawing` warning.
- Cropping, rotation, effects, and floating wrap are not reproduced. Anchored images appear at their source paragraph, or after the field when anchored inside a projected field result. For detail, see [DOCX fidelity](/docs/2.x/docx-fidelity).
- `exportMarkdownFrom()` accepts the same `images` options and leaves the session open. `exportMarkdownLayout()` stays text-only and returns `MarkdownExportResult` synchronously.
- Markdown omits a shape group as one drawing, including its member pictures.
- Markdown omits text boxes, note separators, and authored continuation notices. `media` still lists their images and occurrences.
- An unplaced body anchor produces separate document and page `image-placement-fallback` warnings. Page warnings include `pageNumber`.
