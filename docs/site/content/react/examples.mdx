## Automate an open editor

Install the editing API. It requires the [EigenPal Pro License](https://www.docx-editor.dev/pricing).

```bash
npm install @docx-editor.dev/editor-api
```

Render this component inside `DocxEditor.Root`. It reads the first paragraph and shows its text:

```tsx
import { useState } from 'react';
import { useDocxEditor } from '@docx-editor.dev/react';
import { DocxEditor as BrowserDocxEditor } from '@docx-editor.dev/editor-api/browser';

export function FirstParagraph() {
  const editor = useDocxEditor();
  const [text, setText] = useState('');

  async function run() {
    if (!editor) return;
    const runtime = BrowserDocxEditor.createBrowser(editor);

    try {
      await runtime.run(async (context) => {
        const first = context.document.body.paragraphs.getFirst();
        first.load('text');
        await context.sync();
        setText(first.text);
      });
    } finally {
      runtime.dispose();
    }
  }

  return (
    <>
      <button disabled={!editor} onClick={() => void run()}>
        Read first paragraph
      </button>
      <output>{text}</output>
    </>
  );
}
```

## Run the React example

The [`examples/vite`](https://github.com/eigenpal/docx-editor/tree/main/examples/vite) app shows composed chrome, the review sidebar, and a custom node. Run it from the repository root with `bun run dev:react`.

## Limits

- Render automation components inside `DocxEditor.Root`. Wait for a non-null editor before you create the runtime.
- Load explicit properties, such as `load('text')`, and await `context.sync()` before you read them.
- Dispose the runtime in `finally`.
- `save()` on the ref can return `null`. Your app owns any upload of the saved bytes.
