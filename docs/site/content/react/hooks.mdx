Call these hooks from components inside `<DocxEditor.Root>`. The packaged `<DocxEditor>` provides this root for its children.

The hooks connect your React components to the same commands and state that packaged controls use.

## Connect controls to editor state

Build buttons with your own React components and TSX. Use `useEditorCommand` for actions and `useEditorState` for selected state.

Choose visible buttons, icons, and CSS in this example. Hiding a button does not change command availability. The engine supplies enabled state and refusal reasons.

## `useEditorCommand`

Pass a chrome slot ID to `useEditorCommand`. The [chrome slot reference](/docs/2.x/guides/chrome-slots) lists every available ID and its named toolbar part. The hook returns the state and action for a control:

```tsx
import { useEditorCommand } from '@docx-editor.dev/react';

function BoldButton() {
  const bold = useEditorCommand('text.bold');

  return (
    <button
      onMouseDown={(e) => e.preventDefault()}
      onClick={() => bold.execute()}
      disabled={!bold.isEnabled}
      data-active={bold.isActive || undefined}
      title={bold.disabledReason ?? 'Bold'}
    >
      B
    </button>
  );
}
```

| Field            | Type             | Description                                      |
| ---------------- | ---------------- | ------------------------------------------------ |
| `execute()`      | `() => boolean`  | Runs the command and reports whether it applied. |
| `isActive`       | `boolean`        | Reports the command state at the caret.          |
| `isEnabled`      | `boolean`        | Reports whether the command can run.             |
| `disabledReason` | `string \| null` | Explains why the command cannot run.             |

Use `isEnabled` to enable each control. Show `disabledReason` when the command cannot run.

Pass an `EditorCommand` when no chrome slot matches your action:

```tsx
const suggest = useEditorCommand({ type: 'setEditingMode', mode: 'suggesting' });
```

## `useEditorState`

Use `useEditorState` to subscribe to part of the editor snapshot. The hook runs the selector for each state update. It renders your component only when the selected value changes:

```tsx
import { useEditorState } from '@docx-editor.dev/react';

function PageIndicator() {
  const page = useEditorState((s) => s.page);
  return (
    <span>
      {page.current} / {page.total}
    </span>
  );
}

function HistoryStatus() {
  const canUndo = useEditorState((s) => s.canUndo);
  return <span>{canUndo ? 'Undo is available' : 'No undo history'}</span>;
}
```

Pass a comparison function as the second argument for object values:

```tsx
const formatting = useEditorState(
  (s) => s.formatting,
  (a, b) => a?.bold === b?.bold && a?.italic === b?.italic
);
```

`canUndo` reports undo availability. It does not report unsaved changes. Track save completion separately in your application.

Select only the state that your component needs. A page indicator does not need to render after a bold-state change.

Useful fields include:

- `page`
- `selection` and `selectionCollapsed`
- `formatting`
- `table` and `image`
- `editable`
- `isLoading` and `isOpening`
- `parseError`
- `editingMode`
- `canUndo` and `canRedo`
- `pageSetup`
- `fontSubstitutions`
- `hasReviewContent`
- `lastRejection`

## `useDocxEditor`

`useDocxEditor` returns the editor instance. It returns `null` before the `DocxEditor.Root` mount effect creates the instance. It also returns `null` outside a `DocxEditor.Root`. Use the instance for actions and one-time reads:

```tsx
import { useDocxEditor } from '@docx-editor.dev/react';

function SaveButton() {
  const editor = useDocxEditor();
  return (
    <button
      disabled={!editor}
      onClick={async () => {
        const bytes = await editor?.save();
        if (bytes) void upload(bytes);
      }}
    >
      Save
    </button>
  );
}
```

For an external paragraph reference, call `scrollToAnchor` on this same instance:

```tsx
import { useDocxEditor } from '@docx-editor.dev/react';

function ReferenceButton({ paraId }: { paraId: string }) {
  const editor = useDocxEditor();
  return (
    <button
      disabled={!editor}
      onClick={() => {
        if (!editor?.scrollToAnchor({ paraId })) {
          // Show an unavailable-reference state in your application.
          return;
        }
        editor.highlightAnchor({ paraId }, { timeoutMs: 1500 });
      }}
    >
      Show reference
    </button>
  );
}
```

Place this component inside `DocxEditor.Root`. Scrolling and highlighting preserve selection and focus. For more information, see [Scroll to a paragraph reference](/docs/2.x/guides/navigation#scroll-to-a-paragraph-reference) and [Highlight a paragraph reference](/docs/2.x/guides/navigation#highlight-a-paragraph-reference).

Calling `editor.snapshot()` during render does not subscribe your component. Use `useEditorState` for reactive state.

## `useEditorEvent`

Use `useEditorEvent` to subscribe for the component's lifetime:

```tsx
import { useRef } from 'react';
import { useEditorEvent } from '@docx-editor.dev/react';

const lastSelection = useRef<unknown>(null);
// `selectionChange` also fires for other state that moves without a document change, such
// as the collaboration status or the page count, so compare the selection itself.
useEditorEvent('selectionChange', (snapshot) => {
  if (snapshot.selection !== lastSelection.current) setPanelOpen(false);
  lastSelection.current = snapshot.selection;
});
useEditorEvent('change', (change) => void autosave(change.revision));
```

## `useEditorHostDocument`

Use `useEditorHostDocument` in custom chrome that adds document listeners, reads focus, or injects a `<style>` element. It returns the document that the editor's pages are mounted in. If you render the editor in a pop-out window or an iframe, that is the other window's document, not the global `document`. The value changes when the editor moves, so effects that depend on it bind again:

```tsx
import { useEffect } from 'react';
import { useEditorHostDocument } from '@docx-editor.dev/react';

type Props = { onShortcut: (event: KeyboardEvent) => void };

function ShortcutListener({ onShortcut }: Props) {
  const hostDocument = useEditorHostDocument();
  useEffect(() => {
    if (!hostDocument) return undefined;
    hostDocument.addEventListener('keydown', onShortcut);
    return () => hostDocument.removeEventListener('keydown', onShortcut);
  }, [hostDocument, onShortcut]);
  return null;
}
```

The hook returns `null` during server rendering. For more information, see [Pop-out windows and iframes](/docs/2.x/guides/pop-out-windows).

## `useFontFamily`

`useFontFamily` provides font-picker state. It returns the current value, options, setter, and enabled state:

```tsx
import { useFontFamily } from '@docx-editor.dev/react';

function FontPicker() {
  const font = useFontFamily();

  return (
    <select
      value={font.value ?? ''}
      disabled={!font.isEnabled}
      onChange={(e) => font.setValue(e.target.value)}
    >
      {font.options.map((family) => (
        <option key={family} value={family}>
          {family}
        </option>
      ))}
    </select>
  );
}
```

`useParagraphStyle` returns the same shape for paragraph styles.

## `usePageSetup`

Use `usePageSetup` to read and change the current section. The hook supports margins, orientation, and paper size:

```tsx
import { usePageSetup } from '@docx-editor.dev/react';

function OrientationToggle() {
  const { pageSetup, apply, isEnabled } = usePageSetup();
  const landscape = pageSetup?.orientation === 'landscape';

  return (
    <button
      disabled={!isEnabled}
      onClick={() => apply({ orientation: landscape ? 'portrait' : 'landscape' })}
    >
      {landscape ? 'Portrait' : 'Landscape'}
    </button>
  );
}
```

## `useWatermark`

Use `useWatermark` to read and change the document watermark. `apply` sends one `setWatermark` command, so one call creates one undo step. Pass `null` to remove the watermark:

```tsx
import { useWatermark } from '@docx-editor.dev/react';

function DraftToggle() {
  const { watermark, apply, isEnabled } = useWatermark();
  const isDraft = watermark?.text === 'DRAFT';

  return (
    <button disabled={!isEnabled} onClick={() => apply(isDraft ? null : { text: 'DRAFT' })}>
      {isDraft ? 'Remove draft mark' : 'Mark as draft'}
    </button>
  );
}
```

`read()` returns the current watermark as a `setWatermark` value. For a picture watermark it includes the picture bytes.

## `useBookmarks`

Use `useBookmarks` to list the document's bookmarks and change them. `insert` bookmarks the selection, `remove` deletes a bookmark, and `goTo` selects one. Each call sends one command:

```tsx
import { useBookmarks } from '@docx-editor.dev/react';

function BookmarkList() {
  const { bookmarks, goTo } = useBookmarks();
  return (
    <ul>
      {bookmarks
        .filter((bookmark) => !bookmark.hidden)
        .map((bookmark) => (
          <li key={bookmark.name}>
            <button
              onMouseDown={(event) => event.preventDefault()}
              onClick={() => goTo(bookmark.name)}
            >
              {bookmark.name}
            </button>
          </li>
        ))}
    </ul>
  );
}
```

`isWritable` says whether the document accepts bookmark edits at the selection. Go To works in a read-only document too.

The list has one entry per name. If collaborators left copies of a name, `duplicates` on its entry counts them. To keep the first and remove the copies, call `keepFirst(name)`. The selection does not move.

## `useGoToBookmark`

Use `useGoToBookmark` to build a Go To UI of your own, as the **Bookmarks** tab of the navigation pane does. It filters the document's bookmarks by the typed name, keeps a highlighted row, and jumps with the `goToBookmark` command. Call it inside `DocxEditor.Root`:

```tsx
import { useGoToBookmark } from '@docx-editor.dev/react';

function GoToBox() {
  const goTo = useGoToBookmark();
  return (
    <div>
      <input
        value={goTo.query}
        onChange={(event) => goTo.setQuery(event.target.value)}
        onKeyDown={(event) => {
          if (event.key === 'ArrowDown') goTo.move(1);
          if (event.key === 'ArrowUp') goTo.move(-1);
          if (event.key === 'Enter') goTo.go();
        }}
      />
      {goTo.problem === 'notFound' && <p>No bookmark has that name.</p>}
      <ul>
        {goTo.rows.map((row) => (
          <li key={row.name}>{row.name}</li>
        ))}
      </ul>
    </div>
  );
}
```

`go(name?)` jumps to `name`, or else to the highlighted row, the bookmark named exactly as typed, or the first row. It returns the command result. `sortBy`, `showHidden`, and their setters choose the order and whether hidden bookmarks are offered. Pass `{ enabled: isOpen }` to read the document only while your UI is shown. Each row's `place` says whether the bookmark is in the body, a header, a footer, a footnote, or an endnote.

## `useCommentDraftRequest`

Use `useCommentDraftRequest` when you render your own comment UI instead of the packaged review rail. The `review.addComment` control does not add a comment by itself, because the comment text comes from a draft. The engine enables the control only while something can open that draft. The packaged review rail registers itself when it mounts. Without a registration, the control is disabled with a reason.

Register your handler, and press the control with `useEditorCommand`:

```tsx
import { useState } from 'react';
import { useCommentDraftRequest, useEditorCommand } from '@docx-editor.dev/react';

function AddCommentButton() {
  const [drafting, setDrafting] = useState(false);
  useCommentDraftRequest(() => setDrafting(true));
  const addComment = useEditorCommand('review.addComment');
  return (
    <>
      <button
        disabled={!addComment.isEnabled}
        title={addComment.disabledReason ?? 'Add comment'}
        onClick={() => addComment.execute()}
      >
        Add comment
      </button>
      {drafting && <MyCommentDraft onClose={() => setDrafting(false)} />}
    </>
  );
}
```

The handler takes no arguments. Read the selection with `editor.getSelectionPlacement()`, and pin it with `editor.retainSelection()` while the draft is open. The most recent registration receives each press. Pass `null` while your UI cannot open a draft. When the component unmounts, the registration ends, and the control is disabled again if nothing else is registered.

## `useParagraphFormat`

Use `useParagraphFormat` to read and change the paragraph at the selection. `apply` sends the supplied fields as one command, so one call creates one undo step:

```tsx
import { useParagraphFormat } from '@docx-editor.dev/react';

function DoubleSpaceButton() {
  const { format, apply, isEnabled } = useParagraphFormat();
  const isDouble = format?.lineSpacing?.value === 2;

  return (
    <button
      disabled={!isEnabled}
      onClick={() => apply({ lineSpacing: { rule: 'multiple', value: isDouble ? 1 : 2 } })}
    >
      {isDouble ? 'Single space' : 'Double space'}
    </button>
  );
}
```

A field is `null` when selected paragraphs have different values. A checkbox shows an indeterminate state. A number field has no indeterminate state. It shows a default until you change it. Omitted fields are not written, so existing values stay. Spacing, line-spacing, and indent fields also accept `null`. That value clears the local setting so the style supplies it. Writing `0` sets an explicit value instead.

For the whole form, `DocxEditor.ParagraphDialog` is the Paragraph dialog over this hook.

## `useDocumentOutline`

`useDocumentOutline` returns headings in document order. It also provides an action that moves to a heading:

```tsx
import { useDocumentOutline } from '@docx-editor.dev/react';

function Outline() {
  const { items, selectedBlockId, goTo, isEmpty } = useDocumentOutline();
  if (isEmpty) return <p>No headings</p>;

  return (
    <ul>
      {items.map(({ heading, depth }) => (
        <li key={heading.blockId} style={{ paddingLeft: depth * 12 }}>
          <button
            data-active={heading.blockId === selectedBlockId || undefined}
            onClick={() => goTo(heading.blockId)}
          >
            {heading.text}
          </button>
        </li>
      ))}
    </ul>
  );
}
```

Each item has the shape `{ heading, depth }`. `heading` has the shape `{ text, level, blockId }`. `depth` measures indentation from the shallowest heading in the document. This calculation aligns a top-level Heading 2 with the base. Use `headings` when you need the flat list without calculated indentation.

## `useDocumentSearch`

`useDocumentSearch` returns the editor's search session, which the **Find** pane also uses. This toolbar searches as you type, and Enter moves to the next match:

```tsx
import { useDocumentSearch } from '@docx-editor.dev/react';

function Find() {
  const search = useDocumentSearch();

  return (
    <>
      <input
        value={search.query}
        onChange={(event) => search.setQuery(event.target.value)}
        onKeyDown={(event) => {
          if (event.key !== 'Enter') return;
          if (search.isPending) search.find(search.query);
          if (event.shiftKey) search.previous();
          else search.next();
        }}
      />
      <span>
        {search.activeIndex + 1} / {search.matches.length}
        {search.truncated && '+'}
      </span>
      <button onClick={search.previous}>Prev</button>
      <button onClick={search.next}>Next</button>
    </>
  );
}
```

`find(query, { selectFirst: true })` searches and selects the first match. `activeMatch` reports the selected match. The `highlight` option accepts `'all'`, `'active'`, or `'none'`. It defaults to `'all'`. Use `'none'` for a component that only reads results. Another component can still request shared search highlights.

`setQuery()` waits 150 milliseconds without query changes. `find()` searches immediately. `truncated` means the count is a minimum. The example displays `+` when the search reaches 2,000 matches.

`DocxEditor.Navigation` opens **Find** on Cmd+F on macOS, or Ctrl+F elsewhere, while focus is in the editor. For details, see [Open Find with Ctrl+F](/docs/2.x/guides/navigation#open-find-with-ctrlf). For shared requests and result updates, see [Search from code](/docs/2.x/guides/navigation#search-from-code).

## `useHighlights`

`useHighlights(name, source, options)` highlights ranges while the component is mounted and returns `{ applied, unavailable }`. If `source` is a function, it runs again after the document changes. Wrap it in `useCallback`:

```tsx
import { useCallback } from 'react';
import { useHighlights, type Editor } from '@docx-editor.dev/react';

function GlossaryHighlights({ terms }: { terms: readonly string[] }) {
  const findTerms = useCallback(
    (editor: Editor) => editor.findMatches(terms, { wholeWord: true }).flat(),
    [terms]
  );
  useHighlights('glossary', findTerms);
  return null;
}
```

For options, see [Highlight text ranges](/docs/2.x/guides/navigation#highlight-text-ranges).

## `useHighlightAt`

`useHighlightAt(name)` returns the highlight under the pointer, or `null`. For an example, see [Show details on hover](/docs/2.x/guides/navigation#show-details-on-hover).

## `useHistoryGroup`

Use `useHistoryGroup` when your app applies formatting continuously, such as a font-size slider or color picker. The document updates on every input event, and one undo action restores the state before the gesture. A redo action restores the final value.

Render the control inside `DocxEditor.Root`. You can use it in your own toolbar or a [toolbar slot override](/docs/2.x/react/composition). The hook returns two members:

| Member      | How you use it                                              |
| ----------- | ----------------------------------------------------------- |
| `ref`       | Attach it to the input or button that receives the gesture. |
| `options()` | Pass its result to each command produced by that gesture.   |

### Add a live font-size slider

Use `useEditorValueCommand` to read the selected value and apply changes. Its `isEnabled` and `disabledReason` come from the editor. `value` follows the selection and updates after undo and redo. Bind your control to `value` to keep it synchronized with the document.

Font size uses half-points: `24` means 12 pt. `null` means mixed or unavailable.

```tsx
import { useState } from 'react';
import { useEditorValueCommand, useHistoryGroup } from '@docx-editor.dev/react';

export function FontSizeSlider() {
  const size = useEditorValueCommand('font.size');
  const gesture = useHistoryGroup({ kind: 'range' });
  const [error, setError] = useState<string | null>(null);
  const label = size.value === null ? 'Mixed or unavailable' : `${size.value / 2} pt`;

  return (
    <label title={size.disabledReason ?? undefined}>
      Font size: {label}
      <input
        ref={gesture.ref}
        type="range"
        min={16}
        max={144}
        step={1}
        value={size.value ?? 22}
        aria-valuetext={label}
        disabled={!size.isEnabled}
        onChange={(event) => {
          const result = size.execute(Number(event.currentTarget.value), gesture.options());
          setError(result.ok ? null : result.reason);
        }}
      />
      <output aria-live="polite">{error}</output>
    </label>
  );
}
```

To check the behavior:

1. Drag the slider, release it, and drag it again.
2. Click **Undo**. The size returns to the value at the end of the first drag.
3. Click **Undo** again. The original formatting returns.

Holding an arrow key also forms one gesture. Releasing the key ends it.

The binding handles pointer release outside the control, cancellation, lost pointer capture, and blur. It retains the gesture across rerenders and disposes it on unmount or editor replacement. Your value handler does not need to start or end a group.

### Choose the gesture policy

| `kind` | Use it for | What ends the gesture |
| --- | --- | --- |
| `range` | A native range input or custom slider | Pointer release or cancellation, lost pointer capture, keyup, or blur |
| `repeat` | A button that applies repeated values while held | Pointer release or cancellation, lost pointer capture, keyup, or blur |
| `keyboard` | A control driven by repeated keydown events | Keyup, Escape, or blur |
| `native-color` | An HTML color input | Native `change`, next activation, Escape, or blur |

For a repeat button, your app owns the repeat timer. Stop that timer on release or cancellation. The binding groups your writes; it does not generate them.

### Add a native color input

Change the slot to `text.color` and the policy to `native-color`. Color commands accept six hexadecimal digits without `#`. React `onChange` applies each value. The binding listens for the native `change` event to end the gesture.

```tsx
function LiveColor() {
  const color = useEditorValueCommand('text.color');
  const gesture = useHistoryGroup({ kind: 'native-color' });
  const [error, setError] = useState<string | null>(null);

  return (
    <label title={color.disabledReason ?? undefined}>
      Text color
      <input
        ref={gesture.ref}
        type="color"
        disabled={!color.isEnabled}
        value={`#${color.value ?? '000000'}`}
        onChange={(event) => {
          const result = color.execute(event.currentTarget.value.slice(1), gesture.options());
          setError(result.ok ? null : result.reason);
        }}
      />
      <span>{color.value === null ? 'Mixed or unavailable' : color.value}</span>
      <output aria-live="polite">{error}</output>
    </label>
  );
}
```

Native color controls differ between browsers. Native `change` means a committed value; it does not guarantee that a popup closed. If the browser sends no `change` event, the next activation, Escape, blur, or unmount ends the gesture. If you need consistent drag boundaries across browsers, use a custom slider.

### Read command results

`execute(value, options?)` returns `ExecResult`. If `ok` is `false`, use `code` for application logic and `reason` for feedback. If `ok` is `true`, `changed` tells you whether the document changed. At a collapsed caret, a formatting command can set the next typing format without changing the document. The change still creates a local undo entry.

For grouped writes, `result.history?.kind` is `started`, `extended`, `split`, or `none`. A split means another history boundary interrupted the gesture; it does not mean the formatting failed. See the [boundary table and supported commands](/docs/2.x/core#group-one-gesture-into-one-undo-step).

`useEditorValueCommand` also accepts `font.family`, `text.highlight`, `styles.style`, and `list.lineSpacing`. Image value slots are available, but image commands reject the `historyGroup` option.

`useEditorCommand().execute(options)` accepts the same options and returns a boolean. Its event-handler form, `onClick={command.execute}`, still works. If you need the full result for a raw command, get the editor with `useDocxEditor()`. Check that it exists, then call `editor.exec(command, options)`.

A review decision can also be one undo step. Get the editor with `useDocxEditor()`, create a handle with `editor.beginHistoryGroup()`, and pass it to each write: `editor.exec`, `editor.addComment(text, { historyGroup })`, `editor.acceptReviewItem(key, { historyGroup })`, and `runtime.run({ historyGroup }, callback)`. End the handle when the decision is complete. See [Group a review decision](/docs/2.x/core#group-a-review-decision).

For optional development feedback, subscribe with `useEditorEvent('historyDiagnostic', handler)`. The editor reports interrupted groups and possible cases where each update starts a separate group. Diagnostics do not change history behavior or write to the console.

`useReviewAuthor(author)` returns the resolved author style, inside or outside the review rail. Use it to color your own review markers or balloons with the same author colors as the rail.

## Dialog draft contexts

Call the hook in a child component of the matching dialog. Each returns `values`, `setValue(name, value)`, `errors`, `isEnabled`, `apply()`, and `cancel()`.

| Hook | Draft type | Draft keys |
| --- | --- | --- |
| `usePageSetupDialog()` | `PageSetupDialogFields` | `pageWidth`, `pageHeight`, `orientation`, `marginTop`, `marginBottom`, `marginLeft`, `marginRight`, `scope` |
| `useParagraphDialog()` | `UseParagraphDialogReturn['values']` | `direction`, `alignment`, `indentLeft`, `indentRight`, `special`, `specialBy`, `spaceBefore`, `spaceAfter`, `lineRule`, `lineValue`, `contextualSpacing`, `keepNext`, `keepLines`, `widowControl`, `pageBreakBefore`, `tabStops`, `clearedAllTabStops` |
| `useTextFormFieldDialog()` | `TextFormFieldDialogFields` | `defaultText`, `type`, `maxLength`, `format`, `enabled` |
| `useRevisionMarkupDialog()` | `ResolvedRevisionMarkup` | `insertions`, `deletions`, `changedLines`, `movedFrom`, `movedTo`, `cells`, `formatting`, `trackMoves`, `trackFormatting` |
| `useWatermarkDialog()` | `WatermarkDialogFields` | `kind`, `imageData`, `imageName`, `scale`, `washout`, `text`, `fontFamily`, `fontSizePt`, `bold`, `italic`, `transparency`, `color`, `layout` |
| `useBookmarkDialog()` | `BookmarkDialogFields` | `name`, `sortBy`, `showHidden` |
| `useSplitCellDialog()` | `SplitCellDialogFields` | `columns`, `rows` |

Page dimensions, margins, and paragraph indents use twips: 1,440 per inch. Paragraph spacing uses points. `lineValue` is a multiple for `lineRule: 'multiple'`, and points for `'exact'` or `'atLeast'`. Paragraph also exposes `mixed` selection state.

`useRevisionMarkupDialog()` also provides `reset()`, which restores the draft defaults without applying them.

`useSplitCellDialog()` also provides `limits`, the most rows and columns the cell at the selection splits into. The draft keeps each count as typed text.

Most `Field` names match draft keys. Page Setup uses `pageSize` for the size selector, which updates `pageWidth` and `pageHeight`. Paragraph's `clearedAllTabStops` is draft state, not a separate `Field`.

See [Connect a custom input](/docs/2.x/guides/customize-dialogs#connect-a-custom-input) for a complete control and its placement inside the dialog.

## Content-control widget state

Inside `DocxEditorContentControlWidget`, `useContentControlWidget()` exposes the same state and actions that its default parts use:

| Members | Purpose |
| --- | --- |
| `session`, `kind`, `items`, `value`, `setValue` | Current session and ISO or list draft |
| `isEnabled`, `refused`, `apply`, `cancel` | Validated writes and dismissal |
| `calendar`, `focusIso`, `focusDay` | Month grid and keyboard focus |
| `previousMonth`, `nextMonth`, `showMonth` | Relative or direct month navigation |
| `selectDay`, `selectToday` | Immediate date selection |
| `dateText`, `setDateText`, `applyDateText` | Regional numeric date entry |
| `listId`, `listNavigation` | Combo relationship and shared list keyboard behavior |
| `accept`, `replaceImage` | Picture file types and image replacement |

`showMonth(year, month)` takes a zero-based month and a year from 100 through 9999. For date sessions, `apply()` commits an ISO date; `applyDateText()` parses the regional draft first. Use `Calendar`, `Navigation`, `Month`, and `Year` to retain packaged behavior. For composition and CSS hooks, see [Compose the value popup](/docs/2.x/guides/customize-dialogs#compose-the-value-popup).
