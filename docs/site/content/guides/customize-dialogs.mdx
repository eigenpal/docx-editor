Pass `popups` to the editor or `Root`. The editor opens each popup and supplies typed props. Forward those props to the default component to keep its state, validation, and commands.

## Replace a popup part

This example replaces **Apply** in the **Page Setup** dialog and registers the wrapper with `definePopup()`.

<FrameworkTabs variant="block">
<Framework value="react">

```tsx
import { DocxEditor, definePopup } from '@docx-editor.dev/react';
import type { DocxEditorPageSetupDialogProps, DocxEditorPopups } from '@docx-editor.dev/react';
import '@docx-editor.dev/core/styles/editor.css';

function PageSetup(props: DocxEditorPageSetupDialogProps) {
  return (
    <DocxEditor.PageSetupDialog {...props}>
      <DocxEditor.PageSetupDialog.Apply asChild>
        <button className="app-apply">Apply changes</button>
      </DocxEditor.PageSetupDialog.Apply>
    </DocxEditor.PageSetupDialog>
  );
}

const popups: DocxEditorPopups = { pageSetup: definePopup(PageSetup) };

export function Editor({ document }: { document: ArrayBuffer }) {
  return <DocxEditor document={document} popups={popups} />;
}
```

</Framework>
<Framework value="vue">

Create `PageSetup.vue`:

```vue
<script setup lang="ts">
import { DocxEditorPageSetupDialog as Dialog } from '@docx-editor.dev/vue';
import type { DocxEditorPageSetupDialogProps } from '@docx-editor.dev/vue';

const props = withDefaults(defineProps<DocxEditorPageSetupDialogProps>(), {
  preset: true,
});
const Apply = Dialog.Apply;
</script>

<template>
  <Dialog v-bind="props">
    <Apply as-child>
      <button class="app-apply">Apply changes</button>
    </Apply>
  </Dialog>
</template>
```

Keep `preset: true` when you forward Vue props. Otherwise, omitted Boolean props become `false`. Register the component in your editor:

```vue
<script setup lang="ts">
import { DocxEditor, definePopup } from '@docx-editor.dev/vue';
import type { DocxEditorPopups } from '@docx-editor.dev/vue';
import PageSetup from './PageSetup.vue';
import '@docx-editor.dev/core/styles/editor.css';

defineProps<{ document: ArrayBuffer }>();
const popups: DocxEditorPopups = { pageSetup: definePopup(PageSetup) };
</script>

<template>
  <DocxEditor :document="document" :popups="popups" />
</template>
```

</Framework>
</FrameworkTabs>

You can also pass a render callback, such as `(props) => <PageSetup {...props} />` in React or `(props) => h(PageSetup, props)` in Vue. Call hooks inside components, not in the callback.

Parts follow these rules:

- Parts accept `className`, `style`, `hidden`, and `asChild`, and forward `id`, `aria-*`, and `data-*`.
- Built-in behavior wins: `onClick` on `Apply` does not replace its handler.
- With `asChild`, packaged decorative classes stay off your element.
- Set `preset={false}` to supply the complete arrangement.
- Hidden fields keep their draft values.

## Choose a popup

Each entry accepts a `definePopup()` result, a render callback, or `false`.

| Entry | Supplied props |
| --- | --- |
| `export` | `DocxEditorExportDialogProps` |
| `print` | `DocxEditorPrintDialogProps` |
| `pageSetup`, `paragraph`, `watermark`, `bookmark`, `splitCell` | Controlled dialog props: `open`, `onClose` |
| `compareDocuments` | `DocxEditorCompareDocumentsDialogProps`. Requires the review module. |
| `imageInsertError` | `{ message, onClose }` |
| `textFormField` | `{ session: TextFormFieldDialogSession }` |
| `revisionMarkup` | `{ session: RevisionMarkupDialogSession }` |
| `hyperlink` | `HyperLinkProps` |
| `contentControl` | `ContentControlProps` |
| `equation` | No state props |
| `contextMenu` | `DocxEditorContextMenuProps` |
| `imageProperties` | `DocxEditorImagePropertiesDialogProps` |
| `imageAltText` | `DocxEditorImageAltTextPopupProps` |
| `noteProperties` | `DocxEditorNotePropertiesDialogProps` |
| `notesContextMenu` | `DocxEditorNotesContextMenuProps` |
| `notePreview` | `DocxEditorNotePreviewProps` |
| `contentControlWidget`, `contentControlCheckbox`, `contentControlPicture` | `{ session: ContentControlWidgetSession }` |
| `invalidTextFormField` | `{ session: InvalidTextFormFieldSession }` |

Omitted entries keep default behavior. Explicit entries override the `menu.onPageSetup`, `hyperlinkPopup`, and `contextMenu` shortcuts. Toolbar menus and pickers use their compound `.Content` parts instead of this map.

To open the bookmark popup from your own control, run the command:

```ts
editor.exec({ type: 'openBookmarkDialog' });
```

If an entry is `false`, the editor does not open it. For `bookmark`, the command then reports `unsupported` and the menu row is disabled.

## Connect a custom input

Put the input in a named `Field`, and call the draft hook in a component under the dialog provider. This example edits the top margin in inches.

<FrameworkTabs variant="block">
<Framework value="react">

```tsx
import { usePageSetupDialog } from '@docx-editor.dev/react';

function TopMargin() {
  const { values, setValue, isEnabled } = usePageSetupDialog();
  return (
    <label>
      Top margin (inches)
      <input
        type="number"
        step="0.1"
        value={values.marginTop / 1440}
        disabled={!isEnabled}
        onChange={(event) => setValue('marginTop', Math.round(Number(event.target.value) * 1440))}
      />
    </label>
  );
}
```

Add this named child inside your `PageSetupDialog`:

```tsx
<DocxEditor.PageSetupDialog.Field name="marginTop">
  <TopMargin />
</DocxEditor.PageSetupDialog.Field>
```

</Framework>
<Framework value="vue">

Create `TopMargin.vue`:

```vue
<script setup lang="ts">
import { usePageSetupDialog } from '@docx-editor.dev/vue';

const { values, setValue, isEnabled } = usePageSetupDialog();
function update(event: Event) {
  const input = event.target as HTMLInputElement;
  setValue('marginTop', Math.round(Number(input.value) * 1440));
}
</script>

<template>
  <label>
    Top margin (inches)
    <input
      type="number"
      step="0.1"
      :value="values.marginTop / 1440"
      :disabled="!isEnabled"
      @input="update"
    />
  </label>
</template>
```

Import `TopMargin` in `PageSetup.vue` and declare `const Field = Dialog.Field`. Add this named child inside `Dialog`:

```vue
<Field name="marginTop"><TopMargin /></Field>
```

</Framework>
</FrameworkTabs>

| Draft hook                    | Dialog                                                  |
| ----------------------------- | ------------------------------------------------------- |
| `usePageSetupDialog()`        | Page Setup. Draft dimensions use twips: 1,440 per inch. |
| `useParagraphDialog()`        | Paragraph Options. Also exposes mixed-selection state.  |
| `useWatermarkDialog()`        | Watermark                                               |
| `useBookmarkDialog()`         | Bookmark                                                |
| `useTextFormFieldDialog()`    | Field Options                                           |
| `useRevisionMarkupDialog()`   | Track changes options. Also provides `reset()`.         |
| `useCompareDocumentsDialog()` | Compare documents                                       |

Each hook returns `values`, `setValue(name, value)`, `errors`, `isEnabled`, `apply()`, and `cancel()`. Vue exposes state as refs. For types, see [React hooks](/docs/2.x/react/hooks#dialog-draft-contexts) or [Vue composables](/docs/2.x/vue/composables#dialog-draft-contexts).

Keep the default `Apply` and `Error` parts. Invalid values keep the dialog open and show an error.

## Customize specialized sessions

<a id="customize-change-tracking-options" />

### Customize track changes options

The Pro review module opens **Track changes options** through `popups.revisionMarkup`.

```tsx
import { DocxEditor, definePopup } from '@docx-editor.dev/react';
import type { DocxEditorPopups, DocxEditorRevisionMarkupDialogProps } from '@docx-editor.dev/react';

function ReviewOptions(props: DocxEditorRevisionMarkupDialogProps) {
  return (
    <DocxEditor.RevisionMarkupDialog {...props} className="review-options">
      <DocxEditor.RevisionMarkupDialog.Field name="cells" hidden />
      <DocxEditor.RevisionMarkupDialog.Apply asChild>
        <button type="button" className="primary-button">
          Save preferences
        </button>
      </DocxEditor.RevisionMarkupDialog.Apply>
    </DocxEditor.RevisionMarkupDialog>
  );
}

const popups: DocxEditorPopups = {
  revisionMarkup: definePopup(ReviewOptions),
};
```

In Vue, wrap `DocxEditorRevisionMarkupDialog` with `preset: true`, as in the Page Setup example. `Field` names match the top-level `ResolvedRevisionMarkup` keys. `setValue()` replaces one top-level value, so spread the existing value to change a nested property.

Outside React or Vue, register `setRevisionMarkupChrome({ onRequest })`, and unregister it when your host unmounts. The request supplies a draft session with `get()`, `set(partial)`, `reset()`, `subscribe(listener)`, `canApply()`, `apply()`, `cancel()`, and `signal`. `apply()` returns `false` when the session cannot apply.

- `set(partial)` validates and merges the draft. `reset()` restores the default draft. Neither method applies settings.
- Read `get()` before you subscribe. `subscribe()` reports later changes and returns an unsubscribe function.
- An external revision-markup update replaces the draft of the open session.
- Manual registrations override adapter fallbacks. Register `null` to use native rendering until you dispose that registration.

Opening a session requires the review module, an attached editor, and the EigenPal Pro License. These renderer methods are host infrastructure, not Office.js-shaped automation.

### Compose the value popup

Use `DocxEditorContentControlWidget` for content-control popups. Check `session.kind` before you render date parts.

<FrameworkTabs variant="block">
<Framework value="react">

```tsx
import {
  DocxEditorContentControlWidget as Widget,
  type DocxEditorContentControlWidgetProps,
} from '@docx-editor.dev/react';

export function BrandedWidget({ session }: DocxEditorContentControlWidgetProps) {
  if (session.kind !== 'date') return <Widget session={session} />;

  return (
    <Widget session={session} className="brand-popup">
      <Widget.Header />
      <Widget.Weekdays />
      <Widget.Grid className="brand-grid" />
      <Widget.Today asChild>
        <button type="button" className="brand-button">
          Pick today
        </button>
      </Widget.Today>
      <Widget.Input />
      <Widget.Error />
      <Widget.Footer />
    </Widget>
  );
}
```

</Framework>
<Framework value="vue">

```vue
<script setup lang="ts">
import {
  DocxEditorContentControlWidget as Widget,
  type DocxEditorContentControlWidgetProps,
} from '@docx-editor.dev/vue';

defineProps<DocxEditorContentControlWidgetProps>();
</script>

<template>
  <Widget v-if="session.kind === 'date'" :session="session" class-name="brand-popup">
    <Widget.Header />
    <Widget.Weekdays />
    <Widget.Grid class-name="brand-grid" />
    <Widget.Today as-child>
      <button type="button" class="brand-button">Pick today</button>
    </Widget.Today>
    <Widget.Input />
    <Widget.Error />
    <Widget.Footer />
  </Widget>
  <Widget v-else :session="session" />
</template>
```

</Framework>
</FrameworkTabs>

Register it as `contentControlWidget: definePopup(BrandedWidget)`. The root handles placement, Escape, outside clicks, focus return, and Tab wrapping.

| Entry | Controls | Default when omitted |
| --- | --- | --- |
| `contentControlWidget` | Dropdown, combo box, date, and building block gallery | List or calendar |
| `contentControlCheckbox` | Checkbox | Toggle immediately |
| `contentControlPicture` | Picture | Open a file dialog |

| Task | Parts |
| --- | --- |
| Render a complete date picker | `Calendar` |
| Arrange calendar navigation | `Header`, `PreviousMonth`, `Title`, `NextMonth`, `Navigation`, `Month`, `Year` |
| Arrange dates and entry | `Weekdays`, `Grid`, `Day`, `Today`, `Input` |
| Render choices or a picture picker | `List`, `Item`, `Picture` |
| Show errors and actions | `Error`, `Footer`, `Apply`, `Cancel` |

Call `useContentControlWidget()` in a child of `Widget` for custom actions:

| Member | Description |
| --- | --- |
| `setValue(value)` | Updates the draft. |
| `apply(value?)` | Commits the draft or an explicit value. A refused write returns `false`, keeps the popup open, and sets `refused`. |
| `cancel()` | Closes without applying. |
| `dateText`, `setDateText`, `applyDateText` | Regional numeric date entry through `session.locale`. Dates use `YYYY-MM-DD`. |
| `items` | List entries. Pass one to `Item`, or call `apply(item.value)`. |
| `accept`, `replaceImage(fileOrBytes)` | Picture replacement. Returns `Promise<boolean>` and keeps the drawing size. |

Checkbox values are `'true'` and `'false'`. A checkbox root without children toggles at once; custom children must call `apply`.

For a custom grid, use `calendar.days` and `focusDay`. For a custom list, use `listId` and `listNavigation`. For a custom root, call `observeContentControlPopup(panel, session.anchor)` and `contentControlPopupKeyDown` from `@docx-editor.dev/core/editor`, and handle outside clicks, focus return, and `session.signal` yourself. Call the cleanup function that `observeContentControlPopup()` returns when your popup closes.

### Customize export feedback

Register `popups.export` to customize progress and errors for **File > Export**. Forward the props to `DocxEditor.ExportDialog` (`DocxEditorExportDialog` in Vue) to keep keyboard handling and focus restoration.

| Property    | Description                                                       |
| ----------- | ----------------------------------------------------------------- |
| `open`      | `true` while the popup is mounted.                                |
| `format`    | `markdown` or `pdf`.                                              |
| `pending`   | `true` while conversion runs; `false` after a failure.            |
| `error`     | Localized failure text, including missing converter instructions. |
| `onClose()` | Dismisses feedback. Conversion keeps running.                     |

Successful downloads close the popup. If a dismissed conversion fails, the error opens the popup again. Progress and error states share one popup instance, and each later export creates a new one. For converter setup, see [Export Markdown and PDF](/docs/2.x/guides/export).

### Customize print feedback

Register `popups.print` to customize settings, progress, and errors for **File > Print**. Forward the props to `DocxEditor.PrintDialog` (`DocxEditorPrintDialog` in Vue), in the same way as the export popup.

| Property | Description |
| --- | --- |
| `open` | `true` while the popup is mounted. |
| `pending` | `true` while the editor saves, converts, and loads the PDF. |
| `error` | Localized failure text. Empty during preparation. |
| `url` | Object URL for the PDF when printing fails after conversion. Valid until the next print or menu unmount. |
| `onClose()` | Closes the popup and cancels pending printing. A running conversion result is discarded. |
| `choosing` | `true` while the popup shows print settings. |
| `settings` | `displayMode` and `comments`. |
| `onSettingsChange(change)` | Changes one or both settings. |
| `onPrint()` | Starts conversion with `settings`. |

A custom print popup gets the settings step only when the menu sets `printSettings: true`. Otherwise printing starts at once.

The editor closes the popup before the browser print dialog opens. Progress and error states share one popup instance, and each later print creates a new one. For the print-job lifecycle, see [Print documents](/docs/2.x/guides/print).

## Style popups

Import your stylesheet after the core stylesheet. Dialogs inherit `--doc-*` colors, so a dark editor gets a dark dialog.

```css
/* className="app-rounded" on the packaged Apply part. */
.docx-editor [data-docx-dialog='pageSetup'] .app-rounded {
  border-radius: 999px;
  padding-inline: 1.25rem;
}
```

| Token or selector | Controls |
| --- | --- |
| `--doc-dialog-font-family` | Panel font stack. |
| `--doc-dialog-font-size` | Base size. Titles, labels, and hints scale from it. |
| `--doc-dialog-radius` | Panel corner radius. |
| `--doc-dialog-control-radius` | Corner radius of inputs, text areas, selects, and buttons. |
| `--doc-dialog-padding` | Side inset of the header, body, and footer. |
| `--doc-dialog-gap` | Vertical distance between rows and sections. |
| `data-docx-dialog` | `pageSetup`, `paragraph`, `watermark`, `bookmark`, `imageInsertError`, `textFormField`, or `revisionMarkup`. |
| `data-docx-part`, `data-docx-field` | Lowercase part names and field names. |

Default rules use at least two classes, such as `.docx-editor .docx-dialog__button`. To override them:

- Add a class or attribute that the default rule does not have, and skip `!important`.
- With `asChild`, a single class styles your element as written.
- The hyperlink popup `Root` keeps its packaged class. Override it with a scoped `.docx-hyperlink-popup` rule.

## Limits

- Custom children must forward refs, attributes, events, the supplied handler, and disabled state.
- `Field` and `asChild` do not adapt input value events. Use the draft hook.
- Draft hooks must run under their matching dialog provider.
- Keep a title, an error region, and accessible dismissal and apply controls in custom arrangements.
- A session ends when its signal aborts: on dismissal, replacement, document load, detach, destroy, or renderer disposal. Do not reuse it.
- `false` on `export` or `print` suppresses feedback only. The operation still runs, so your handlers must report errors.
- External portals and Vue `Teleport` do not inherit the editor theme. Provide it at the destination.
- Invalid-field sessions use `acknowledge()` to handle the fill, or `cancel()` to dismiss without clearing it.
