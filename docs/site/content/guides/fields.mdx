A DOCX field stores an instruction and an optional saved result. The editor preserves both through open and save. It evaluates a defined set of display-only fields.

<Callout type="warn">
  Field instructions stay inert. The editor never runs macros, DDE instructions, OLE content, or
  external include instructions such as `INCLUDETEXT` and `INCLUDEPICTURE`. External image links
  never fetch content.
</Callout>

## Supported fields

| Field | Behavior |
| --- | --- |
| `PAGE`, `NUMPAGES`, `SECTIONPAGES` | Update in headers and footers. Body fields with an empty saved result also update. |
| `STYLEREF` | Updates supported character-style and paragraph-style references in headers. A paragraph without a paragraph style matches the default paragraph style. A paragraph style outranks a character style with the same name. Supports `\l` and `\* MERGEFORMAT`. |
| `REF` | Resolves bookmark text or numbering in the body and notes. |
| `NOTEREF` | Resolves a bookmarked footnote or endnote reference number. |
| `AUTONUM`, `AUTONUMLGL`, `AUTONUMOUT` | Generate separate number sequences in document order. |
| `LISTNUM` | Numbers from the document's list definitions in the body. Without a name, uses the list of its paragraph or of the last numbered paragraph before it, else the built-in list. Without `\l`, a field in a numbered paragraph uses the next level down. In the built-in list, the level is the paragraph's outline level, else the level below the last heading. |
| `SYMBOL` | Renders the requested character, font, and size. |
| Selected metadata fields | Render sanitized values from document properties. |
| `DATE`, `TIME`, `FILENAME`, `SEQ`, `EQ`, `CITATION`, `BIBLIOGRAPHY` | Show the saved result. No new value is calculated. |

Other fields show their saved result. `REF`, `PAGEREF`, and `NOTEREF` with `\h` link to their bookmark. For switch support, wrapping, and header pagination, see [DOCX fidelity](/docs/2.x/docx-fidelity#fields-links-and-table-of-contents).

## Edit saved field results

Set `fieldResults` to `'editable'` when you create the editor to let users edit saved results:

```ts
import { createDocxEditor } from '@docx-editor.dev/core';

const editor = createDocxEditor({
  container,
  document: bytes,
  fieldResults: 'editable',
});
```

The packaged editor and `DocxEditor.Root` accept the same prop:

<FrameworkTabs>
<Framework value="react">

```tsx
import { DocxEditor } from '@docx-editor.dev/react';

export function FieldEditor({ bytes }: { bytes: Uint8Array }) {
  return <DocxEditor document={bytes} fieldResults="editable" />;
}
```

</Framework>
<Framework value="vue">

```vue
<script setup lang="ts">
import { DocxEditor } from '@docx-editor.dev/vue';

defineProps<{ bytes: Uint8Array }>();
</script>

<template>
  <DocxEditor :document="bytes" field-results="editable" />
</template>
```

</Framework>
</FrameworkTabs>

The option applies only at creation. Later prop changes have no effect and log a development warning. By default, each field behaves as one unit.

| Field kind | In editable mode |
| --- | --- |
| `DATE`, `TIME`, `CREATEDATE`, `SAVEDATE`, `PRINTDATE`, `MERGEFIELD`, `HYPERLINK`, `QUOTE`, `FILENAME`, `FILLIN`, `SEQ` | The saved result is editable text. |
| Computed fields, such as `PAGE`, `NUMPAGES`, `REF`, `PAGEREF`, `DOCPROPERTY` | Stay one atomic unit. |
| A simple field (`w:fldSimple`) inside a complex field result | Not supported. Do not enable editable mode for these documents. |

- Manual edits save as result text. The editor does not calculate the field or set `w:dirty`.
- An application that updates fields later can replace manual edits, except `HYPERLINK` display text and locked fields.
- Suggesting mode tracks edits inside the result.
- Text typed at either edge of a result stays outside the field.
- Deleting only the result text leaves an empty field that acts as one unit. Typing goes beside it, and an adjacent Backspace or Delete removes it.
- Editing the result of a `w:fldSimple` field converts it to an equivalent complex field.
- If you set `fieldResults: 'editable'` and register a collaboration module, `createDocxEditor` throws a `TypeError`.
- For a custom core integration, pass the same `FieldResultsMode` to layout, `paragraphTextOf()`, and each edit. The modes produce different text offsets.

## Insert and update fields from code

The automation API inserts fields with the Office.js-shaped `Range.insertField()`:

```ts
await runtime.run(async (context) => {
  const hit = context.document.body.search('see section ').getFirst();
  hit.insertField('After', 'Ref', '_Ref123456 \\h');
  await context.sync();
});
```

Insertion writes the instruction as text and never evaluates it. For field types, tracked insertion, and `updateResult()`, see [Fields and pagination](/docs/2.x/editor-api/fields).

## Refresh results on save

`save()` updates calibrated, writable `REF` and `NOTEREF` results in the body, footnotes, and endnotes. The refresh can add one undo step for all updated parts.

- Locked fields, revision markup, nested or unsafe results, and protected content controls keep their saved result.
- View mode, read-only sessions, and collaborative sessions do not rewrite results.
- `REF` updates only when its saved result at open matches the computed value or is empty. Otherwise the saved result stays.

## Legacy text form fields

Legacy `FORMTEXT` fields open the **Field Options** popup on double-click. Configure the popups and date parsing with these props:

| Prop | Purpose |
| --- | --- |
| `popups.textFormField` | Replaces the **Field Options** popup (default value, type, maximum length, format, fill-in). |
| `popups.invalidTextFormField` | Replaces the alert for an invalid number or date. |
| `locale` | Parses date input. Defaults to `en-US`. |
| `i18n` | Sets interface strings. Independent of `locale`. |

This example accepts Polish dates with the default English interface:

```tsx
<DocxEditor document={bytes} locale="pl-PL" />
```

With `pl-PL`, `01.02.2030` means February 1. ISO input (`2030-02-01`) works in every locale. For popup composition, see [Customize popups](/docs/2.x/guides/customize-dialogs).

- Unprotected fields: partial edits keep the field definition. Replacing the whole result removes the field definition.
- Protected fields: with [forms protection](/docs/2.x/guides/document-protection), filling keeps the definition and Tab moves between fields.
- Protected input validates and formats when the user leaves the field.
- Invalid pending protected input makes `save()` reject with code `invalidArgs`. The input stays for correction.
- Date input supports Gregorian numeric dates and full English month names only.
- A maximum length of `0` sets no length limit.

`FORMCHECKBOX` and `FORMDROPDOWN` fields toggle or select in one undo step. Disabled fields and viewing mode refuse changes. Suggesting mode also refuses them, because the value has no tracked form. Entry and exit macros never run.

## Remove a table of contents

Run the `removeToc` command to remove a generated table of contents (TOC):

```ts
const tocId = editor.snapshot().tocContext?.id;
editor.exec({ type: 'removeToc', ...(tocId ? { tocId } : {}) });
```

Without `tocId`, the command targets the last right-clicked TOC, the TOC at the selection, or the only TOC. The removal is one undo step and synchronizes in collaboration sessions. The context menu offers **Remove table of contents**.

The command refuses and leaves the document unchanged in these cases:

- Suggesting mode. A removal has no tracked form.
- Locked or data-bound TOC content.
- A section break before the end of the field, or a table or content control inside the field.

A successful removal handles nearby content as follows:

| Content | After removal |
| --- | --- |
| Text before and after the field | Stays, joined into one paragraph. |
| A section break at the end of the TOC | Stays, in the joined paragraph or in an empty paragraph. |
| Comments and footnotes anchored wholly inside the TOC | Removed. |
| Bookmark and comment ranges that partly overlap the TOC | Stay. Their removed ends move to the deletion point. |
| A wrapper control locked only against deletion | Stays with its heading. The command removes only the field. |

Generated TOC rows are read-only. Delete and Backspace do not remove them.

## Limits

- Computed fields stay atomic in every mode.
- Field instructions stay inert. Macros, DDE, OLE, and external include instructions never execute.
- Saved results inside another field's instruction do not display.
- `LISTNUM` and `REF` in headers, footers, and text boxes keep their saved result.
- `NOTEREF` with `\p` or `\f` keeps its saved result.
- `STYLEREF` results longer than 4,096 characters keep their saved result.
- Header `STYLEREF` fields keep their saved results when the body exceeds the scan limits.
- Header `STYLEREF` pagination stops with an error if it does not settle within its pass limit.
- Option+F9 (macOS) or Alt+F9 (Windows) shows field instructions without changing the document.
