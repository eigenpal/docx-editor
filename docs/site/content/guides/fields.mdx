Word fields contain an instruction and an optional saved result. The editor
preserves both forms when it opens and saves a DOCX file.

The editor evaluates a defined set of display-only fields. It never runs macros,
DDE instructions, or external include instructions.

## Supported fields

| Field                                     | Behavior                                                            |
| ----------------------------------------- | ------------------------------------------------------------------- |
| `PAGE`, `NUMPAGES`, and `SECTIONPAGES`    | Update in headers and footers. Empty-cache body fields also update. |
| `REF`                                     | Resolves bookmark text or numbering in the document body and notes. |
| `NOTEREF`                                 | Resolves a bookmarked footnote or endnote reference number.         |
| `AUTONUM`, `AUTONUMLGL`, and `AUTONUMOUT` | Generate separate document-order number sequences.                  |
| `SYMBOL`                                  | Renders the requested character, font, and size.                    |
| Selected metadata fields                  | Render sanitized values from document properties.                   |

The editor also renders saved results for other complex and simple fields.
Unsupported instructions keep their saved result.

## `REF` fields

`REF` resolves bookmark text and numbered paragraph references. The editor
supports the `\r`, `\w`, `\n`, `\t`, `\h`, and `\* MERGEFORMAT` switches.

The `\t` switch removes text that is not a number delimiter from a referenced
number. It needs `\r`, `\w`, or `\n`. The `\h` switch parses without adding
hyperlink behavior.

The editor checks a non-empty saved result once. A matching result enables live
updates after later edits. A mismatch keeps Word's saved result for that field.

An empty saved result remains eligible for live updates.

The editor also keeps the saved result for missing bookmarks, bullet targets,
and unsupported switches. Bookmark text resolution stops at the target
paragraph boundary.

The `\r` switch uses the same full-context number as `\w`. It does not calculate
Word's relative number.

Live `REF` resolution covers the document body, footnotes, and endnotes. Header,
footer, and text-box results keep their saved values.

## `NOTEREF` fields

`NOTEREF` resolves the display number of a bookmarked footnote or endnote
reference. It honors section number formats and `eachSect` restarts.

The editor keeps the saved result for `\p`, `\f`, `eachPage` restarts, and custom
note marks. The `\h` switch does not add hyperlink behavior.

## `AUTONUM` fields

Each `AUTONUM` field kind has its own sequence. The editor numbers each sequence
in document order.

Word can restart these counters by heading context. The editor does not apply
that restart behavior.

The `\*` switch supports Arabic, alphabetic, Roman, ordinal, cardinal text,
ordinal text, and hexadecimal formats. The `\e` switch removes the trailing
period.

An unsupported switch produces no generated value. Save does not add result
runs because Word does not store results for these fields.

## Save-time refresh

`save()` updates calibrated, writable `REF` and `NOTEREF` results in the body,
footnotes, and endnotes. It commits all updated parts in one undo step.

The editor skips locked fields, revision markup, nested or unsafe result
structures, and protected content controls. A skipped field keeps its saved
result.

View mode and read-only sessions do not rewrite results. A collaborative session
also exports the saved results without rewriting them.

## Fields that stay inert

`DATE`, `TIME`, `FILENAME`, `SEQ`, `LISTNUM`, `EQ`, `CITATION`, and
`BIBLIOGRAPHY` do not calculate a new value. The editor displays a saved result
when one exists.

The editor preserves field instructions through save. It does not execute
macros, DDE instructions, OLE content, or external include instructions.

## Legacy text form fields

In an unprotected document, clicking a `FORMTEXT` field selects its whole result.
Replacing the whole result removes the field definition. Editing part of its result keeps the definition.
Press Backspace immediately after a field, or Delete immediately before it,
to select the whole field. Press the key again to remove it.
Double-click a text form field, or select **Edit field…** from its context menu.
Press Shift+F10 to open the context menu from the keyboard.
The same options dialog appears in React and Vue.

Set the default value, type, maximum length, format, and **Fill-in enabled**.
A maximum length of zero means unlimited. The dialog supports regular text,
number, and date inputs with the formats in its list.
The native selection highlight marks a whole selected field. A caret marks an
insertion point inside its text. Field shading and accessible status provide context.

In a document protected for forms, typing changes the result and keeps the
field definition and default. Press Tab or Shift+Tab to select another enabled
text form field. Other document text remains protected.

The default-text dialog and protected filling accept plain text results.
They refuse results with nested fields, revision markup, or other structure.
Protected filling enforces maximum length and skips disabled fields.
Pasting into a limited field keeps the prefix that fits its remaining capacity.
When you leave a field, the editor validates and formats its result.
The default value stays unchanged. An invalid number or date opens an alert.
Acknowledge the alert to clear the invalid result and enter another value in the same field.
Undo restores the cleared input. If the field changes while the alert is open,
the editor checks its current value and protection before clearing it.

When you leave a numeric field, the editor converts supported mixed input before
formatting. For example, `a1b2c3` becomes `123`, and `abc` becomes zero.
It accepts dollar signs, grouping commas, spaces, and accounting parentheses.
An empty numeric output format truncates fractional digits during filling.
Formatted numeric defaults use the same conversion: `abc 12` with `0.00` becomes `12.00`.
Without a numeric format, the default remains verbatim, including text such as `abc 12`.
Formatted numeric defaults store the formatted value in the DOCX default metadata.
Reopening an unchanged numeric default preserves its existing input-length limit.

Set `locale` on the React or Vue editor or root component to select regional date
input conventions. Use a full BCP-47 tag, such as `en-US`, `en-GB`, or `pl-PL`:

```tsx
<DocxEditor locale="pl-PL" />
```

`locale` selects how newly entered dates are interpreted. Each field's authored
output format still controls its displayed result. With `en-GB`, `1/2/2030` means
February 1, even when the field displays `MM/dd/yyyy`. With `pl-PL`, `01.02.2030`
also means February 1. Year-first locales such as `ja-JP` accept `2030/2/1`.

The editor derives Gregorian numeric order and punctuation from
`Intl.DateTimeFormat.formatToParts()`. It accepts the locale's numeric pattern,
ASCII digits and the locale's digits, and common slash, dot, or hyphen separators.
Dates use the Gregorian calendar even if the locale requests another calendar.
ISO dates (`2030-02-01`) and full English month names are also supported.
ISO-shaped year-month-day input takes precedence if it conflicts with a regional pattern. Localized
month names, non-Gregorian input, and arbitrary operating-system date-format overrides
are not supported. Locale does not change number-field parsing or localize the
month names in an authored output picture.

For day-first and month-first locales, unambiguous `12/31/2030` and `31/12/2030`
both mean December 31. Ambiguous dates follow locale; impossible dates are rejected.
Two-digit years 00–29 mean 2000–2029; 30–99 mean 1930–1999.

Omitted, malformed, or runtime-unsupported editor locales fall back to `en-US`,
independently of the browser or server default. Language-only tags are accepted;
use a regional tag when the distinction matters. UI strings remain controlled by
`i18n`. Engine-generated labels use the matching translation catalogue, falling
back to a compatible language/script catalogue and then to English.

Locale changes apply without a remount. An in-progress field edit keeps the locale
it started with; later edits use the new locale. Visiting an unchanged field does
not reparse its displayed date. Saved formatted date defaults retain their output
picture when reopened under another locale.

For headless form operations, pass `locale` to `setTextFormFieldDefault` or
`commitTextFormField`. Omission means `en-US`; malformed operation locale values
are rejected as invalid arguments.

Full parity across Word locales and all input grammars is not established.
Unsupported syntax remains refused rather than guessed.

Computed text input types and format pictures outside the dialog's list remain
preserved. They do not accept protected filling. Checkbox and dropdown interactions
are not supported. The editor never runs entry or exit macros.
