DOCX document protection restricts which edits a document permits. The editor enforces recorded restrictions and toggles forms protection. The toggle does not require an EigenPal Pro License.

## Toggle forms protection

Check the `toggleDocumentProtection` command before you run it:

```ts
import type { Editor } from '@docx-editor.dev/core';

function toggleProtection(editor: Editor) {
  const command = { type: 'toggleDocumentProtection' } as const;
  const permission = editor.can(command);
  return permission.ok ? editor.exec(command) : permission;
}
```

When the result has `ok: false`, show its `reason`. Do not infer permission from the editing mode. Each toggle is one undo step, and save preserves the setting.

- The command enables forms protection only. It cannot set read-only, comments-only, or tracked-changes protection.
- If the document records one of those restrictions with enforcement off, the command refuses with `locked`. Change that restriction in another tool first.
- Stopping protection keeps the recorded restriction with enforcement off.
- The command can stop other enforced restrictions that have no password.

In custom chrome, bind the `review.protectDocument` [chrome slot](/docs/2.x/guides/chrome-slots#review-and-content-controls) with `useEditorCommand()`. The packaged menu item is **Review > Protect Document for Forms**.

## Read protection state

Read `editor.snapshot().documentProtection`. It is `null` before a document loads.

| Field      | Meaning                                                                             |
| ---------- | ----------------------------------------------------------------------------------- |
| `edit`     | Recorded restriction: `none`, `forms`, `readOnly`, `comments`, or `trackedChanges`. |
| `enforced` | Whether the restriction is active. Check this before you treat `edit` as a lock.    |
| `password` | Whether the document carries protection password metadata.                          |

## Check permitted operations

The editor applies a restriction only when `enforced` is `true`:

| Restriction | Permitted operations |
| --- | --- |
| Forms | Fill text form fields, toggle checkboxes, select dropdown entries, and edit inside unlocked controls or unprotected sections. Suggesting mode is unavailable. |
| Read-only | Viewing mode. Content edits and comment writes are unavailable. |
| Comments-only | Comment writes in editing mode. Content edits and suggesting mode are unavailable. |
| Tracked changes | Suggesting mode with a review module and an author. Untracked editing is unavailable. |

Commands that would change protected content return `locked` with a reason. For filling behavior, see [Fields and cross-references](/docs/2.x/guides/fields#legacy-text-form-fields) and [Content controls](/docs/2.x/guides/content-controls).

## Limits

- The editor cannot set or verify protection passwords.
- With `mode="view"`, the session stays read-only. Comment writes and the protection toggle are unavailable.
- Turning on forms protection while suggesting switches to editing mode. `snapshot().lastRejection` explains the change.
- Tracked-changes protection does not supply a missing review module or author. See [Suggesting needs an author](/docs/2.x/pro/tracked-changes#suggesting-needs-an-author).
- Comments and review keep their own [Pro setup](/docs/2.x/pro) requirements.
- Permission exception ranges (`w:permStart`) do not grant editing access.
- Forms protection permits filling supported legacy text fields, but refuses direct formatting of them.

<Callout type="warn">
  Document protection does not authorize collaboration clients. Remote updates bypass local
  protection checks. Enforce room access in your application.
</Callout>
