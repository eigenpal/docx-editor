Keep the packaged toolbar, replace individual controls, or compose your own interface. Import components and hooks from your React or Vue adapter.

Text direction commands are in the **Format** menu. The default toolbar omits their shortcuts. You can add the `LeftToRight` and `RightToLeft` toolbar parts to a custom toolbar.

## Build a toolbar with the composition API

Compose named toolbar parts and style them with CSS. These examples show selected controls and application styles, not packaged presets. The source includes the selected composition and CSS.

Hiding a control does not remove its editor API operation. The document state determines whether each command is available.

<ToolbarCustomDemo />

Choose an approach for your application:

| Goal                                       | API                                      |
| ------------------------------------------ | ---------------------------------------- |
| Keep the default controls                  | `DocxEditor.Toolbar`                     |
| Change a control's appearance              | `className`, `icon`, or `asChild`        |
| Add your controls and keep them responsive | `Toolbar.Group`                          |
| Replace one control with your own content  | `Toolbar.Slot`                           |
| Remove a whole group                       | `Toolbar.Group` with `hidden`            |
| Arrange selected controls                  | `preset={false}` and named toolbar parts |
| Use your own buttons                       | `useEditorCommand(slotId)`               |
| Change interface colors                    | `--doc-*` CSS properties                 |

For toolbar placement and optional components, see [React composition](/docs/2.x/react/composition#arrange-editor-components) or [Vue composition](/docs/2.x/vue/composition#arrange-editor-components).

## Use the provider primitives

Use provider primitives when your application owns the editor frame. Import the editor stylesheet once and give the container a height. Packaged controls and the viewport apply their own `.docx-editor` scope. Add that class to a wrapper when custom controls need editor styles and tokens.

For complete wrappers, see [React composition](/docs/2.x/react/composition#primitives) or [Vue composition](/docs/2.x/vue/composition#primitives).

<FrameworkTabs>
<Framework value="react">

```tsx
import { DocxEditor, useChromeTranslate } from '@docx-editor.dev/react';

function MyChrome({ bytes }: { bytes: Uint8Array }) {
  const t = useChromeTranslate();
  return (
    <DocxEditor.Root document={bytes}>
      <DocxEditor.Toolbar t={t} />
      <DocxEditor.Viewport>
        <DocxEditor.Content />
        <DocxEditor.HyperLink />
        <DocxEditor.ContextMenu />
      </DocxEditor.Viewport>
    </DocxEditor.Root>
  );
}
```

</Framework>
<Framework value="vue">

```vue
<script setup lang="ts">
import {
  DocxEditorContent,
  DocxEditorContextMenu,
  DocxEditorHyperLink,
  DocxEditorRoot,
  DocxEditorToolbar,
  DocxEditorViewport,
  useChromeTranslate,
} from '@docx-editor.dev/vue';

defineProps<{ bytes: Uint8Array }>();
const t = useChromeTranslate();
</script>

<template>
  <DocxEditorRoot :document="bytes">
    <DocxEditorToolbar :t="t" />
    <DocxEditorViewport>
      <DocxEditorContent />
      <DocxEditorHyperLink />
      <DocxEditorContextMenu />
    </DocxEditorViewport>
  </DocxEditorRoot>
</template>
```

</Framework>
</FrameworkTabs>

If you use a locale provider, mount this component inside it so `useChromeTranslate()` reads its catalog.

`Root` owns the editor instance. `Viewport` provides scrolling. `Content` displays editable pages. Other parts use the same provider.

## Keep host controls responsive

The preset toolbar stays on one row. When it runs out of width, it moves whole groups into the **More** (`⋯`) panel, and each moved group becomes a labelled section of the panel. Use `Toolbar.Group` to give your own controls the same behavior.

<FrameworkTabs>
<Framework value="react">

```tsx
<DocxEditor.Toolbar>
  {/* A host group: measured, collapsed by priority, and labelled in the panel. */}
  <DocxEditor.Toolbar.Group id="review-nav" label="Review" priority={15}>
    <DocxEditor.Toolbar.Action label="Previous change" icon={<UpIcon />} onSelect={previous} />
    <DocxEditor.Toolbar.Action label="Next change" icon={<DownIcon />} onSelect={next} />
  </DocxEditor.Toolbar.Group>

  {/* A built-in id adds controls to that group. */}
  <DocxEditor.Toolbar.Group id="review">
    <DocxEditor.Toolbar.AddComment />
  </DocxEditor.Toolbar.Group>

  {/* `hidden` removes a whole built-in group and its separator. */}
  <DocxEditor.Toolbar.Group id="zoom" hidden />
</DocxEditor.Toolbar>
```

</Framework>
<Framework value="vue">

```vue
<DocxEditorToolbar>
  <!-- A host group: measured, collapsed by priority, and labelled in the panel. -->
  <DocxEditorToolbar.Group id="review-nav" label="Review" :priority="15">
    <DocxEditorToolbar.Action label="Previous change" @select="previous" />
    <DocxEditorToolbar.Action label="Next change" @select="next" />
  </DocxEditorToolbar.Group>

  <!-- A built-in id adds controls to that group. -->
  <DocxEditorToolbar.Group id="review">
    <DocxEditorToolbar.AddComment />
  </DocxEditorToolbar.Group>

  <!-- `hidden` removes a whole built-in group and its separator. -->
  <DocxEditorToolbar.Group id="zoom" hidden />
</DocxEditorToolbar>
```

</Framework>
</FrameworkTabs>

`Toolbar.Group` takes these props:

| Prop | Description |
| --- | --- |
| `id` | The group id. A built-in id changes that group. Any other id creates a host group. |
| `label` | The panel heading and the group's accessible name. Use plain text or a translation key that the toolbar's `t` resolves. The default is `id`. |
| `priority` | The collapse priority. A lower number leaves the bar first. |
| `pinned` | `true` keeps the group in the bar at every width. |
| `after` | The id of the group that this group follows. |
| `hidden` | Removes the group from the bar and the panel. |
| `overflowContent` | A function that returns the group's panel content. Use it when the panel needs a different form than the bar. |

### Placement

Host groups follow the built-in groups in order of appearance. They come before the contextual table controls. Set `after` to place a group after a built-in group or another host group. Several groups with the same `after` keep their order of appearance.

### Collapse order

Built-in groups have these priorities. The review group is pinned and never collapses.

| Group       | Priority |
| ----------- | -------- |
| `zoom`      | 10       |
| `script`    | 20       |
| `format`    | 30       |
| `list`      | 40       |
| `alignment` | 50       |
| `styles`    | 60       |
| `font`      | 70       |
| `text`      | 80       |
| `history`   | 90       |

A host group without a `priority` collapses before every built-in group. If two groups have the same priority, the group further along the bar collapses first. A `priority` on a built-in id changes that group's priority.

### Content in the panel

In the panel, each `Toolbar.Action` becomes a full-width row with its icon and `label`. A press runs the action and closes the panel. Other content renders as written. Pass `overflowContent` to render a different form, for example a list in place of a popover.

The panel stays inside the viewport with an 8 px margin. It lines up with the end of the **More** button, or with its start when the end does not fit, and it is never wider than the viewport less both margins.

Loose children of `Toolbar`, outside a group, keep their earlier behavior. They render in one block after the groups and never collapse.

### Replace a slot's content

`Toolbar.Slot` replaces one built-in slot with your own content. The content keeps the slot's place and collapses with the slot's group. In the panel, it renders under the slot's label, or as `overflowContent` when you pass it.

<FrameworkTabs>
<Framework value="react">

```tsx
<DocxEditor.Toolbar>
  <DocxEditor.Toolbar.Slot slot="zoom.level" overflowContent={() => <ZoomList />}>
    <ZoomPicker />
  </DocxEditor.Toolbar.Slot>
</DocxEditor.Toolbar>
```

</Framework>
<Framework value="vue">

```vue
<DocxEditorToolbar>
  <DocxEditorToolbar.Slot slot="zoom.level" :overflow-content="() => h(ZoomList)">
    <ZoomPicker />
  </DocxEditorToolbar.Slot>
</DocxEditorToolbar>
```

</Framework>
</FrameworkTabs>

### Development warnings

The toolbar renders a misplaced part and prints a development warning that names it. Production builds do not print these warnings.

- A `Toolbar.Group` whose `after` names no group goes to the end of the bar.
- A `Toolbar.Slot` for a slot that the preset arrangement does not draw is appended after the groups. An id that is not a `ChromeSlotId` gets the same treatment.

### Insert tables and add comments

`Toolbar.TableInsert` opens a 6×6 size grid, the same grid as **Insert** > **Table** in the menu bar. Arrow keys move in the grid, and a press inserts a table of that size.

`Toolbar.AddComment` starts a comment draft on the selection in the review rail. It needs the review module and a mounted review rail. It is disabled in viewing mode and when nothing is selected. `Toolbar.Comments` is a different control: it shows or hides the **Comments & Changes** pane.

### Menu bar overflow

The menu bar also stays on one line. When the menus do not fit, it moves them, from the end, into one `⋯` menu. Each moved menu becomes a submenu with the same rows. The bar keeps its keyboard behavior: the arrow keys move between the menus and the `⋯` menu, and `ArrowRight` opens a submenu.

The bar must be able to shrink for the measurement to work. In a flex row, give it `min-width: 0`. Set `overflow={false}` (`:overflow="false"` in Vue) to let the bar wrap onto more lines instead.

## Add root-level command buttons

Use `useEditorCommand()` to connect a custom button to command availability, active state, and execution:

<FrameworkTabs>
<Framework value="react">

```tsx
import { useEditorCommand } from '@docx-editor.dev/react';

function BoldButton() {
  const bold = useEditorCommand('text.bold');
  return (
    <button
      onMouseDown={(e) => e.preventDefault()} // chrome must not steal the caret
      onClick={() => bold.execute()}
      disabled={!bold.isEnabled}
      aria-pressed={bold.isActive}
      title={bold.disabledReason ?? 'Bold'}
    >
      Bold
    </button>
  );
}
```

</Framework>
<Framework value="vue">

```vue
<script setup lang="ts">
import { useEditorCommand } from '@docx-editor.dev/vue';

const bold = useEditorCommand('text.bold');
</script>

<template>
  <!-- chrome must not steal the caret -->
  <button
    @mousedown.prevent
    @click="bold.execute()"
    :disabled="!bold.isEnabled.value"
    :aria-pressed="bold.isActive.value"
    :title="bold.disabledReason.value ?? 'Bold'"
  >
    Bold
  </button>
</template>
```

`useEditorCommand` returns computed refs on a plain object, so read `isEnabled`, `isActive`, and `disabledReason` with `.value`.

</Framework>
</FrameworkTabs>

## Format painter

The `format.painter` slot copies formatting from the selection and applies it to another location. It leaves the text unchanged.

- Click the control once to arm it for a single application, then select the text to format.
- Double-click the control to keep it on for repeated applications, and press `Esc` to release it.
- Press `Ctrl+Alt+C` to copy the formatting and `Ctrl+Alt+V` to apply it. On macOS, use `Command` in place of `Ctrl`.

On macOS, browsers reserve `Command+Option+C` for their element inspector. Web pages cannot override that shortcut. Use the control or right-click menu to copy formatting. `Command+Option+V` applies formatting.

Some Windows and Linux keyboard layouts assign a character to `AltGr+C`, including Polish. On those layouts, `Ctrl+Alt+C` types that character. Use the control or right-click menu.

- Right-click the document and choose **Copy formatting** or **Paste formatting**.

The selection determines which formatting the painter copies. A selection inside one paragraph copies character formatting: font, size, color, and character marks. Including the paragraph mark also copies the paragraph style, alignment, spacing, and indents.

The painter copies resolved formatting, including fonts inherited from styles. It preserves the target paragraph borders (`w:pBdr`), run character style (`w:rStyle`), and run shading (`w:shd`).

To drive the painter from your own chrome, use the `copyFormatting` and `pasteFormatting` commands. `pasteFormatting` reports a disabled reason until something is copied.

## Table editing

When the caret or a rectangular cell selection is inside a table, the formatting toolbar shows contextual table controls:

- **Resize**: drag a column divider or the table's right edge to set Word-compatible twip widths. Inner dividers preserve total width. The right edge changes total width.
- **Insert rows/columns**: hover the row or column header band, then click `+`. You can also use the right-click menu.
- **Borders and fill**: select cells, then choose a border target, style, width, color, and cell fill. Clearing fill removes direct shading.

These controls target the innermost table under the pointer or selection. Merge and split operations are unsupported. Tables with merged cells refuse column resizing, insertion, and deletion with an explicit disabled reason.

The [Igloo demo](https://igloo.docx-editor.dev/) shows a custom toolbar order, custom icons, and two host actions. See the [Igloo example source](https://github.com/eigenpal/docx-editor/tree/main/examples/igloo).
