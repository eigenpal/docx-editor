The editor renders headers and footers at their authored positions and edits them in place. Users double-click the header or footer area to open it. Undo, redo, and save cover these edits.

## Edit a header or footer from code

The automation API returns each header or footer variant as a `Body` proxy:

```ts
await runtime.run(async (context) => {
  const section = context.document.sections.getFirst();
  await context.sync();
  const footer = section.getFooter('Primary');
  footer.load('text');
  await context.sync();
  footer.insertText('Internal document', 'End');
  await context.sync();
});
```

`getHeader(type)` and `getFooter(type)` accept `Primary`, `FirstPage`, or `EvenPages`. For story rules, see [Page layout and stories](/docs/2.x/editor-api/page-layout-and-stories#address-headers-and-footers).

## Insert page fields

Run `insertPageField` while a header or footer is open:

```ts
const result = editor.exec({ type: 'insertPageField', field: 'PAGE' });
if (!result.ok) console.warn(result.reason);
```

Outside a header or footer scope, the command returns `ok: false` with code `unsupported`.

| `field` | Shows | Chrome slot |
| --- | --- | --- |
| `PAGE` | The displayed page number. Honors `w:pgNumType` start and format. | `insert.pageNumber` |
| `NUMPAGES` | The document page count. | `insert.totalPages` |
| `SECTIONPAGES` | The page count of the current section. | `insert.sectionPages` |
| `PAGE_X_OF_Y` | `PAGE` and `NUMPAGES` together. | `insert.pageXofY` |

Page fields stay DOCX fields and update when the document reflows. The header **Options** menu offers the same insertions. For switch support, see [Fields and cross-references](/docs/2.x/guides/fields).

## Set a watermark

Run `setWatermark` to add or change a watermark. This example adds a diagonal text watermark:

```ts
const result = editor.exec({
  type: 'setWatermark',
  watermark: { text: 'CONFIDENTIAL', layout: 'diagonal', transparency: 0.5 },
});
if (!result.ok) console.warn(result.reason);
```

Each call is one undo step. A refused call writes nothing and returns a `reason` that names the option, for example `color must be RRGGBB`. Pass `watermark: null` to remove the watermark.

A watermark stacks with the other pictures behind the header text in the order the document sets.

| Option | Applies to | Default | Values |
| --- | --- | --- | --- |
| `text` | Text | none | One line, up to 256 characters. |
| `imageData` | Picture | none | PNG, JPEG, GIF, BMP, or WebP bytes. |
| `fontFamily` | Text | `Calibri` | A font family name. |
| `fontSizePt` | Text | Auto (`null`) | 1 to 1000 points. Auto fills the page. |
| `bold`, `italic` | Text | `false` | Boolean. |
| `color` | Text | `C0C0C0` | `RRGGBB`. |
| `transparency` | Text | `0.5` | 0 (opaque) to 1. |
| `layout` | Text | `diagonal` | `diagonal` or `horizontal`. |
| `scale` | Picture | Auto (`null`) | 0.01 to 10 times the natural size. Auto fits the page. |
| `washout` | Picture | `true` | Boolean. |

Set either `text` or `imageData`, never both. This example sets a picture watermark from a user file:

```ts
async function setPictureWatermark(file: File) {
  const imageData = new Uint8Array(await file.arrayBuffer());
  return editor.exec({ type: 'setWatermark', watermark: { imageData, washout: true } });
}
```

### Read the watermark

| API | Returns |
| --- | --- |
| `editor.getWatermark()` | The current watermark, or `null`. |
| `editor.query({ type: 'watermark' })` | The watermark, including picture bytes. |
| `useWatermark()` | The current watermark and an `apply` function. See [React hooks](/docs/2.x/react/hooks#usewatermark) and [Vue composables](/docs/2.x/vue/composables#usewatermark). |

## Customize header controls

Replace the **Watermark** popup through `popups.watermark`. This example changes the text presets:

```tsx
import { DocxEditor } from '@docx-editor.dev/react';

<DocxEditor
  popups={{
    watermark: (props) => (
      <DocxEditor.WatermarkDialog {...props} presets={['INTERNAL', 'CONFIDENTIAL', 'DRAFT']} />
    ),
  }}
/>;
```

Pass `preset={false}` to compose the parts yourself. `DocxEditor.WatermarkDialog.Preview` draws the caret's section page. For a custom preview, `watermarkShapeBox` returns the shape size in points:

```ts
import { watermarkShapeBox } from '@docx-editor.dev/core/editor';

// A Letter page with one-inch margins has a 468 by 648 point text area.
const box = watermarkShapeBox({ text: 'DRAFT' }, { width: 468, height: 648 });
```

The shape is centered on the text area. A diagonal shape turns 45 degrees counterclockwise. For popup composition, see [Customize popups](/docs/2.x/guides/customize-dialogs).

## Limits

- Editing a shared header or footer changes every page that uses that part.
- `w:titlePg` selects the `first` variant. `w:evenAndOddHeaders` alternates `default` and `even` variants.
- Sections without their own references inherit them from earlier sections.
- A page with no reference for its selected variant shows no header or footer.
- Blank pages added by odd-page or even-page section breaks have no header or footer.
- The automation API does not expose header and footer linkage or first-page layout toggles.
- One watermark applies document-wide. The command creates a default header when a section has none.
- Forms protection refuses `setWatermark` with `locked`.
- Text boxes in headers open on double-click. See [Edit text boxes](/docs/2.x/guides/images#edit-text-boxes).
- Legacy frames, continuous sections, and page-number switches follow [DOCX fidelity](/docs/2.x/docx-fidelity#page-layout-headers-and-footers).
