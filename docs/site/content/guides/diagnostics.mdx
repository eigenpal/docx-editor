The editor reports open, save, edit, review, font, and collaboration events as diagnostics. This page lists every stable failure code with its cause and action.

## Capture diagnostics

Register a module with an `onDiagnostic` listener when you create the editor:

```tsx
import { DocxEditor } from '@docx-editor.dev/react';
import { explainDiagnostic, type EditorDiagnostic, type EditorModule } from '@docx-editor.dev/core';

// Create the module once, outside the component. The editor reads modules only at creation.
const diagnostics: EditorModule = {
  id: 'diagnostics',
  onDiagnostic: (event: EditorDiagnostic) => {
    if (event.kind === 'edit.rejected') {
      console.warn(event.code, explainDiagnostic(event.code).hint);
    }
  },
};

const MODULES = [diagnostics];

export function Editor({ bytes }: { bytes: Uint8Array }) {
  return <DocxEditor document={bytes} modules={MODULES} />;
}
```

The module receives events from the initial document open. `editor.on('diagnostic', listener)` receives the same events, but only after the editor exists, so it misses the initial open. A listener that throws does not affect the editor.

## Handle a failure code

Branch on `code` in application logic. These helpers from `@docx-editor.dev/core` map codes to text:

| Function | Returns |
| --- | --- |
| `explainDiagnostic(code)` | The fixed `hint` for a code, and a `docs` link to its row on this page. |
| `diagnosticCodeOfRefusal(reason)` | The code for the local refusal message in `snapshot().lastRejection`. |
| `diagnosticCodes()` | Every public code. |
| `diagnosticCauses()` | Every internal `cause` value. |

In the editing API, a refusal has two codes. `error.code` says how the call failed. `error.debugInfo.innerError.code` names the rule from this page. Handle the inner code:

```ts
import { isDocxEditorError } from '@docx-editor.dev/editor-api';

try {
  await runtime.run(async (context) => {
    context.document.body.paragraphs.getFirst().insertText('Reviewed', 'End');
    await context.sync();
  });
} catch (error) {
  if (!isDocxEditorError(error)) throw error;
  const rule = error.debugInfo.innerError?.code;
  if (rule === 'edit.read-after-commit') {
    // The writes are applied. Read again; do not replay them.
  } else if (rule === 'edit.stale-target') {
    // Read the document again and reconsider the edit.
  } else {
    throw error;
  }
}
```

The outer code for one rule depends on when the runtime refused:

| Outer `error.code` | When |
| --- | --- |
| `InvalidArgument` | The runtime refused before it wrote anything, such as an unsupported field type or a protected insertion point. A string that is not well-formed XML also gives `edit.invalid-argument`. |
| `GeneralException` | The document refused the write itself, such as a tracked write into content-locked content with `edit.protected-content`. |
| `NotSupported`, `NotImplemented` | The input or operation is outside the supported subset, such as `insertOoxml()` with more than one equation and `edit.ooxml-unsupported`. |

Codes are stable. New codes can appear, but existing codes are never renamed. A tracking refusal never justifies switching tracking off automatically to make the edit succeed.

## Read diagnostic events

Switch on `kind` to narrow the event. Every event also has `schemaVersion`, `editorSessionId`, and `time`. The `editorSessionId` is random per editor instance and is not persisted.

| Kind | When | Fields |
| --- | --- | --- |
| `document.open` | A document opened or failed to open. | `outcome` (`opened` or `rejected`), `sizeBucket`. Opened: `durationMs`, `pagesBucket` (omitted by headless hosts), and `shape` buckets. Rejected: `code` and the [failure detail](#failure-detail). |
| `document.save` | A `save()` call returned or failed. | `outcome` (`saved` or `rejected`), `durationMs`. Saved: `sizeBucket`. Rejected: `code` and the failure detail. |
| `edit.rejected` | An edit, command, or tracked change was refused. | `code`, `origin` (`command`, `input`, or `automation`), `tracked`, `command` for a refused `exec` call, and the failure detail. |
| `review.skipped` | A decision on tracked changes, such as **Accept All**, skipped some changes. A refused card reports `edit.rejected` first. In the editing API, only a refused batch reports it (`count` 1); `resolve()` returns its skips. | `code`, `count`, and the failure detail. |
| `font.failed` | A font did not load; a substitute applies. | `code`. |
| `history` | An undo step did not group as intended. Informational. | `code`. |
| `custom-node` | A custom node payload could not be read. | `code`. The node name is not included. |
| `collab.status` | A collaboration session joined, disconnected, failed, or healed. | `status`, `previous`, `recovering`, and `code` when something is wrong. The first `ready` has `connectMs` when the editor observed the wait. |
| `collab.participants` | The number of people in the room changed. | `count`, including this editor. |
| `performance` | A timing summary after a minute, on page hide, or on close. | `windowMs`, optional `pagesBucket`, `interaction`, `layout`, and `paint`. Slow interactions add `code`. See [Measure performance](/docs/2.x/telemetry/performance). |
| `session` | An editor started, was used, or ended. | `phase` (`start`, `active`, or `end`). `active` and `end` add `durationMs`, `activeMs`, `inputEdits`, `commandEdits`, and `automationEdits`. See [Measure sessions, edits, and saves](/docs/2.x/telemetry/sessions). |

Sizes and counts use buckets, such as `4-8MiB` or `10-99`.

## Failure detail

Optional detail fields identify the engine condition and where it occurred. They use closed lists.

| Field | On | Holds |
| --- | --- | --- |
| `cause` | `document.open`, `document.save`, `edit.rejected`, `review.skipped` | The engine's own reason, such as `undeclared-prefix` under `open.xml-malformed`. For an unexpected error, `exception`. |
| `errorName` | `document.open`, `document.save`, `edit.rejected` | The exception class when `cause` is `exception`, such as `TypeError`. The message is never included. |
| `stage` | `document.open`, `document.save`, `edit.rejected` | Where an exception was caught: `open-mount`, `open-layout`, `command`, `review-item`, `automation`, or `save`. |
| `part` | `document.open`, `review.skipped` | The package part role, such as `main-document`, `header`, or `relationships`. Nonstandard names report `other`. |
| `operation` | `review.skipped` | `accept`, `reject`, or `reassign`. |
| `changeKind` | `review.skipped` | `insert`, `delete`, `replace`, `moveFrom`, `moveTo`, `format`, `paragraphMark`, or `structural`. |
| `formattingKind` | `review.skipped` | The property change, such as `rPrChange` or `tblGridChange`, or `other`. |

Use `code` for application logic. Use `cause` only to investigate, because causes can change between versions.

An open that throws reports `open.failed`, a save that throws reports `save.failed`, and a command, review card, or editing API batch that throws reports `edit.internal-invariant`. Each has `cause: 'exception'`, and the error still reaches your code. An exception from your own code inside `run()` is not reported.

This event shows a malformed header:

```json
{
  "kind": "document.open",
  "outcome": "rejected",
  "code": "open.xml-malformed",
  "cause": "undeclared-prefix",
  "part": "header",
  "sizeBucket": "64-128KiB"
}
```

When you report a problem, include the code, the failure detail, and the `engineVersion` that your telemetry adds.

## Codes

`explainDiagnostic(code).docs` links to each code's anchor, such as `#edit-read-only`.

### Open

Limits marked **server** accept a higher value for a trusted file through the `limits` option of `createServer`. The other limits are fixed security refusals.

| Code | Cause | Action |
| --- | --- | --- |
| <a id="open-unsupported-source" />`open.unsupported-source` | The input is not DOCX bytes. | Pass a `Uint8Array` or `ArrayBuffer` of a `.docx` file, or `'blank'`. |
| <a id="open-zip-corrupt" />`open.zip-corrupt` | Not a valid ZIP archive, or an entry is damaged. | Ask for a fresh copy. |
| <a id="open-zip-invalid-entry-name" />`open.zip-invalid-entry-name` | An entry path is unsafe, such as `..` or a leading `/`. | Refused for safety. |
| <a id="open-zip-entry-limit" />`open.zip-entry-limit` | Too many archive entries. | Server: `limits.zip.maxEntries`. |
| <a id="open-zip-size-limit" />`open.zip-size-limit` | The archive expands past the total size limit. | Server: `limits.zip.maxTotalBytes`. |
| <a id="open-zip-ratio-limit" />`open.zip-ratio-limit` | The expansion ratio looks like a decompression bomb. | Server: `limits.zip.maxRatio`. |
| <a id="open-xml-malformed" />`open.xml-malformed` | An XML part is not well formed. | Open and save the file in a desktop editor to repair it. |
| <a id="open-xml-dtd-forbidden" />`open.xml-dtd-forbidden` | An XML part declares a DTD or entity. | Refused to block XML entity attacks. |
| <a id="open-xml-part-size-limit" />`open.xml-part-size-limit` | One XML part exceeds the per-part size limit. | Server: `limits.xml.maxBytes`. |
| <a id="open-xml-depth-limit" />`open.xml-depth-limit` | An XML part nests too deep, often through nested tables. | Fixed limit. Flatten the nesting. |
| <a id="open-xml-element-limit" />`open.xml-element-limit` | An XML part has too many elements. | Server: `limits.xml.maxElements`. |
| <a id="open-invalid-limits" />`open.invalid-limits` | The `createServer` limits are not valid numbers. | Check the `limits` option. |
| <a id="open-content-types-invalid" />`open.content-types-invalid` | No valid `[Content_Types].xml` part. | Save the file again as `.docx`. |
| <a id="open-missing-main-document" />`open.missing-main-document` | No main document part, such as a renamed `.xlsx` or `.pptx`. | Use a `.docx` file. |
| <a id="open-relationships-invalid" />`open.relationships-invalid` | A relationship is invalid or duplicated. | Open and save the file in a desktop editor to repair it. |
| <a id="open-relationship-limit" />`open.relationship-limit` | Too many relationships. | Server: `limits.maxRelationships`. |
| <a id="open-part-limit" />`open.part-limit` | Too many XML parts. | Server: `limits.maxXmlParts`. |
| <a id="open-failed" />`open.failed` | No specific code applies. | Report it with the engine version. |

### Save

| Code | Cause | Action |
| --- | --- | --- |
| <a id="save-no-document" />`save.no-document` | `save()` ran before a document loaded, or after it failed to open. | Wait for the open, and check `document.open` for a refusal. |

### Review

| Code | Cause | Action |
| --- | --- | --- |
| <a id="review-revision-unsupported" />`review.revision-unsupported` | The change kind cannot be accepted or rejected, so it stays. A change with no `w:id` or author has cause `unaddressed`. | Keep it, or edit directly with tracking off. |
| <a id="review-incomplete-group" />`review.incomplete-group` | The decision would also resolve a change it leaves out. The `cause` names it, such as `paired-change`. | Clear the filter, decide that change first, or decide both. |
| <a id="review-retained-structure" />`review.retained-structure` | The row holds an untracked nested table (cause `nested-table`). | Use `resolve()` or **Accept All**; `acceptAll()` and `rejectAll()` refuse whole. |
| <a id="review-locked-content" />`review.locked-content` | A content control locks the content. | Set `ContentControl.cannotEdit` to false, then decide. |
| <a id="review-bound-content" />`review.bound-content` | The control is bound to a custom XML part. | Keep the change. The decision stays blocked while the binding exists, so remove the binding outside the editor first. |
| <a id="review-stale-revision" />`review.stale-revision` | The change no longer exists. | Read the review items again. |

## Protect diagnostic data

Engine diagnostics never contain document content. They use closed lists of codes, booleans, and bucketed numbers. Document text, part names, relationship targets, author names, font names, and exception messages are excluded.

Attributes that you add, raw errors, and data your SDK collects can still disclose content. Rare bucket combinations can also distinguish documents within an organization. For more information, see [Privacy review checklist](/docs/2.x/telemetry/privacy-review).
