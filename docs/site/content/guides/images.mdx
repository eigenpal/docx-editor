The editor displays inline and floating DrawingML pictures (`w:drawing` with `pic:pic`). React and Vue ship controls to insert pictures, change wrapping, resize, and edit alternative text. Saving preserves the picture markup and media.

## Insert an image

Check the bytes with `normalizeImageBytes`, then run `insertImage`. Import from `@docx-editor.dev/vue` in Vue.

```ts
import { normalizeImageBytes } from '@docx-editor.dev/react';

const result = normalizeImageBytes(bytes);
if (result.ok) {
  await editor.executeImageCommand({
    type: 'insertImage',
    data: result.bytes,
    mime: result.mime,
    widthPoints: result.widthPoints,
    heightPoints: result.heightPoints,
  });
}
```

`widthPoints` and `heightPoints` are maximums. An image that does not fit its cell, column, or page scales down proportionally. Read the committed size from `snapshot().image`.

| Format | Insert | Display |
| --- | --- | --- |
| PNG, JPEG, GIF | Yes | Yes |
| BMP, WebP, SVG | No | Yes, at the authored `wp:extent` |
| TIFF, EMF, WMF | No | Rasterized when conversion succeeds, otherwise a labeled placeholder |
| External `r:link` or `TargetMode="External"` | No | Placeholder; never loaded automatically |

- The editor refuses insertion while another picture is selected. Place the caret in text first. The toolbar shows this reason when it disables insertion.
- PDF export of EMF and WMF needs the drawing module. For more information, see [Advanced drawing rendering](/docs/2.x/pro/drawing).
- To use your own image decoder, pass an `ImageDecodePort` through the `imageDecodePort` prop on `DocxEditor` or the adapter's root component.

## Drop an image

Drag a PNG, JPEG, or GIF file onto text in either adapter. The drop caret shows the insertion position. The drop caret follows the pointer without changing your selection. Dropping inserts at that position, including inside table cells.

Open a header, footer, or note for editing before dropping into that region. Headers and footers accept drops only on the page where you opened them for editing. Page gaps, inactive regions, and protected content reject drops. Text boxes do not accept pointer drops.

Only the first image file enters the document. Text takes precedence when a transfer also contains a text preview image. File controls and paste remain available when dragging is unavailable.

Hold the pointer near the viewport edge to scroll while dragging. Scrolling stops when you move away or cancel. A short message explains blocked drops. The message distinguishes read-only documents, unsupported content, and positions outside editable text.

### Move an inline image

Use a mouse or pen to drag an inserted inline image onto editable text. You can also drag its selection frame. The drop caret shows the destination before you release the pointer. Each completed move is one undo step. Movement keeps the image data, dimensions, and alternative text.

Move images within the active editing region. Protected images and tracked editing modes refuse movement. Images inside hyperlinks or tracked-change wrappers do not support dragging. Press **Escape** to cancel. A document change during the drag cancels the move.

Inline charts and DrawingML diagrams move the same way. A chart with an alternate picture does not move.

### Resize and move a DrawingML diagram

Select a DrawingML diagram to resize it, drag it, change its wrapping, set alternative text, or delete it. Its content stays read-only, so crop, replace, rotate, and borders are unavailable.

A resize writes the new frame size and scales the saved diagram drawing to match. Shapes scale on each axis. Text follows the smaller axis and rounds to whole points. Other DOCX applications lay the diagram out again for the new frame, so their result can differ slightly. Each resize is one undo step and reaches collaboration peers.

### Handle custom drop data

Use the core editor from either adapter's `useDocxEditor` hook. In Vue, read its `.value`. Subscribe to `dragOver` and `drop` for your custom MIME type. Call the native event's `preventDefault()` synchronously to claim the event. The adapter then skips its default image insertion.

Read transfer data before any asynchronous work. Pass the exact `position` object to `insertImage.at` after obtaining the image bytes. The following example uses your application's `readAssetImage` function to retrieve an image from an asset identifier. Your application supplies `showDropError` to display a refusal or loading error.

```ts
import type { EditorPointPosition } from '@docx-editor.dev/core/editor';

const mime = 'application/x-document-asset';
const stopDrag = editor.on('dragOver', ({ event, position }) => {
  if (event.defaultPrevented || !position) return;
  if (event.dataTransfer?.types.includes(mime)) {
    event.preventDefault();
    event.dataTransfer.dropEffect = 'copy';
  }
});

const stopDrop = editor.on('drop', ({ event, position }) => {
  if (event.defaultPrevented) return;
  if (!position || !event.dataTransfer?.types.includes(mime)) return;
  event.preventDefault();
  const id = event.dataTransfer.getData(mime);
  void insertAsset(id, position).catch(showDropError);
});

async function insertAsset(id: string, position: EditorPointPosition) {
  const bytes = await readAssetImage(id);
  const image = normalizeImageBytes(bytes);
  if (!image.ok) {
    showDropError(image.reasonKey);
    return;
  }
  const result = await editor.executeImageCommand({
    type: 'insertImage',
    data: image.bytes,
    mime: image.mime,
    widthPoints: image.widthPoints,
    heightPoints: image.heightPoints,
    at: position,
  });
  if (!result.ok) showDropError(result.reason);
}

// Call this function when your host component unmounts.
function disposeAssetDrop() {
  stopDrag();
  stopDrop();
}
```

`editor.positionAtPoint(clientX, clientY)` resolves browser client coordinates through the current zoom and scroll position. It returns a position in the active editing region, or `null` for a miss. The returned object contains `part`, `paragraphId`, and the UTF-16 `offset`.

Positions retain the document revision that produced them. Keep the exact object; do not clone or serialize it. Image insertion refuses a stale position after document edits, reloads, or editing-region changes. Selection changes alone do not redirect the insertion. Report a refusal and ask the user to drop again.

These methods control the browser host. They do not extend the Office.js document automation model.

## Read and change an image

Read the selected image from the editor state. In Vue, `useEditorState` returns a `ShallowRef`.

```tsx
import { useEditorState } from '@docx-editor.dev/react';

const image = useEditorState((s) => s.image); // SelectedImageState | null
```

Outside a component, call `editor.getSelectedImage()` or read `editor.snapshot().image`. Both return the same `SelectedImageState`.

| Field | Meaning |
| --- | --- |
| `widthEmu`, `heightEmu` | Extent in EMUs |
| `crop` | Crop inset per edge, in percent (0 to 100) |
| `wrap` | Wrap target (see the next table) |
| `position`, `rotationDegrees`, `locks`, `hidden` | Placement and lock state |
| `title`, `description`, `hyperlink` | Alternative text and link |
| `resourceStatus` | `pending`, `ready`, `unrenderable`, `external`, or `missing` |
| `canResize`, `canMove` | False for locked or hidden drawings, rotated legacy VML text boxes, and viewing mode. `canMove` is also false for inline drawings. |
| `canChangeWrap`, `canCrop` | True for pictures only, never text boxes |

Check `canResize`, `canMove`, `canChangeWrap`, and `canCrop` before you offer the matching control.

| `wrap` value                          | OOXML                                             |
| ------------------------------------- | ------------------------------------------------- |
| `inline`                              | `wp:inline`                                       |
| `square`, `squareLeft`, `squareRight` | `wrapSquare` with `bothSides`, `left`, or `right` |
| `tight`, `through`                    | `wrapTight`, `wrapThrough`                        |
| `topAndBottom`                        | `wrapTopAndBottom`                                |
| `behind`, `inFront`                   | `wrapNone` with `@behindDoc` `1` or `0`           |

This example wraps text around the selected picture:

```ts
if (editor.can({ type: 'setImageWrapType', target: 'square' }).ok) {
  editor.exec({ type: 'setImageWrapType', target: 'square' });
}
```

| Command              | Effect                                                        |
| -------------------- | ------------------------------------------------------------- |
| `setImageWrapType`   | Changes the wrap target                                       |
| `setImagePosition`   | Moves a floating drawing, in EMUs                             |
| `setImageProperties` | Changes size, crop, alternative text, hyperlink, and border   |
| `transformImage`     | Rotates or flips: `rotateCW`, `rotateCCW`, `flipH`, `flipV`   |
| `replaceImage`       | Replaces the picture bytes through `executeImageCommand`      |
| `deleteImage`        | Deletes the picture                                           |
| `setShapeFill`       | Sets or removes the fill of a shape, text box, line, or group |
| `setShapeOutline`    | Sets the outline visibility, color, and width in points       |

`snapshot().image.shapeFormat` reads the selected shape's fill and outline, or `null` for a picture. Each shape command is one undo step. Each completed drag or resize gesture is one undo step. Alternative text reads `@descr`, then `@title`. A picture with neither is decorative.

## Format a shape

The **Format shape** pane sets the fill and outline of the selected shape, text box, line, or group. Open it with **Format shape** on the toolbar or in the context menu. A double-click on a text box still edits its text.

The pane lives in `DocxEditor.SidePanel`, which shows it while a shape is selected and shows the Chart pane while a chart is selected. Use `DocxEditor.ShapePane` to place the pane in your own layout. Vue uses `DocxEditorSidePanel` and `DocxEditorShapePane`.

- **Fill**: No fill, theme colors with tints and shades, standard colors, a hex color, and transparency in percent.
- **Outline**: No line, the same colors, a hex color, a width from 0.25 to 6 points or any typed width, and a dash type.

Each field is also a part that you can place in your own toolbar, popover, or drawer. For more information, see [Place shape and chart controls](/docs/2.x/guides/object-controls).

Each change is one undo step. A gradient, pattern, or picture fill shows by name; a picked color or No fill replaces it. A theme color saves as a theme reference with its tint or shade, so it follows a theme change. A hex color saves as RGB and never shows as a theme color.

In a group, the first press selects the group and a fill applies to every shape in it. A second press selects the shape under the pointer, and the pane then edits that shape alone. Press Escape to select the group again. A shape inside a group does not move, resize, or delete on its own, and it takes its wrap and alt text from the group. Only a pointer selects a shape inside a group; the keyboard selects the group. The selection is local to each editor in a collaboration session.

From code, pass a theme color as an object: `editor.exec({ type: 'setShapeFill', color: { theme: 'accent1', shift: 40 } })` sets Accent 1, Lighter 40%. A negative `shift` is darker.

To build your own pane, use `useSelectedShape`. Its `edit` method takes the same checked changes as the packaged pane:

```tsx
function OutlineButton() {
  const shape = useSelectedShape();
  return (
    <button
      disabled={!shape.canEditOutline}
      title={shape.outlineDisabledReason ?? undefined}
      onClick={() => shape.edit({ type: 'outlineWidth', text: '3' })}
    >
      3 pt outline
    </button>
  );
}
```

`shape.execute` runs `setShapeFill` or `setShapeOutline` on the shape that the hook shows. A refused change returns its reason; nothing is applied.

## Edit text boxes

Run `insertTextBox` with the caret in a body paragraph. The editor adds an empty rectangular box and places the caret in it.

```ts
if (editor.can({ type: 'insertTextBox' }).ok) {
  editor.exec({ type: 'insertTextBox' });
}
```

The toolbar slot is `insert.textBox`. Insertion in tables, headers, and footers is unavailable.

- Click a body text box to edit it. Drag the frame to move an anchored box, or drag its handles to resize. An inline box resizes but moves only with its line.
- Double-click a header or footer text box to open the header or footer with the caret in the box. Press **Escape** once to select the box and twice to close the header or footer.
- Pasting into a text box inserts plain text. Table insertion is unavailable inside a text box.
- Rotated or vertical text, and boxes that hold a table, take no caret. Clicking selects the box and its frame states the reason.
- Rotated legacy VML boxes, and boxes sized as a percentage of the page or margin, cannot move or resize.
- **Find** and `useDocumentSearch` search text boxes in the body, headers, and footers, not in notes.

## Custom unsupported-content components

Register a component to replace the placeholder for unsupported content, a drawing, or an equation. Match on the OOXML namespace and element name.

<FrameworkTabs>
<Framework value="react">

```tsx
<DocxEditor document={bytes}>
  <DocxEditor.UnsupportedElement
    match={(element) => element.namespaceUri === 'urn:my-widgets'}
    layout={{ width: 180, height: 48 }}
  >
    {({ element }) => <MyUnsupportedContent element={element} />}
  </DocxEditor.UnsupportedElement>
</DocxEditor>
```

</Framework>
<Framework value="vue">

```vue
<DocxEditor :document="bytes">
  <DocxEditor.UnsupportedElement
    :match="(element) => element.namespaceUri === 'urn:my-widgets'"
    :layout="{ width: 180, height: 48 }"
  >
    <template #default="{ element }">
      <MyUnsupportedContent :element="element" />
    </template>
  </DocxEditor.UnsupportedElement>
</DocxEditor>
```

</Framework>
</FrameworkTabs>

| Prop | Description |
| --- | --- |
| `match` | Selects elements. Omit it for a catch-all. The first mounted matching declaration wins. Prop updates keep its priority; a remounted declaration moves last. |
| `layout` | Width and height in points for opaque content: finite, positive, and at most 100,000. Defaults: 120 × 24 inline, 240 × 96 block. Drawing and equation placeholders keep their own size. |
| `includePartial` | Also matches partially rendered drawings. Default `false`. |

The `UnsupportedElement` record has these fields:

| Field | Description |
| --- | --- |
| `nodeId`, `ownerPartName` | Element identity and its document part. For `mc:AlternateContent`, `nodeId` is the drawing. |
| `namespaceUri`, `localName` | OOXML element name. For `mc:AlternateContent`, the wrapper, which is also `source`. |
| `source` | Read-only canonical source, not an XML string. Treat its values as untrusted. `null` when a standalone painter has no source lookup. |
| `placement` | `inline` or `block` |
| `label` | Text of the built-in placeholder |
| `drawing`, `equation` | Optional engine metadata, such as `support`, `drawingIssues`, `graphicKind`, and `drawing.chart` |
| `bounds` | Optional box after layout |

- To keep the built-in placeholder, return empty content from the render function or slot itself: `null`, `false`, an empty fragment, or whitespace. The editor does not try the next declaration.
- A returned component that later renders `null` still replaces the placeholder, with an empty box.
- Components can unmount when their page leaves the viewport. Keep durable state in your application.
- Custom components do not change the saved DOCX or PDF export.
- The component slot stops keyboard, clipboard, context-menu, and drop events from reaching the editor.
- Properties, metadata, and the internal content of a drawing, equation, or field are never separate replacement targets.
- To match chart and DrawingML diagram placeholders, see [Replace a placeholder](/docs/2.x/pro/drawing#replace-a-placeholder). That recipe works without the EigenPal Pro License.

### Replace a partially rendered drawing

Set `includePartial` to show your own preview for drawings that render without some features. Shapes with editable text, fully supported drawings, hidden drawings, and drawings without a layout position stay excluded.

```tsx
<DocxEditor document={bytes}>
  <DocxEditor.UnsupportedElement includePartial match={(element) => !!element.drawing}>
    {({ element }) => <DrawingPreview element={element} />}
  </DocxEditor.UnsupportedElement>
</DocxEditor>
```

In Vue, set `:include-partial="true"`. Size the preview to `element.bounds`. A click on the preview selects the drawing.

### Preview with your rendering service

Call `drawingPreviewDocx()` to create a DOCX that holds one drawing, including unsaved edits. Send it to your own renderer.

```ts
import { drawingPreviewDocx } from '@docx-editor.dev/core/editor';

const result = drawingPreviewDocx(editor, element);
if (result.ok) {
  // Send result.docx, result.pageFitsDrawing, and element.bounds to your renderer.
}
```

The editor never uploads documents or calls a rendering service. On a server, use `inspectDrawingSupport()` and `createDrawingPreviewPackage()` from `@docx-editor.dev/core/store`.

| Failure `reason`    | Cause                                 |
| ------------------- | ------------------------------------- |
| `drawing-not-found` | The drawing is not in the package     |
| `too-many-parts`    | More than 64 copied parts, by default |
| `too-large`         | More than 64 MiB, by default          |

- Use the `limits` argument to change the defaults. The preview excludes external relationships, embedded objects, macros, and templates.
- If `pageFitsDrawing` is `true`, use the first page. Otherwise crop from `(0, 0)` to `bounds.width * dpi / 72` by `bounds.height * dpi / 72`. Without `bounds`, trim the white space around the drawing.
- Run the renderer without network access and with time and memory limits. Treat the DOCX and returned images as untrusted.
- Show returned images through an image element. Never insert returned SVG or HTML strings into the page.
- Cache previews outside the component, for example in a `WeakMap` keyed by `element.source`. Cancel stale requests. Invalidate previews when your application changes related chart data, diagram data, or themes.
- `drawingPreviewDocx()` is synchronous. Call it in an effect or event handler, and queue large batches.
- `inspectDrawingSupport()` covers body, header, footer, footnote, and endnote drawings. If `report.complete` is `false`, the inventory is incomplete. It skips chart data, diagram data, inherited theme effects, and image bytes, so an empty issue list does not prove full support.
- Pass an inspection entry with the same package object to `createDrawingPreviewPackage()`. Node IDs do not persist in saved XML.

## Limits

- External images never load automatically. Open, layout, paint, and save make no network request. Only an explicit user action embeds an external target.
- Embedded image bytes pass signature checks and size limits before decoding. SVG paints in a static image mode: its scripts never run and its external references never load.
- Drawing hyperlinks (`a:hlinkClick`) need an explicit gesture and pass through `sanitizeHref`.
- With tracking on, image insertion and deletion record tracked changes. Property edits (size, position, wrap, crop, alt text, and links) apply directly, because they have no tracked form. Replacing a picture is refused.
- PDF export does not apply brightness, contrast, grayscale, or black-and-white adjustments.
- Picture commands do not address members of a shape group.
- Copy and cut refuse selections that contain a chart or an embedded object.
- Charts, DrawingML diagrams without a saved drawing, and drawing effects need the drawing module. Core renders saved diagram drawings. For the module, see [Advanced drawing rendering](/docs/2.x/pro/drawing).
- Wrap geometry, VML previews, shape groups, and alternative content follow the rules in [DOCX feature support](/docs/2.x/docx-fidelity).
