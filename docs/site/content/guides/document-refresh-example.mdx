This example opens a DOCX file and requests a replacement from a mock server. You keep the same editor instance throughout the update. You can preserve scroll or move to the changed paragraph before its highlight fades in and out.

The editor does not watch a file path or URL. Your application receives updated bytes and passes them to `refresh.apply()`. This example uses a button and HTTP. You can use polling or server notifications to trigger the same flow.

## Create the app

1. Create a Vite React project:

   ```bash
   npm create vite@latest docx-refresh-demo -- --template react-ts
   cd docx-refresh-demo
   npm install
   npm install @docx-editor.dev/react @docx-editor.dev/core
   npm install --save-dev fflate
   ```

2. Replace `vite.config.ts`, `src/main.tsx`, and `index.html` with the files in this guide.
3. Start the development server:

   ```bash
   npm run dev
   ```

4. Open the local address that Vite prints.

## Add the mock server

The mock generates two versions of a sample document. Its response includes the complete replacement DOCX and the exact changed text location. A 1.5-second delay gives you time to edit during processing.

This mock returns a fixed sample; it does not process uploaded documents. It replaces any edits made before capture. Use **Reset sample** before each test. Use your document processor to edit `submission.bytes` in a real application. Keep authentication and document ownership checks in your backend.

Replace `vite.config.ts` with this development server configuration:

```ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { strToU8, zipSync } from 'fflate';

// Generate controlled fixtures. This is not a general DOCX processor.
function sampleDocx(updated: boolean) {
  const w = 'http://schemas.openxmlformats.org/wordprocessingml/2006/main';
  const ct = 'http://schemas.openxmlformats.org/package/2006/content-types';
  const rel = 'http://schemas.openxmlformats.org/package/2006/relationships';
  const office = 'http://schemas.openxmlformats.org/officeDocument/2006';
  const paragraphs = Array.from({ length: 40 }, (_, index) => {
    const text =
      updated && index === 20
        ? 'Delivery date: October 12.'
        : `Section ${index + 1}: Project schedule.`;
    return `<w:p><w:pPr><w:spacing w:after="480"/></w:pPr>
      <w:r><w:t>${text}</w:t></w:r></w:p>`;
  }).join('');
  return zipSync({
    '[Content_Types].xml': strToU8(`<Types xmlns="${ct}">
      <Default Extension="rels"
        ContentType="application/vnd.openxmlformats-package.relationships+xml"/>
      <Override PartName="/word/document.xml"
        ContentType="application/vnd.openxmlformats-officedocument.wordprocessingml.document.main+xml"/>
      </Types>`),
    '_rels/.rels': strToU8(`<Relationships xmlns="${rel}">
      <Relationship Id="rId1" Type="${office}/relationships/officeDocument"
        Target="word/document.xml"/></Relationships>`),
    'word/document.xml': strToU8(`<w:document xmlns:w="${w}"><w:body>
      ${paragraphs}<w:sectPr><w:pgSz w:w="12240" w:h="15840"/>
      <w:pgMar w:top="1440" w:bottom="1440" w:left="1440" w:right="1440"/>
      </w:sectPr></w:body></w:document>`),
  });
}

export default defineConfig({
  plugins: [
    react(),
    {
      name: 'mock-document-server',
      configureServer(server) {
        server.middlewares.use(async (req, res, next) => {
          if (req.url === '/api/document' && req.method === 'GET') {
            res.setHeader('Content-Type', 'application/octet-stream');
            res.end(sampleDocx(false));
            return;
          }
          if (req.url !== '/api/update' || req.method !== 'POST') {
            next();
            return;
          }
          const submissionId = req.headers['x-submission-id'];
          if (typeof submissionId !== 'string' || !submissionId) {
            res.statusCode = 400;
            res.end('Missing submission ID');
            return;
          }
          // Simulate a server job. No uploaded document enters this mock.
          await new Promise((resolve) => setTimeout(resolve, 1500));
          if (res.destroyed) return;
          res.setHeader('Content-Type', 'application/json');
          res.end(
            JSON.stringify({
              documentId: 'schedule',
              submissionId,
              sequence: 1,
              bytes: Buffer.from(sampleDocx(true)).toString('base64'),
              changes: [
                {
                  id: 'delivery-date',
                  location: {
                    paragraphIndex: 20,
                    start: 15,
                    end: 25,
                    text: 'October 12',
                  },
                },
              ],
            })
          );
        });
      },
    },
  ],
  server: { host: '127.0.0.1' },
});
```

## Connect the editor

The `document` prop opens the initial file. Keep that prop stable during server updates and use `refresh.apply()` for each result. `capture()` connects the submitted document revision to its response. Keep the returned submission object in the browser.

The example verifies document and submission IDs before applying a result. It also aborts the request and cancels processing when the controls unmount.

Replace `src/main.tsx` with this client:

```tsx
import { useEffect, useRef, useState } from 'react';
import { createRoot } from 'react-dom/client';
import {
  DocxEditor,
  DocumentRefreshError,
  createDocumentRefresh,
  useDocxEditor,
  type RefreshChangeInput,
  type RefreshSubmission,
} from '@docx-editor.dev/react';
import '@docx-editor.dev/core/styles/editor.css';

interface ServerUpdate {
  documentId: string;
  submissionId: string;
  sequence: number;
  bytes: string;
  changes: RefreshChangeInput[];
}

function UpdateControls() {
  const editor = useDocxEditor();
  return editor ? <ReadyControls editor={editor} /> : null;
}

function ReadyControls({ editor }: { editor: NonNullable<ReturnType<typeof useDocxEditor>> }) {
  const refresh = createDocumentRefresh(editor);
  const request = useRef<AbortController | null>(null);
  const [busy, setBusy] = useState(false);
  const [done, setDone] = useState(false);
  const [scrollToChange, setScrollToChange] = useState(false);
  const [message, setMessage] = useState('Scroll, then request an update.');

  useEffect(
    () => () => {
      request.current?.abort();
      refresh.cancel();
    },
    [refresh]
  );

  async function update() {
    if (request.current) return;
    const controller = new AbortController();
    request.current = controller;
    setBusy(true);
    let submission: RefreshSubmission | undefined;
    try {
      submission = await refresh.capture();
      if (controller.signal.aborted) return;
      setMessage('Server processing. You can still edit the document.');
      const response = await fetch('/api/update', {
        method: 'POST',
        headers: { 'X-Submission-Id': submission.id },
        signal: controller.signal,
        // A real processor can receive body: submission.bytes.
      });
      if (!response.ok) throw new Error('The server request failed.');
      const output: ServerUpdate = await response.json();
      if (output.documentId !== 'schedule' || output.submissionId !== submission.id) {
        throw new Error('The response belongs to another document or job.');
      }
      if (controller.signal.aborted) return;
      const result = await refresh.apply({
        submission,
        sequence: output.sequence,
        bytes: Uint8Array.from(atob(output.bytes), (c) => c.charCodeAt(0)),
        changes: output.changes,
      });
      if (!result.ok) {
        setMessage(
          result.code === 'local-edits'
            ? 'Update refused: your local edits stay in the editor.'
            : `Update refused: ${result.code}.`
        );
        return;
      }
      const change = result.changes.find((c) => c.status === 'available');
      const moved =
        scrollToChange && change && refresh.navigateToChange(change.id, { behavior: 'instant' });
      // Keep the default blue fill, padding, and rounded corners.
      refresh.highlightChanges({
        timeoutMs: 3000,
        animation: { durationMs: 180, exitDurationMs: 300 },
      });
      setDone(true);
      setMessage(
        moved
          ? 'Document updated. Scrolled to the changed paragraph.'
          : 'Document updated. Scroll position preserved.'
      );
    } catch (error) {
      if (!controller.signal.aborted) {
        setMessage(
          error instanceof DocumentRefreshError
            ? `Cannot capture the document: ${error.code}.`
            : error instanceof Error
              ? error.message
              : 'Update failed.'
        );
      }
    } finally {
      if (submission) refresh.finish(submission);
      if (request.current === controller) {
        request.current = null;
        setBusy(false);
      }
    }
  }

  return (
    <section style={{ padding: 16 }}>
      <h1 style={{ margin: '0 0 8px' }}>DOCX refresh example</h1>
      <p>The mock replaces this sample. Reload the page to reset it.</p>
      <label>
        <input
          type="checkbox"
          checked={scrollToChange}
          disabled={busy || done}
          onChange={(event) => setScrollToChange(event.target.checked)}
        />
        Scroll to the change after the update
      </label>{' '}
      <button disabled={busy || done} onClick={update}>
        {busy ? 'Updating…' : 'Request server update'}
      </button>{' '}
      <button disabled={busy} onClick={() => location.reload()}>
        Reset sample
      </button>
      <p role="status">{message}</p>
    </section>
  );
}

function App() {
  const [bytes, setBytes] = useState<ArrayBuffer | null>(null);
  const [error, setError] = useState('');
  useEffect(() => {
    const controller = new AbortController();
    async function load() {
      try {
        const response = await fetch('/api/document', {
          signal: controller.signal,
        });
        if (!response.ok) throw new Error('Cannot open the sample.');
        const document = await response.arrayBuffer();
        if (!controller.signal.aborted) setBytes(document);
      } catch {
        if (!controller.signal.aborted) setError('Cannot open the sample.');
      }
    }
    void load();
    return () => controller.abort();
  }, []);
  if (!bytes) return <p role="status">{error || 'Loading document…'}</p>;
  return (
    <div
      className="docx-editor"
      style={{
        height: '100vh',
        display: 'flex',
        flexDirection: 'column',
      }}
    >
      <DocxEditor.Root document={bytes} mode="edit">
        <UpdateControls />
        <DocxEditor.Toolbar />
        <DocxEditor.Viewport style={{ flex: 1, minHeight: 0 }}>
          <DocxEditor.Content />
        </DocxEditor.Viewport>
      </DocxEditor.Root>
    </div>
  );
}

createRoot(document.getElementById('root')!).render(<App />);
```

## Test the behavior

1. Scroll to another position and select **Request server update**. The document changes without moving your scroll position.
2. Select **Reset sample** and enable **Scroll to the change after the update**. Request another update. The editor centers paragraph 21, fades its highlight in, and dismisses it after three seconds.
3. Reset the sample and request an update. While the server processes it, type in the document. The editor refuses the response with `local-edits` and keeps your edit.

The highlight uses the default blue fill, rounded corners, padding, and no border. The example sets separate entrance and exit durations. For appearance options, see [Highlight and navigate](/docs/2.x/guides/document-refresh#highlight-and-navigate).

The mock reports a range within body paragraph 21 using `paragraphIndex: 20`. Its offsets select `October 12` in the returned paragraph. The editor validates this location before showing a highlight. A replacement DOCX alone does not identify changes.

An accepted replacement resets selection and undo history. The editor accepts unrelated content when submission and revision checks pass. Your application must verify document identity before applying results. For recovery and failure handling, see [Refresh from server updates](/docs/2.x/guides/document-refresh).

## Connect your processor

Replace the mock endpoint with your backend and send `submission.bytes` in the request body. Return the complete updated DOCX, its document and submission IDs, and a processor-assigned sequence number. Return change locations when you want highlights or navigation.

For multiple results, capture once and apply each cumulative result with the same submission object. Call `finish(submission)` only after the processor completes. The controller rejects stale results and results that conflict with local edits. Do not retry those results automatically.

Use instant navigation when the highlight must start after the target becomes visible. Smooth navigation starts scrolling but does not wait for scrolling to finish. For multiple results, see [Receive cumulative updates](/docs/2.x/guides/document-refresh#receive-cumulative-updates).
