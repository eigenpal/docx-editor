## Status

`@docx-editor.dev/vue` targets Vue 3 and ships in the same fixed version group as the React package.

## Install

```bash
npm install @docx-editor.dev/vue
```

Pulls in `@docx-editor.dev/core` and `@docx-editor.dev/i18n`.

## Quickstart

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { DocxEditor } from '@docx-editor.dev/vue';

const doc = ref<Uint8Array>();
</script>

<template>
  <DocxEditor :document="doc" />
</template>
```

## Using with Nuxt

For Nuxt 3 and 4, install [`@docx-editor.dev/nuxt`](/docs/1.x/vue/nuxt), the official Nuxt module. It wraps this adapter and auto-imports an SSR-safe `<DocxEditor>`, so there's no `<ClientOnly>` wrapper to write:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@docx-editor.dev/nuxt'],
});
```

See [Nuxt](/docs/1.x/vue/nuxt) for the module options and what to import from the adapter directly.

## Root surface

- `DocxEditor`: the packaged Vue host component
- `DocxEditorShell`, `DocxEditorTitleBar`, `DocxEditorToolbar`, `DocxEditorSidebar`: root-level chrome components
- `HorizontalRuler`, `VerticalRuler`, `PageIndicator`: shared chrome pieces exported from the package root
- the shared font helpers and command utilities are also exported from the root package

There are no separate `/ui`, `/composables`, `/dialogs`, or `/plugin-api` package exports in v2.

## Parity with React

`scripts/parity/parity.contract.json` lists every public prop and ref member shipped under either adapter. CI parses both packages' API snapshots and fails when the contract changes without an update.

## Automating the document

`@docx-editor.dev/editor-api` drives a document through an object model. In Vue, the stable path today is the server entry over DOCX bytes:

```ts
import { DocxEditor } from '@docx-editor.dev/editor-api';

const runtime = await DocxEditor.createServer(bytes, { author: 'Assistant' });
const text = await runtime.run(async (context) => {
  const body = context.document.body;
  body.load('text');
  await context.sync();
  return body.text;
});
runtime.dispose();
```

Save the result with `runtime.save()` and hand the bytes back to the editor with `ref.load(...)`. The object model and its rules are in [DocxEditor API](/docs/1.x/editor-api).
