## Status

`@docx-editor.dev/vue` targets Vue 3 and is released in the same fixed version group as the React package. It keeps the same component name, subpath layout, and plugin contract where Vue supports the same surface. Remaining gaps are tracked in the parity contract below.

## Install

```bash
npm install @docx-editor.dev/vue
```

Pulls in `@docx-editor.dev/core` and `@docx-editor.dev/i18n`.

## Quickstart

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { DocxEditor } from '@docx-editor.dev/vue';
import '@docx-editor.dev/vue/styles.css';

const buf = ref<ArrayBuffer | null>(null);
</script>

<template>
  <DocxEditor :document-buffer="buf" />
</template>
```

## Using with Nuxt

For Nuxt 3 and 4, install [`@docx-editor.dev/nuxt`](/docs/1.x/vue/nuxt), the official Nuxt module. It wraps this adapter and auto-imports an SSR-safe `<DocxEditor>`, so there's no `<ClientOnly>` wrapper to write:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@docx-editor.dev/nuxt'],
});
```

See [Nuxt](/docs/1.x/vue/nuxt) for the module options and what to import from the adapter directly.

## Subpaths

- `@docx-editor.dev/vue`: `<DocxEditor>`, `DocxEditorProps`, `DocxEditorRef`, `EditorMode`, `renderAsync`, `i18nPlugin`, `provideLocale`
- `@docx-editor.dev/vue/ui`: `Toolbar`, `EditorToolbar`, `ResponsiveToolbar`, `TableToolbar`, `MenuBar`, `TitleBar`, `ColorPicker`, `FontPicker`, `StylePicker`, and the dialog components (find/replace, hyperlink, page setup, table properties, and more)
- `@docx-editor.dev/vue/composables`: Vue equivalents of the React hooks (`useDocxEditor`, `useHistory`, `useAutoSave`, `useTrackedChanges`, `useFindReplace`, etc.)
- `@docx-editor.dev/vue/dialogs`: hyperlink, find/replace, paste special, page setup
- `@docx-editor.dev/vue/plugin-api`: plugin host
- `@docx-editor.dev/vue/styles`: CSS

Every export is in the [Vue API reference](/docs/1.x/api/vue).

## Parity with React

`scripts/parity/parity.contract.json` lists every public prop and ref member shipped under either adapter, grouped as paired, deferred-in-Vue, or adapter-specific. CI parses both packages' API snapshots and fails when the contract changes without an update. Deferred-in-Vue items today include the controlled `comments` prop, `onSave`/`onFontsLoaded`/clipboard callbacks, and the plugin overlay surface. Items in the paired bucket are expected to behave the same in both adapters.

## Automating the document

`@docx-editor.dev/agents` drives a document through an object model. Its `/browser` entry needs the engine's editor instance, and the Vue adapter's ref does not expose one yet — `getEditor()` answers the `Editor` facade, which is not the same object. Until the Vue provider surface lands, automate from the server entry over DOCX bytes:

```ts
import { DocxEditor } from '@docx-editor.dev/agents';

const runtime = await DocxEditor.createServer(bytes, { author: 'Assistant' });
const text = await runtime.run(async (context) => {
  const body = context.document.body;
  body.load('text');
  await context.sync();
  return body.text;
});
runtime.dispose();
```

Save the result with `runtime.save()` and hand the bytes back to the editor with `ref.load(...)`. The object model and its rules are in [Automation](/docs/1.x/agents).
