Pass a card class through `card`. Compose `Author`, `Summary`, `Accept`, `Reject`, `Replies`, and `Reply` parts.

Use `List` for custom cards. Its React callback or Vue `#item` slot supplies each review item. `useReviewItem()` reads the surrounding card item.

Use `useReviewAuthor()` for the resolved author color and avatar. To choose between initials badges and the comment icon on collapsed markers, set the `commentMarkers` review pane setting. Use `Markers` with an `icon` function for marker icons of your own. Keep rejected writes visible to the user.

To list comments only and open each tracked change in a balloon at its text, set `revisionsIn: 'balloons'` instead of a filter. A comments-only `filter` hides revision cards and gives no other route to revision decisions. For more information, see [Customize your review display](/docs/2.x/customization/review-display).

## Style card parts

Add a selector under your editor wrapper. Use the resolved author token for the leading border.

```css
.docx-editor.contract-workspace .contract-card {
  border-radius: 12px;
  border-inline-start: 3px solid var(--doc-review-author-current);
  background: var(--doc-surface);
  box-shadow: 0 3px 14px var(--doc-border);
}
.docx-editor.contract-workspace .contract-card[data-active] {
  background: var(--doc-review-card-active-bg);
}
```

Use `card.className` for every card. Root `className` styles the review column. Custom card arrangements must retain reply, resolve, accept, and reject actions that your workflow needs.

## Choose a comment box style

The live example offers rounded, square, author accent, and quiet thread styles. Use `data-kind="comment"` to style comment boxes separately from tracked change cards. Use `data-active` for the selected card and `data-resolved` for resolved comments.

The following styles add an author accent and a quiet reply area. They apply to both framework examples.

```css
.docx-editor.contract-workspace .contract-card[data-kind='comment'] {
  border-inline-start: 3px solid var(--doc-review-author-current);
  background: color-mix(in srgb, var(--doc-review-author-current) 5%, var(--doc-surface));
}
.docx-editor.contract-workspace .contract-comment-body {
  font-size: 13px;
  line-height: 1.6;
}
.docx-editor.contract-workspace .contract-thread {
  margin-block-start: 12px;
  border-inline-start: 1px solid var(--doc-border);
  padding-inline-start: 12px;
}
.docx-editor.contract-workspace .contract-reply {
  border-radius: 8px;
  background: var(--doc-bg);
}
```

For a quiet thread style, remove the card shadow and use a one-pixel border. Keep author names, dates, and action labels visible. Do not use author color as the only way to identify a reviewer.

Named parts replace their packaged counterparts in place. The examples retain packaged resolve, reopen, delete, and reply actions. Use `hidden` on a named part only when your workflow provides another action. Styling changes do not change document comments or shared review data.
