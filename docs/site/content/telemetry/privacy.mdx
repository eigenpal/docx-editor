<Callout>`@docx-editor.dev/telemetry` is available in version 2.29.0 and later.</Callout>

This page is for teams that must show, in a privacy or security review, what their editor telemetry sends. It lists every field the editor can send and the rules that keep personal data and document content out. For the settings in your own app and SDKs that you need to check, see [Privacy review checklist](/docs/2.x/telemetry/privacy-review).

## Summary

- The package never sends data by itself. It sends only to the exporters that you configure, and only to your own backends.
- Diagnostics and metrics contain no document content and no personal data. Document text, file names, part names, relationship targets, author names, comment text, font names, element names from the file, and exception messages are never included.
- Every value is a code from a closed list, a boolean, a bucketed size or count, or a timing in milliseconds.
- Two independent checks enforce this: one where the engine builds the event, and one in the telemetry package before any exporter receives it.
- Values that you add yourself, such as a room or user identifier, are your responsibility. So are the other things that your Sentry and OpenTelemetry SDKs collect.

## How it is enforced

The engine builds each diagnostic from closed lists when the event is made. It never copies a string from the document into an event: a part name becomes a role such as `header`, an exception becomes its class such as `TypeError`, and a count becomes a bucket such as `10-99`. An internal refusal message, which can describe the document, is mapped to a public code, and the message itself stays in the engine.

The telemetry package checks every event again before an exporter receives it. A string field that is not in its allowed list is removed. An event with an unknown kind or code is dropped completely, and the `docx_editor_telemetry_dropped_events_total` metric counts it. This second check protects you when the engine and the telemetry package come from different versions.

The test suites verify both checks with files that contain planted text, part names, and author names. Each test serializes every event and error message and fails if a planted string appears.

## What each event contains

Every event has `kind`, `schemaVersion`, `editorSessionId`, and `time`, and the telemetry package adds `engineVersion`. The `editorSessionId` value is random for each editor instance and is never stored, so it identifies no person and no document. If you send it together with your own user identifier, it becomes linkable to that user.

| Event | Fields | Values |
| --- | --- | --- |
| `document.open`, opened | `sizeBucket`, `pagesBucket`, `durationMs`, and `shape` if you allow it | Size in 15 power-of-two buckets, such as `1-2MiB`. Pages in 6 buckets: `0`, `1`, `2-9`, `10-99`, `100-999`, `1000+`. Duration in milliseconds. |
| `document.open`, rejected | `code`, `sizeBucket`, `cause`, `part`, `errorName`, `stage` | A public code, the engine's reason token, the role of the failed part, and for an exception its class and where it was caught. |
| `edit.rejected` | `code`, `origin`, `tracked`, `command`, `cause`, `errorName`, `stage` | A public code; `command`, `input`, or `automation`; a boolean; a built-in command name such as `insertTable`. A custom command name is never sent. |
| `review.skipped` | `code`, `count`, `operation`, `changeKind`, `formattingKind`, `part`, `cause` | `accept`, `reject`, or `reassign`; the kind of tracked change; a known property-change element or `other`. The author and the change are never sent. |
| `font.failed` | `code` | A code. The font family name is never sent. |
| `history`, `custom-node` | `code` | A code. A custom node's name and data are never sent. |
| `collab.status` | `status`, `previous`, `code`, `recovering`, `connectMs` | Session states, a failure code, a boolean, milliseconds. The room name is never sent. |
| `collab.participants` | `count` | The number of people in the room. Names are never sent. |
| `performance` | `interaction`, `layout`, `paint`, `windowMs`, `pagesBucket`, `code` | Timing summaries in milliseconds and band counts. No key, character, or position is recorded. |

Every closed list is part of the public API. To read them in code, call `diagnosticCodes()` and `diagnosticCauses()` from `@docx-editor.dev/core`. For what each field means, see [Diagnostics](/docs/2.x/guides/diagnostics).

### Document shape

By default, an opened document reports only `sizeBucket` and `pagesBucket`. With `documentShape: 'detailed'`, it also reports four buckets: XML parts, paragraphs, tracked changes and comments, and embedded fonts. There is no option that sends exact counts.

One bucket says little about a document. Several buckets together form a combination, and a rare combination can stand out inside one organization. For this reason the detailed shape is off by default. Turn it on only if you need to group open times by document structure.

### Metrics

Metrics carry the same codes and buckets as labels. A metric label accepts only short identifier values, matching `[A-Za-z0-9_.:+-]{0,64}`; any other value becomes `other`. Each label you add with `metricLabels` keeps at most 50 distinct values, and later values become `other`. For every metric and label, see [Metrics](/docs/2.x/telemetry/metrics).

## Collaboration servers

- Metrics never carry a room name.
- `rooms.list()` labels each room with an index that is valid only in the current process, such as `room-3`. To get a stable label that does not reveal the name, pass `roomLabel: hmacRoomLabel(secret)`. Show real names only on an endpoint that only administrators can reach.
- `perRoomSeries: true` accepts only the default label or `hmacRoomLabel`, so a room name cannot become a metric label.
- Refusal reasons from your hooks become a known reason or `other`. The error message is never recorded.

For more information, see [Rooms, people, and memory](/docs/2.x/telemetry/rooms).
