<Callout>`@docx-editor.dev/telemetry` is available in version 2.29.0 and later.</Callout>

The editor sends only codes, booleans, buckets, and timings, as described in [Privacy](/docs/2.x/telemetry/privacy). This page covers what you control: the identifiers you add, consent, and the SDKs that send the data. Go through each section, then complete the checklist.

## Your own identifiers

`attributes`, `resource`, and `metricLabels` send exactly what you give them. Event attributes accept any string up to 256 characters, so the package cannot tell a pseudonymous identifier from an email address.

- Send pseudonymous identifiers that your backend issues, such as an internal user number or a random room token. Never send names, email addresses, document titles, matter numbers, or file names.
- Add a key to `metricLabels` only if it has few values, such as an environment or an app version. A user or room identifier as a metric label creates one series per user or room.

The following example sends an app version and a pseudonymous tenant identifier, and labels metrics by the version only:

```ts
import { createTelemetry } from '@docx-editor.dev/telemetry';
import { otelExporter } from '@docx-editor.dev/telemetry/otel';

export const telemetry = createTelemetry({
  exporters: [otelExporter()],
  attributes: { 'app.version': '4.2.0', 'tenant.id': 't_8f3a' },
  metricLabels: ['app.version'],
});
```

## Consent

Pass `consent` when your app asks for consent. The editor reads it before each event and metric, and records nothing while it returns `false`. Events from that time are dropped, not buffered. To follow Global Privacy Control, Do Not Track, and your own opt-out key, use `consent: browserPrivacySignals({ optOutKey })`, alone or combined with your consent manager.

`consent` controls only what this package records. Your OpenTelemetry SDK still exports the metrics it recorded before, and your Sentry and OpenTelemetry SDKs have their own consent settings. Apply your consent decision to them as well.

## Sentry

The Sentry SDK collects more than your diagnostics. Check each of these settings:

- **Session Replay** records the page, and the page shows the document. Block the editor with `EDITOR_SELECTORS`, or turn Replay off on pages with the editor.
- **Click and key breadcrumbs** describe the element that was clicked, and inside the editor its `alt`, `title`, and `aria-label` values come from the document. Remove them with `dropEditorBreadcrumbs`.
- **Page URLs** are attached to every event and to navigation and fetch breadcrumbs. If your URLs contain a document, matter, or client identifier, remove it in `beforeSend` and `beforeBreadcrumb`.
- **IP addresses and user data** are sent when `sendDefaultPii` is `true`. Keep it `false`.
- **Console breadcrumbs** record what your own code logs. Drop the `console` category if your code logs document details.
- **Request bodies** on a server can be attached to an issue. If an endpoint receives document bytes or agent instructions, remove `event.request.data` in `beforeSend`.
- **Uncaught errors** that your global error handler captures carry the JavaScript error message and stack trace. These come from the runtime, not from the document, but the package does not control them.

For a configuration that applies these settings, see [Keep document content out of Sentry](/docs/2.x/telemetry/sentry#keep-document-content-out-of-sentry).

## OpenTelemetry

Your OpenTelemetry SDK adds resource attributes to every metric and span, such as `service.name`. Some instrumentations also add the browser's user agent or page URL. Check the resource and the instrumentations that you register, and keep identifiers out of them.

## Verify it yourself

You can check what the editor sends in your own test suite. Collect every event with `memoryExporter`, open, edit, and review a file that contains text you can recognize, and check that the text never appears in the events:

```ts
import { createTelemetry, memoryExporter } from '@docx-editor.dev/telemetry';

export const memory = memoryExporter();
export const telemetry = createTelemetry({ exporters: [memory] });

/** Throws if any recorded event contains `text`. Call it after your test edits the file. */
export function assertNoDocumentText(text: string): void {
  if (JSON.stringify(memory.events).includes(text))
    throw new Error('A telemetry event contains document text.');
}
```

During development, `consoleExporter()` prints each event as it would be sent.

## Review checklist

- [ ] Exporters send only to backends that your organization controls or has approved.
- [ ] `attributes` and `resource` contain only pseudonymous identifiers.
- [ ] `metricLabels` lists only keys with few values.
- [ ] `documentShape` is left at `'basic'`, or the detailed shape is approved.
- [ ] `consent` reads your consent manager, and your Sentry and OpenTelemetry SDKs follow the same decision.
- [ ] Sentry: Replay blocks the editor, `dropEditorBreadcrumbs` is set, `sendDefaultPii` is `false`, and URLs and request bodies are scrubbed.
- [ ] Collaboration server: `rooms.list()` is behind an administrator endpoint, and `roomLabel` is the default or `hmacRoomLabel`.
