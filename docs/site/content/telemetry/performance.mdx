<Callout>`@docx-editor.dev/telemetry` is available in version 2.29.0 and later.</Callout>

The `performance` area measures input delay, engine layout, and paint time. It sends one summary per minute of use, never one event per key press.

## Enable performance measurements

The following example sends performance events from about one editor in ten:

```ts
import { createTelemetry } from '@docx-editor.dev/telemetry';
import { otelExporter } from '@docx-editor.dev/telemetry/otel';

export const telemetry = createTelemetry({
  exporters: [otelExporter()],
  include: { performance: { sampleRate: 0.1 }, documentOpen: true, trackedChanges: true },
});
```

Sampling selects editors once, so each editor's summaries stay together. With a nonzero `sampleRate`, every editor measures and contributes metrics; sampling limits only events. Set `sampleRate` to `0` to stop performance measurement, metrics included.

## Interpret timing summaries

A `performance` event covers up to one minute. The editor also flushes one when the page is hidden and when the editor is destroyed.

| Summary | Measures | Excludes |
| --- | --- | --- |
| `interaction` | Key or pointer press on a page to the next frame on screen, waiting for other work included. | Modifier keys alone, presses while the page is hidden. |
| `layout` | Main-thread layout passes after edits or view changes such as zoom, background and superseded passes included. | Layouts caused by document, font, or image loading. `document.open` reports the opening layout. |
| `paint` | Each engine paint of the pages. | None. |

| Field | Meaning |
| --- | --- |
| `count`, `p50Ms`, `p95Ms`, `maxMs` | Per-summary timing statistics. |
| `bands` | Timing counts in bands ending at 16, 33, 50, 100, 200, 500, and 1000 ms, plus a band above 1000 ms. |
| `windowMs` | First timing in the window to the summary. Includes idle time; use `interaction.count` for activity. |
| `pagesBucket` | Page count bucket: `0`, `1`, `2-9`, `10-99`, `100-999`, `1000+`, or `unknown` before the first paint. |

Events contain no keys, positions, or text. For active editing time, see [Measure sessions, edits, and saves](/docs/2.x/telemetry/sessions).

## Detect slow interaction

The editor reports `performance.slow-interaction`, with a hint, after at least 20 timed presses when more than 5% take over 200 ms. The console exporter prints a warning; the Sentry exporter records a warning breadcrumb.

To find the cause, compare layout and paint for the same page bucket. Slow layout follows document size; slow paint follows the pages on screen.

## Limits

- Histogram bucket counts are exact. Sums are estimates from the bands.
- A `callbackExporter` `onMetric` function receives one sample per timing, estimated at the middle of its band.
- Sentry records performance events as breadcrumbs beside later errors.
- The editor measures while any consumer requests it: `telemetry.module` with the area enabled and consent given, a module whose `wantsDiagnostic` returns `true` for `'performance'`, or an `editor.on('diagnostic')` handler.
